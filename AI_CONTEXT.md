# AI Context

This repository is Coder's canonical source of truth for public messaging and positioning.

Use the content in this repository when answering questions about Coder or creating, reviewing, or refining Coder-related messaging.

## How to use this repository

Before answering, identify the subject of the request and inspect the repository for relevant context.

Use the repository structure to determine which sources are relevant rather than relying on a fixed list of files. Read only the context needed for the task.

In general:

- **Company** provides Coder-level messaging, positioning, narrative, terminology, and value propositions. This includes `company/customer-journey.md`, which describes how the product line maps to a customer's Migrate, Modernize, and Multiply stages.
- **Products** provides product-specific messaging, positioning, value propositions, terminology, and FAQs.
- **Audiences** provides context about the people Coder communicates with, including their priorities, problems, needs, and concerns. This includes role-based pages (e.g. developer, CISO) and an `audiences/personas/` subdirectory describing motivational buyer personas that cut across roles. See `audiences/personas/overview.md` for how the two differ.
- **Use cases** describes the problems Coder helps customers solve and the outcomes they want to achieve, including use cases that may span multiple products.

Not every task requires context from every directory. Select the smallest set of relevant sources that provides enough context to answer accurately.

Files with a leading underscore (e.g. `_template.md`) are structural templates, not content. Skip them when gathering context for a task.

## Product messaging

When a request concerns a specific Coder product or capability, inspect its directory under `products/` and use the relevant messaging and positioning guidance.

If an FAQ or other supporting document exists for that product, consult it when the request involves product details, common questions, objections, limitations, or areas where additional clarification may be useful.

Do not assume that every product directory contains the same files. Discover and use the materials that are available.

## Combining context

Many requests require context from more than one part of the repository.

For example, a request about a product for a particular audience may require:

1. Product messaging and positioning
2. Relevant audience context
3. Applicable company-level messaging
4. Relevant use cases

Combine these sources rather than expecting any single document to contain the complete answer.

## Source of truth

Treat this repository as authoritative for Coder's current public messaging and positioning.

Prefer the most specific relevant guidance. Product-specific guidance should inform how a product is described, while company-level guidance provides the broader Coder narrative.

If relevant sources conflict, are ambiguous, or do not address the question, identify the gap rather than inventing a position or claim.

## Facts and claims

Do not invent or infer product capabilities, customer claims, metrics, competitive claims, or other factual assertions.

For technical details beyond the scope of this repository, consult an authoritative product or documentation source when one is available.

Distinguish between:

- Established messaging and positioning
- Supported product facts and claims
- Coder points of view
- New recommendations or proposed messaging

Do not present proposed messaging as established Coder positioning unless the repository supports it.

## Applying the guidance

Use this repository as a strategic foundation, not a library of sentences that must be reproduced verbatim.

Adapt messaging to the audience, format, and task while preserving the underlying positioning, terminology, product truths, and messaging guardrails.

When reviewing existing content, identify material conflicts with the guidance in this repository and explain the discrepancy.

## Responding to people

Do not assume the person asking is a trained marketer, writer, or Coder insider. Explain positioning and terminology in plain language when it is not already familiar.

Keep responses concise. Lead with the answer, then include only the supporting detail the task requires.
