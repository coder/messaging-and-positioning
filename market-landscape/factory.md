*Factory's coding agent is called Droid. As of 2026-11-03, `factory.ai` and `docs.factory.ai` redirect to [factory.com](https://factory.com/) and [docs.factory.com](https://docs.factory.com/), while Factory still documents API and relay hosts under `*.factory.ai` ([deployment options](https://docs.factory.com/enterprise/network-and-deployment), [Remote Control](https://docs.factory.com/remote-control)).*

## One-Line Positioning

Factory packages Droid with a Factory-hosted control plane by default and customer-hosted options by arrangement, while Coder provides self-hosted development infrastructure and a native control-plane agent, with a documented path to use Droid through AI Gateway rather than replace it ([Factory deployment options](https://docs.factory.com/enterprise/network-and-deployment), [Coder Agents](https://coder.com/docs/@main/ai-coder/agents), [Factory client configuration](https://coder.com/docs/@main/ai-coder/ai-gateway/clients/factory)).

## Strategic Themes and Patterns

- **Relationship.** Competitive where buyers are choosing agent execution infrastructure and governance, and complementary where they want Droid on Coder: Factory offers managed computers, environment baselines, and customer-operated sandbox orchestration, while Coder provides self-hosted workspaces and its native agent ([Factory deployment options](https://docs.factory.com/enterprise/network-and-deployment), [OpenCompute](https://docs.factory.com/opencompute/overview), [Coder Agents](https://coder.com/docs/@main/ai-coder/agents)). These are overlapping decisions, not feature-for-feature substitutes; see [Why Coder](../company/why-coder.md).
- **Control.** Factory's deployment guide lists a Factory-hosted control plane for Managed and Factory-hosted by default for Private, with Custom Deployment discussions for buyers who require otherwise ([deployment options](https://docs.factory.com/enterprise/network-and-deployment)). Native Coder Agents runs its loop in the customer's Coder deployment; this is a default operating-model distinction, not a claim that Factory cannot run customer-hosted ([Coder Agents](https://coder.com/docs/@main/ai-coder/agents)).
- **Model choice.** Both support multiple model providers, customer credentials, and compatible self-hosted endpoints, so model independence alone does not distinguish Coder from Factory ([Factory BYOK](https://docs.factory.com/model-independence/byok), [Coder models](https://coder.com/docs/@main/ai-coder/agents/models)). Factory additionally offers managed model access and automatic selection through Factory Router, subject to organization policy ([models](https://docs.factory.com/models), [Router](https://docs.factory.com/model-independence/factory-router)).
- **Agent choice.** Factory's documented native Automations, Delegations, Missions, and Workstreams use Droid; this does not mean another executable cannot run on its computers ([Automations](https://docs.factory.com/automations/overview), [Delegations](https://docs.factory.com/delegations), [Missions](https://docs.factory.com/missions/overview), [Workstreams](https://docs.factory.com/workstreams/overview)). Coder workspaces can host multiple coding agents, with AI Gateway configurations for supported clients including Droid, Claude Code, Codex CLI, and OpenCode, rather than identical native orchestration for every agent ([client compatibility](https://coder.com/docs/@main/ai-coder/ai-gateway/clients)).
- **Consistency.** Coder provides Terraform-defined workspace infrastructure for developers and agents; Factory Environments provide reusable snapshots from selected sources, with optional repositories and setup scripts ([Coder overview](https://coder.com/docs/@main), [Environment creation](https://docs.factory.com/environments/create)). The distinction is the provisioning and lifecycle model, not an absence of human access in Factory: Droid Computers support SSH and full VS Code Remote-SSH sessions ([Droid Computers](https://docs.factory.com/droid-computers/overview)); see the [Coder Message House](../company/message-house.md) for the Control, Choice, and Consistency pillars.
- **Lock-in risk.** The assessment here is that moving Factory-specific orchestration and integrations may require adaptation, not that all work must be rebuilt: CLI sessions can remain local, GitHub Automations live in repository workflows, and Workstream documents can be downloaded ([CLI settings](https://docs.factory.com/droid-cli/settings), [custom Automations](https://docs.factory.com/automations/custom), [shared folders](https://docs.factory.com/workstreams/shared-folder)). `AGENTS.md`, `SKILL.md`, and MCP offer reusable instructions and integrations, but do not guarantee identical behavior or portable platform state across products ([AGENTS.md](https://docs.factory.com/harness/agents-md), [Skills](https://docs.factory.com/harness/skills), [MCP](https://docs.factory.com/harness/mcp)).
- **Build versus buy.** For an entirely customer-operated stack, evaluate Coder's self-hosted platform against Factory's customer-hosted offering and the burden of building the required infrastructure internally, rather than treating Factory's hosted default as its only option ([Coder Agents](https://coder.com/docs/@main/ai-coder/agents), [Factory deployment options](https://docs.factory.com/enterprise/network-and-deployment)). Coder's broader infrastructure rationale is in [Why Coder](../company/why-coder.md).
- **Where Factory is sufficient on its own.** Teams that accept Factory-hosted orchestration and want Droid-specific workflows and managed compute may not need another platform; Factory recommends starting with Managed unless a specific regulatory or policy requirement rules it out ([deployment options](https://docs.factory.com/enterprise/network-and-deployment), [Automations](https://docs.factory.com/automations/overview)). This removes control-plane operations from the customer, not the need to configure repositories, credentials, or integrations ([Delegations prerequisites](https://docs.factory.com/delegations)).
- **How they work together.** A platform team can install Droid on a supported Coder workspace and route its custom models through AI Gateway using the documented Factory client configuration ([Factory client](https://coder.com/docs/@main/ai-coder/ai-gateway/clients/factory), [Factory runtime options](https://docs.factory.com/enterprise/network-and-deployment)). Workspace policy governs execution and AI Gateway audits routed model traffic; this is not Agent Relay integration or a complete audit of every local process action ([template network boundaries](https://coder.com/docs/@main/ai-coder/agents/platform-controls/template-optimization#configure-network-boundaries), [Gateway audit](https://coder.com/docs/@main/ai-coder/ai-gateway/audit), [Agent Relay](https://coder.com/docs/@main/ai-coder/agent-relay)).

## Coder's Strengths Here

- **Self-hosted native agent, generally available.** Native Coder Agents runs its loop in the customer-operated control plane and is generally available ([Coder Agents](https://coder.com/docs/@main/ai-coder/agents), [getting started](https://coder.com/docs/@main/ai-coder/agents/getting-started)). Factory Private and OpenCompute remain in Private Preview, while Droid's own loop can already run on a customer machine, so the contrast is platform deployment rather than inherently cloud-hosted Droid reasoning ([deployment options](https://docs.factory.com/enterprise/network-and-deployment), [Factory data flows](https://docs.factory.com/enterprise/privacy-and-data-flows)).
- **Disconnected native-agent deployment.** Coder supports air-gapped deployments with local model inference and the required dependencies available inside the boundary, but cloud-dependent integrations such as Agent Relay are not offline options ([air-gap installation](https://coder.com/docs/@main/install/prepare/airgap), [Coder Agents](https://coder.com/docs/@main/ai-coder/agents), [Agent Relay](https://coder.com/docs/@main/ai-coder/agent-relay)). Agent Time reporting uses a Coder-managed service when enabled; customers with disconnected or restricted-reporting deployments can discuss alternative methods with Coder ([licensing and usage](https://coder.com/docs/@main/ai-coder/agents/licensing-usage)).
- **One workspace layer for developers and agents.** Terraform templates provision Coder workspaces on supported VMs, Kubernetes, or Docker infrastructure across cloud and on-premises deployments ([Coder overview](https://coder.com/docs/@main)). Developers can open an agent's workspace in VS Code, Cursor, or JetBrains, while platform teams can use stricter templates for agent workloads ([Coder Agents](https://coder.com/docs/@main/ai-coder/agents), [template optimization](https://coder.com/docs/@main/ai-coder/agents/platform-controls/template-optimization)).
- **Model-traffic governance across supported agents.** AI Gateway records last user prompts, token usage, and tool-call requests for routed traffic, with attribution to the authenticated Coder identity, including traffic from its documented Factory client ([Gateway audit](https://coder.com/docs/@main/ai-coder/ai-gateway/audit), [authentication](https://coder.com/docs/@main/ai-coder/ai-gateway/auth), [Factory client](https://coder.com/docs/@main/ai-coder/ai-gateway/clients/factory)). It does not retain tool responses or establish a complete execution audit, and session grouping depends on client-supplied identifiers ([Gateway audit](https://coder.com/docs/@main/ai-coder/ai-gateway/audit)).
- **Server-side model credentials for the native agent.** Native Coder Agents does not distribute its model-provider credentials to workspaces; this does not describe independently configured third-party CLI or experimental ACP harness credentials ([Coder models](https://coder.com/docs/@main/ai-coder/agents/models), [ACP subagents](https://coder.com/docs/@main/ai-coder/agents/acp-subagents)). Droid resolves custom-model authentication on its execution machine and supports environment references, keyless endpoints, and credential helpers instead of mandatory static keys ([Factory BYOK](https://docs.factory.com/model-independence/byok)).
- **Explicit workspace network policy.** Platform teams set workspace-wide network restrictions through templates and the underlying infrastructure; without those restrictions, agent workspaces can have full internet access ([template network boundaries](https://coder.com/docs/@main/ai-coder/agents/platform-controls/template-optimization#configure-network-boundaries), [security best practices](https://coder.com/docs/@main/tutorials/best-practices/security-best-practices#outbound-network-access)). Native Coder Agents does not need workspace-to-model-provider access, but Droid and other runtimes, builds, or integrations can require additional approved destinations ([Coder architecture](https://coder.com/docs/@main/ai-coder/agents/architecture), [Factory networking](https://docs.factory.com/enterprise/network-and-deployment)).

## Factory Overview

- **What it is.** Factory describes an agent-native software development platform for planning, building, reviewing, testing, and shipping software ([Factory](https://factory.com/)). Droid is accessible through the desktop app, CLI, SDK, web/mobile interfaces, and integrations for VS Code, Cursor, Windsurf, JetBrains, and Zed, with differing IDE capabilities rather than identical context sharing everywhere ([Factory App](https://docs.factory.com/factory-app/overview), [SDK](https://docs.factory.com/sdk/typescript), [web/mobile](https://factory.com/product/web), [IDE integrations](https://docs.factory.com/ide-integrations)).
- **Runtime and data flows.** Droid's agent loop runs on its execution machine and reads that filesystem rather than relying on a remote code index ([data flows](https://docs.factory.com/enterprise/privacy-and-data-flows)). That is not a no-cloud-storage guarantee: selected code can enter model requests, CLI cloud-session sync defaults on, and managed Environments build snapshots containing cloned code ([data flows](https://docs.factory.com/enterprise/privacy-and-data-flows), [CLI settings](https://docs.factory.com/droid-cli/settings), [Environment creation](https://docs.factory.com/environments/create)).
- **Execution options.** Droid can execute on supported developer machines, CI through headless `droid exec`, customer-maintained machines connected through Remote Control, persistent managed Droid Computers, or fresh Environment instances ([Droid Exec](https://docs.factory.com/droid-exec/overview), [Remote Control](https://docs.factory.com/remote-control), [Droid Computers](https://docs.factory.com/droid-computers/overview), [Environments](https://docs.factory.com/environments/overview)). OpenCompute provisions sandboxes on customer-controlled infrastructure; it is an orchestrator, not Factory-owned compute capacity ([OpenCompute](https://docs.factory.com/opencompute/overview)).
- **Workflows.** Factory documents scheduled, Slack, GitHub, and webhook Automations; delegation from Slack, Linear, Jira Cloud, and Microsoft Teams; and Missions and Workstreams for coordinated agent work ([Automations](https://docs.factory.com/automations/overview), [Delegations](https://docs.factory.com/delegations), [Missions](https://docs.factory.com/missions/overview), [Workstreams](https://docs.factory.com/workstreams/overview)). Availability differs: webhook triggers are Private Preview, Google Chat delegation is in development, and Workstreams is beta and not yet available on Business or Enterprise ([webhook triggers](https://docs.factory.com/automations/custom), [Google Chat](https://docs.factory.com/delegations/google-chat), [Workstreams](https://docs.factory.com/workstreams/overview)).
- **Models.** Factory offers managed models from several providers with per-model usage multipliers, automatic model selection through Factory Router, and custom endpoints for customer keys, gateways, and local models ([models](https://docs.factory.com/models), [Router](https://docs.factory.com/model-independence/factory-router), [BYOK](https://docs.factory.com/model-independence/byok)). Custom models remain subject to organizational controls and the interface/deployment limitations below ([managed settings](https://docs.factory.com/enterprise/hierarchical-settings-and-org-control)).
- **Target customer and funding.** Factory sells self-serve individual and Teams plans and sales-led Business and Enterprise plans ([pricing](https://factory.com/pricing)). On September 15, 2026, Factory announced $200 million raised at a $5 billion valuation, bringing its reported total funding above $400 million ([Factory announcement](https://factory.com/news/5-billion-valuation)).
- **Factory Managed.** Factory operates the control plane; customers operate their local and CI environments, while Factory-managed sandbox compute is also available and model traffic can use customer gateways ([deployment options](https://docs.factory.com/enterprise/network-and-deployment)). Its enterprise EU deployment places session content and inference in Europe, while organization records, user profiles, billing, and identity retain global dependencies ([EU data residency](https://docs.factory.com/enterprise/network-and-deployment#eu-deployment-and-data-residency)).
- **Factory Private.** The deployment guide describes a Factory-hosted control plane by default and customer-operated OpenCompute sandboxes in the customer's infrastructure, with model inference and session storage governed separately by configuration ([deployment options](https://docs.factory.com/enterprise/network-and-deployment), [OpenCompute](https://docs.factory.com/opencompute/overview)). Factory introduced OpenCompute in private preview on October 14, 2026 ([announcement](https://factory.com/news/opencompute)).
- **Customer-hosted and airgap options.** Factory directs buyers who rule out its hosted control plane to a Custom Deployment discussion; its dedicated airgap build is for deployments entirely inside the customer's network and is not publicly distributed ([deployment options](https://docs.factory.com/enterprise/network-and-deployment), [airgapped deployment](https://docs.factory.com/enterprise/airgapped-deployment)). Factory's differing descriptions of Private warrant confirming the actual control-plane placement and operating responsibilities before purchase, as detailed below.

## Coder Overview for This Comparison

- **Coder Agents.** A native self-hosted agent with its loop in the Coder control plane; documented provider configurations include Anthropic, OpenAI, Google, Azure OpenAI, AWS Bedrock, OpenRouter, Vercel AI Gateway, and OpenAI-compatible endpoints ([Coder Agents](https://coder.com/docs/@main/ai-coder/agents), [models](https://coder.com/docs/@main/ai-coder/agents/models)). Self-hosted orchestration does not imply self-hosted inference when a customer selects an external model provider ([architecture](https://coder.com/docs/@main/ai-coder/agents/architecture)).
- **Coder Workspaces.** Self-hosted, Terraform-defined environments for developers and agents, on the infrastructure provisioned by the selected template ([Coder overview](https://coder.com/docs/@main), [Coder Agents message house](../products/coder-agents/message-house.md)).
- **AI Governance.** Included with Premium, with AI Gateway providing model access and auditing for configured clients including Droid; workspace network policy is configured through templates, not implied by routing traffic through the gateway ([pricing](https://coder.com/pricing), [Factory client](https://coder.com/docs/@main/ai-coder/ai-gateway/clients/factory), [AI Governance message house](../products/coder-ai-governance/message-house.md)).
- **Agent Relay.** Early-access integration connecting supported cloud-agent sessions to Coder workspaces, while orchestration and inference remain with the provider ([Agent Relay](https://coder.com/docs/@main/ai-coder/agent-relay)). Its documented providers are Cursor and Claude Code; Factory is not listed as of 2026-11-03 ([Agent Relay](https://coder.com/docs/@main/ai-coder/agent-relay)).

## Where Factory Is Strong or Coder Has a Gap

- **Managed operations.** Factory Managed supplies vendor-operated orchestration and optional managed compute, whereas customers operate their Coder deployment ([Factory deployment options](https://docs.factory.com/enterprise/network-and-deployment), [Coder overview](https://coder.com/docs/@main)). This is useful when avoiding control-plane operations is more important than owning that layer.
- **Packaged lifecycle workflows.** Factory documents setup workflows for code review, security review, project-specific QA, incident response, AutoWiki, and repository Agent Readiness ([code review](https://docs.factory.com/automations/code-review-ci), [security review](https://docs.factory.com/automations/security-review), [QA](https://docs.factory.com/automations/automated-qa), [incident response](https://docs.factory.com/automations/incident-response), [AutoWiki](https://docs.factory.com/automations/wiki/overview), [Agent Readiness](https://docs.factory.com/agent-readiness/overview)). These are concrete integration starting points, not a guarantee of successful autonomous delivery or zero setup.
- **Delegation from existing tools.** Factory documents launching Droid from Slack, Linear, Jira Cloud, and Microsoft Teams, subject to organization enablement, app permissions, credentials, and compute setup ([Delegations](https://docs.factory.com/delegations), [Jira](https://docs.factory.com/delegations/jira)). Google Chat is a separately documented in-development option, not an unqualified fifth supported integration ([Google Chat](https://docs.factory.com/delegations/google-chat)).
- **Work-linked analytics.** Agent Effectiveness links sessions and spend to connected pull requests, tickets, and projects; it requires Enterprise, Advanced Analytics enablement, organization integrations, and cloud session sync ([overview](https://docs.factory.com/agent-effectiveness/overview), [setup](https://docs.factory.com/agent-effectiveness/setup)). Its attribution API is separately Private Preview, and linked-session credits can overlap across work items rather than form an additive allocation of total spend ([API](https://docs.factory.com/agent-effectiveness/api)).
- **Managed model access and routing.** Factory provides multiple model families through its usage plans and offers automatic selection with Factory Router, while Coder Agents uses provider access configured by the customer ([Factory models](https://docs.factory.com/models), [Router](https://docs.factory.com/model-independence/factory-router), [Coder models](https://coder.com/docs/@main/ai-coder/agents/models)). Factory BYOK is an alternative, not evidence that all model access requires a separate provider contract ([BYOK](https://docs.factory.com/model-independence/byok)).
- **Model-vendor procurement.** Factory is listed in Claude Marketplace and OpenAI Marketplace, where eligible customers may apply part of their existing commitments to qualifying purchases under the vendors' terms ([Claude Marketplace](https://claude.com/marketplace/agents-products), [OpenAI Marketplace](https://openai.com/business/marketplace/)). Anthropic describes commitment use as limited preview, and both vendors require eligibility confirmation rather than promising that every Factory purchase qualifies ([Claude Marketplace](https://claude.com/marketplace/agents-products), [OpenAI Marketplace](https://openai.com/business/marketplace/)).
- **Self-serve paid entry.** Factory publishes subscriptions starting at $20 per month; Coder's paid tiers are sales-led, alongside its free Community tier ([Factory pricing](https://factory.com/pricing), [Coder pricing](https://coder.com/pricing)).
- **Compliance evidence for procurement.** Factory reports SOC 2 Type II, ISO 27001, and ISO 42001, and its Trust Center lists supporting reports and certificates behind access-request controls ([Factory enterprise](https://docs.factory.com/enterprise), [Trust Center resources](https://trust.factory.com/resources)). These are vendor-reported attestations and certifications, not an independent verification of their scope or a claim that Coder lacks compliance evidence.

## Known Limitations in Factory's Approach

- **Private and OpenCompute are in preview (as of 2026-11-03).** Both are Private Preview and require access through Factory's sales or account team ([deployment options](https://docs.factory.com/enterprise/network-and-deployment), [OpenCompute](https://docs.factory.com/opencompute/overview)). This status should not be generalized to all customer-hosted Droid execution, since local machines and Remote Control are separately documented ([Remote Control](https://docs.factory.com/remote-control)).
- **Conflicting control-plane descriptions (as of 2026-11-03).** The architecture article dated September 24 and enterprise-automation article dated June 24 describe a customer-hosted Private control plane, while the deployment guide and Private announcement, updated October 26, describe a Factory-hosted default ([architecture article](https://factory.com/articles/factory-private-architecture), [enterprise-automation article](https://factory.com/articles/how-enterprises-automate-software-development), [deployment guide](https://docs.factory.com/enterprise/network-and-deployment), [Private announcement](https://factory.com/news/factory-private)). This page follows the guide for defaults, not as evidence against customer-hosted availability; buyers should confirm the contracted topology, operations, and feature scope.
- **Airgap removes connected services (as of 2026-11-03).** Factory lists account and usage-limit management, session sync/sharing, Slack, Agent Readiness reports, built-in web search and URL fetching, automatic updates, and Factory-hosted analytics among unavailable features ([airgapped deployment](https://docs.factory.com/enterprise/airgapped-deployment)). At least one custom model is required, Factory-managed models and Router are unavailable, and the customer's network must enforce isolation rather than relying on Airgap Mode as a security boundary ([airgapped deployment](https://docs.factory.com/enterprise/airgapped-deployment)).
- **Connected runtimes need approved Factory destinations (as of 2026-11-03).** Factory documents `*.factory.ai` access and outbound relay connections for Remote Control; moving execution into a customer workspace does not eliminate those dependencies ([deployment options](https://docs.factory.com/enterprise/network-and-deployment), [Remote Control](https://docs.factory.com/remote-control)). The dedicated airgap build is a separate disconnected path ([airgapped deployment](https://docs.factory.com/enterprise/airgapped-deployment)).
- **Workflow availability varies (as of 2026-11-03).** Workstreams is beta on Pro, Plus, Max, and Teams, not yet Business or Enterprise; webhook Automations is Private Preview; Google Chat Delegations is in development ([Workstreams](https://docs.factory.com/workstreams/overview), [webhook triggers](https://docs.factory.com/automations/custom), [Google Chat](https://docs.factory.com/delegations/google-chat)). Do not assume the whole feature inventory is available to an enterprise deployment.
- **EU compute and rollout constraints (as of 2026-11-03).** The Environment prerequisites state that Factory-hosted compute is unavailable to EU-region organizations and that access depends on organization rollout and compute policy ([Environment prerequisites](https://docs.factory.com/environments/prerequisites)). An EU control-plane offering therefore does not establish availability of every managed-compute workflow.
- **Persistent computers diverge from their baseline (as of 2026-11-03).** A Droid Computer initialized from an Environment retains its own state and is not updated by later Environment rebuilds ([Droid Computers](https://docs.factory.com/droid-computers/overview)).
- **Personal custom models are interface-limited (as of 2026-11-03).** Personal BYOK entries work in the CLI and desktop app but do not appear in hosted web or mobile interfaces; this is not a blanket limitation on organization-managed custom models ([BYOK](https://docs.factory.com/model-independence/byok), [managed settings](https://docs.factory.com/enterprise/hierarchical-settings-and-org-control)).

## Common Questions

- **Doesn't Factory Private run in our VPC?** Its documented default puts Droid sandboxes in customer infrastructure through OpenCompute while Factory hosts the platform control plane; customer-hosted control-plane requirements are directed to a Custom Deployment discussion ([deployment options](https://docs.factory.com/enterprise/network-and-deployment)). Native Coder Agents instead runs its control-plane loop and workspace execution in the customer's Coder deployment, while inference follows the customer's model configuration ([Coder Agents](https://coder.com/docs/@main/ai-coder/agents), [models](https://coder.com/docs/@main/ai-coder/agents/models)).
- **Isn't Factory model-agnostic too?** Yes: managed models, customer keys, gateways, and local endpoints are documented, with configuration and interface restrictions ([models](https://docs.factory.com/models), [BYOK](https://docs.factory.com/model-independence/byok)). Position Coder on self-hosted infrastructure and supported agent choice, not exclusive model independence ([Coder Message House](../company/message-house.md), [Gateway clients](https://coder.com/docs/@main/ai-coder/ai-gateway/clients)).
- **Can we use Droid with Coder?** Yes: Coder documents custom-model configuration using the user's Coder token with centralized provider credentials, or permitted personal provider credentials together with Coder authentication ([Factory client](https://coder.com/docs/@main/ai-coder/ai-gateway/clients/factory)). Factory is not listed as an Agent Relay provider, and no Droid- or Factory-specific module was found in the [public Registry source checked on 2026-11-03](https://github.com/coder/registry/tree/d5159d5b6495e833662071d2955b56ce8da4a069/registry) ([Agent Relay](https://coder.com/docs/@main/ai-coder/agent-relay)).
- **Does Factory support air-gapped deployment?** Yes, through a nonpublic enterprise airgap build for Custom Deployments, using custom models and omitting the connected features listed above ([airgapped deployment](https://docs.factory.com/enterprise/airgapped-deployment)). Coder also supports disconnected native-agent deployments with local inference and required dependencies; where Agent Time reporting applies, customers can discuss alternative methods with Coder, while Agent Relay remains cloud-dependent ([air-gap installation](https://coder.com/docs/@main/install/prepare/airgap), [licensing and usage](https://coder.com/docs/@main/ai-coder/agents/licensing-usage), [Agent Relay](https://coder.com/docs/@main/ai-coder/agent-relay)).
- **How do Factory Environments compare to Coder workspaces?** Factory Environments are reusable snapshots that create independent instances and can initialize persistent Droid Computers with human SSH/IDE access ([Environments](https://docs.factory.com/environments/overview), [Droid Computers](https://docs.factory.com/droid-computers/overview)). Coder workspaces are Terraform-provisioned environments for developers and agents, with template-defined infrastructure and lifecycle controls ([Coder overview](https://coder.com/docs/@main), [Coder Workspaces message house](../products/coder-workspaces/message-house.md)).

## When Factory Alone Is Enough

- **Vendor-hosted orchestration is acceptable.** Teams can use Factory Managed and still route model traffic to their own providers or gateways ([deployment options](https://docs.factory.com/enterprise/network-and-deployment)).
- **Managed compute is the priority.** Factory-operated Droid Computers and enabled managed Environment workflows can remove the need to operate agent machines, subject to region and rollout availability ([Droid Computers](https://docs.factory.com/droid-computers/overview), [Environment prerequisites](https://docs.factory.com/environments/prerequisites)).
- **Droid is the chosen workflow.** Teams that prefer Factory's native agent and documented Automations may not need a separate platform for multiple coding agents ([Automations](https://docs.factory.com/automations/overview), [Missions](https://docs.factory.com/missions/overview)).
- **Individuals and small teams want self-service.** Factory offers individual subscriptions and a Teams plan for up to 10 seats ([pricing](https://factory.com/pricing)).

## Pricing and Packaging

- **Factory list prices.** Pro is $20 per month, Plus $100, Max $200, and Teams $60 per team per month plus $40 per seat for up to 10 seats; Business and Enterprise are custom-priced ([Factory pricing](https://factory.com/pricing), [organization plans](https://docs.factory.com/pricing/organizations)). Teams gives each seat Pro usage limits, while Business and Enterprise usage follows contract terms ([organization plans](https://docs.factory.com/pricing/organizations)).
- **Factory usage.** Individual plans have independent rolling 5-hour, 7-day, and 30-day limits; Missions require Extra Usage to be enabled and use the same rolling limits, rather than being exclusively prepaid work ([individual plans](https://docs.factory.com/pricing/individuals)). Extra Usage credits have a $10 minimum and do not expire; BYOK has a free allowance followed by plan-dependent charges whose amounts are not specified on that page ([individual plans](https://docs.factory.com/pricing/individuals)).
- **Unresolved Factory entitlement.** The pricing page lists managed Droid Computers under Plus, while the Individual Plans documentation lists them under Pro; confirm the minimum plan and included compute with Factory rather than treating either page as definitive ([pricing](https://factory.com/pricing), [individual plans](https://docs.factory.com/pricing/individuals)).
- **Coder tiers and concurrency.** Community is free; Premium includes AI Governance, and Premium and AI Premium are sales-led ([Coder pricing](https://coder.com/pricing)). Community and Premium support five concurrently active native Coder Agents deployment-wide, with excess work queued; AI Premium removes the normal cap using purchased Agent Time, subject to usage limits and the documented concurrency fallback ([licensing and usage](https://coder.com/docs/@main/ai-coder/agents/licensing-usage)).
- **Coder usage and total cost.** Agent Time measures qualifying model-invocation duration, including subagent generation and compaction, not total workspace uptime; infrastructure and model-provider charges remain separate from Coder licensing and Agent Time ([licensing and usage](https://coder.com/docs/@main/ai-coder/agents/licensing-usage), [models](https://coder.com/docs/@main/ai-coder/agents/models), [Coder overview](https://coder.com/docs/@main)). These differ from Factory's subscription and usage units, so list prices alone do not establish which deployment is cheaper; see [Packaging](../company/packaging.md).
