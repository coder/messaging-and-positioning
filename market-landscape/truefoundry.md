*(TrueFoundry is the brand of Ensemble Labs, Inc. ([privacy policy](https://www.truefoundry.com/privacy-policy)). Its docs still introduce it as [a platform on Kubernetes for building and deploying models](https://www.truefoundry.com/docs/introduction), and it now leads with its [AI Gateway and MCP Gateway](https://www.truefoundry.com/). ## One-Line Positioning

TrueFoundry offers a broad LLM, MCP, and agent gateway that competes with Coder's AI Gateway, while Coder ties model requests to the developer, workspace, and agent session behind them and governs the environments where that work runs.

## Strategic Themes and Patterns

- **Relationship.** Competitive at the gateway layer. TrueFoundry positions one control plane across an [LLM Gateway, MCP Gateway, and Agent Gateway](https://www.truefoundry.com/llms.txt) and publishes [governance guides for coding agents](https://www.truefoundry.com/docs/ai-gateway/coding-agents-governance) such as Claude Code, Codex, Cursor, and GitHub Copilot, which overlaps with what Coder's [AI Gateway](https://coder.com/docs/ai-coder/ai-gateway) does for coding agents and IDEs. TrueFoundry also offers GPU model serving and fine-tuning ([AI Deployment Platform](https://www.truefoundry.com/unified-ai-deployments), [Training and Fine-Tuning](https://www.truefoundry.com/training-fine-tuning)), which Coder doesn't, and a hosted agent harness, [TrueForge](https://www.truefoundry.com/docs/agent-platform/agent-harness/overview).
- **Partial overlap on environments.** TrueFoundry's Workbench offers [Jupyter notebooks](https://www.truefoundry.com/docs/launch-notebooks), which its docs frame around ML projects, and [SSH servers](https://www.truefoundry.com/docs/launch-an-ssh-server) that users open from local VS Code, both running on Kubernetes. Coder Workspaces are general-purpose environments [defined in Terraform](https://coder.com/docs) on VMs, Kubernetes, or Docker, across Windows, Linux, and macOS, and reachable from VS Code, JetBrains, Cursor, a web terminal, remote desktop, or SSH.
- **Platform context.** A standalone gateway sees the requests clients send it. Coder's AI Gateway runs inside the platform where development happens, so requests are [attributed to a Coder user](https://coder.com/docs/ai-coder/ai-gateway), spend is attributed [down to the workspace](../products/coder-ai-governance/message-house.md), and activity is grouped into [interceptions, threads, and sessions](https://coder.com/docs/ai-coder/ai-gateway/audit). TrueFoundry attributes cost to [users, teams, virtual accounts, models, and custom metadata](https://www.truefoundry.com/docs/ai-gateway/cost-tracking), so any environment or workspace context comes from metadata the client or its token supplies.
- **Choice, Control, Consistency.** Choosing TrueFoundry costs little on Choice of models, since it lists [35+ provider platforms](https://www.truefoundry.com/docs/ai-gateway/supported-providers) behind an OpenAI-compatible API. On Control, self-hosted TrueFoundry authenticates users through TrueFoundry's [auth server](https://www.truefoundry.com/docs/ai-gateway/modes-of-deployment) unless it runs on-prem on the higher-tier Enterprise plan. On Consistency, its coding-agent guidance assumes managed developer devices, where admins push gateway settings with MDM and [block direct vendor endpoints with network policy](https://www.truefoundry.com/docs/ai-gateway/coding-agents-governance) that the customer supplies. In Coder, agents run in workspaces, and each template defines the environment and [what it can reach on the network](https://coder.com/docs/ai-coder/agents/platform-controls/template-optimization#configure-network-boundaries).
- **Lock-in risk.** Gateway lock-in is moderate. Clients can be repointed because TrueFoundry's API is OpenAI-compatible and also serves the [Anthropic Messages API](https://www.truefoundry.com/docs/ai-gateway/messages-overview), but policies built around it, such as [virtual models](https://www.truefoundry.com/docs/ai-gateway/virtual-model), [budget rules](https://www.truefoundry.com/docs/ai-gateway/budget-limiting-v2), and [virtual MCP servers](https://www.truefoundry.com/docs/ai-gateway/mcp/virtual-mcp-server), are harder to move. TrueFoundry ships the gateway as images from a [private registry](https://www.truefoundry.com/docs/platform/deploy-gateway-plane), and its [GitHub organization](https://github.com/truefoundry) publishes Helm charts, SDKs, and open-source tools such as TrueForge, but not the gateway's source code, as of 2026-10-29. The larger risk is treating a model gateway as the whole AI governance layer, which leaves developer environments and their egress policy to be built separately.
- **Build versus buy.** A model gateway governs the requests it receives, not where coding agents run or what they can reach. Teams that adopt TrueFoundry as their gateway still need governed environments for developers and their coding agents, egress policy where those agents run, and a link between model activity and those environments. [Why Coder](../company/why-coder.md) holds that building self-hosted development infrastructure at this depth is realistic for only a small number of organizations. Those teams can keep TrueFoundry, since AI Gateway can send traffic to an upstream [OpenAI-compatible endpoint](https://coder.com/docs/ai-coder/ai-gateway/providers#openai), though neither vendor documents that pairing.
- **Where TrueFoundry is sufficient on its own.** An organization that wants one gateway for LLM, MCP, and agent traffic across many applications, and that already manages developer devices and networks through MDM and network policy, may find TrueFoundry enough. TrueFoundry rates five clients, including Claude Code, Codex CLI, and OpenCode, as [full for both model routing and fleet-wide enforcement](https://www.truefoundry.com/docs/ai-gateway/coding-agents-governance), using its `tfy-local-ai-setup` binary for the Claude clients and Codex and each vendor's managed config for the others.

## Coder's Strengths Here

- **Gateway identity is the Coder identity.** Users authenticate to AI Gateway with their [Coder session or API tokens](https://coder.com/docs/ai-coder/ai-gateway/auth#authenticate-ai-clients), with no separate gateway login, and template admins can [pre-configure tools](https://coder.com/docs/ai-coder/ai-gateway/clients#configure-in-workspace-tools) with the user's session token and the gateway URL so they route through AI Gateway with no setup by developers. TrueFoundry ties coding-agent requests to users through personal access tokens or, for Claude Code, Claude Desktop, and Codex, a [binary deployed to each device with MDM](https://www.truefoundry.com/docs/ai-gateway/claude-mdm) that signs users in with OIDC or a device-login token.
- **Governs execution, not only model traffic.** Templates decide what each workspace can reach, using the network controls the customer already has ([security best practices](https://coder.com/docs/tutorials/best-practices/security-best-practices#outbound-network-access)), such as Kubernetes network policies, cloud security groups, or an egress proxy ([AI Governance message house](../products/coder-ai-governance/message-house.md)). The policy applies to every process in the workspace, including traffic that never reaches a gateway ([network boundaries](https://coder.com/docs/ai-coder/agents/platform-controls/template-optimization#configure-network-boundaries)), so blocking direct provider endpoints there makes AI Gateway the only route to a model for agents in that workspace, with no device MDM involved.
- **Agent session forensics.** AI Gateway records the last user prompt, token usage, tool calls, and model reasoning for each interception and groups them into [threads and sessions](https://coder.com/docs/ai-coder/ai-gateway/audit), using the session IDs that Claude Code and Codex already send. TrueFoundry groups requests into sessions when the client sends an [`X-TFY-CONVERSATION-ID` header](https://www.truefoundry.com/docs/ai-gateway/session-management), and records [turn-by-turn transcripts](https://www.truefoundry.com/docs/agent-platform/agent-harness/observability) for agents run in its TrueForge harness.
- **Self-hosted with no vendor auth dependency.** Coder runs on the customer's infrastructure, with all features supported in [air-gapped deployments](https://coder.com/docs/install/prepare/airgap) and license keys validated locally, and `coderd` [manages AI Gateway authentication](https://coder.com/docs/ai-coder/ai-gateway/standalone). Self-hosted TrueFoundry authenticates users through TrueFoundry's [central auth server](https://www.truefoundry.com/docs/platform/sso/overview) unless the customer runs on-prem on its higher-tier Enterprise plan (see Known Limitations).
- **Part of the environment platform.** The same deployment provides [Terraform-defined workspaces](https://coder.com/docs) for developers and agents, and [Coder Agents](https://coder.com/docs/ai-coder/agents) [routes its model requests through AI Gateway automatically](https://coder.com/docs/ai-coder/agents/models#providers).

## TrueFoundry Overview

- **What it is.** An enterprise [AI gateway for LLMs, MCP servers, and agents](https://www.truefoundry.com/), alongside a Kubernetes platform for [deploying models, agents, jobs, and MCP servers](https://www.truefoundry.com/unified-ai-deployments) and [fine-tuning models](https://www.truefoundry.com/training-fine-tuning). TrueFoundry cites [1000+ LLMs in its docs](https://www.truefoundry.com/docs/ai-gateway/intro-to-llm-gateway) and [1,600+ models on its AI Gateway page](https://www.truefoundry.com/ai-gateway) (company claims).
- **Architecture.** A split [control plane, gateway plane, compute plane, and data plane](https://www.truefoundry.com/docs/platform/architecture), plus authentication, licensing, and analytics servers that TrueFoundry hosts. The gateway is stateless, runs auth, rate-limit, and budget checks in memory, and gets its config from the control plane over NATS ([gateway plane architecture](https://www.truefoundry.com/docs/platform/gateway-plane-architecture)). The compute plane, which gateway-only customers don't need, always runs in the [customer's own environment](https://www.truefoundry.com/docs/platform/compute-plane-architecture).
- **Gateway capabilities.** [Virtual models](https://www.truefoundry.com/docs/ai-gateway/virtual-model) with weighted, priority, latency, and complexity-based routing, retries, and fallbacks. [Exact-match and semantic caching](https://www.truefoundry.com/docs/ai-gateway/caching). [Rate limits](https://www.truefoundry.com/docs/ai-gateway/ratelimiting-v2) by user, team, model, or metadata, and [budgets](https://www.truefoundry.com/docs/ai-gateway/budget-limiting-v2) by user, team, virtual account, model, agent, or metadata. [Guardrails](https://www.truefoundry.com/docs/ai-gateway/guardrails-overview) on LLM input and output and on MCP tool calls. [OpenTelemetry export](https://www.truefoundry.com/docs/ai-gateway/export-opentelemetry-data) and request logging with [redaction of stored bodies](https://www.truefoundry.com/docs/ai-gateway/logging-config).
- **Coding-agent governance.** A [governance table](https://www.truefoundry.com/docs/ai-gateway/coding-agents-governance) rates 13 coding tools and AI apps on model routing, fleet-wide enforcement, guardrails, and MCP. Its [`tfy-local-ai-setup` binary](https://www.truefoundry.com/docs/ai-gateway/claude-mdm), deployed with MDM, writes managed settings for Claude Code, Claude Desktop, and Codex, and [Claude Code hooks](https://www.truefoundry.com/docs/ai-gateway/claude-code-hooks) send prompt submissions and tool calls to gateway guardrails. Its open-source [aitori agent](https://www.truefoundry.com/docs/ai-gateway/govern-traffic-through-ai-gateway) runs as the device's HTTPS proxy and reroutes calls to listed AI hosts, such as Claude and ChatGPT, to the gateway.
- **MCP Gateway.** A [registry](https://www.truefoundry.com/docs/ai-gateway/mcp/mcp-server-getting-started) of managed, remote, OpenAPI-generated, virtual, and hosted stdio servers, with server access by [user, team, or virtual account](https://www.truefoundry.com/docs/ai-gateway/mcp/mcp-gateway-auth-security), tool subsets through [virtual MCP servers](https://www.truefoundry.com/docs/ai-gateway/mcp/virtual-mcp-server), [human approval for tool calls](https://www.truefoundry.com/docs/ai-gateway/mcp/mcp-tool-approval) on Enterprise, and [outbound OAuth and on-behalf-of token exchange](https://www.truefoundry.com/docs/ai-gateway/mcp/mcp-gateway-auth-security).
- **Agent Gateway and TrueForge.** The [Agent Registry](https://www.truefoundry.com/docs/agent-platform/agent-governance/agent-registry) registers agents built on any framework, including A2A agents, and the Agent Gateway proxies calls to those it routes. [TrueForge](https://www.truefoundry.com/docs/agent-platform/agent-harness/what-truefoundry-adds), an open-source agent harness that TrueFoundry hosts, runs agents' code, file, and shell steps in a managed sandbox whose egress is [unrestricted by default](https://trueforge.dev/sandbox), with optional domain allowlists. TrueFoundry's [September 16, 2026 release notes](https://www.truefoundry.com/docs/changelog) label its TrueForge integration as beta.
- **Target customer.** Enterprises, with [solution pages](https://www.truefoundry.com/) by role, such as CISO and VP of Platform, and by industry, including banking, insurance, healthcare, and government.
- **Deployment model.** Four documented [AI Gateway options](https://www.truefoundry.com/docs/ai-gateway/modes-of-deployment): SaaS, SaaS with request logs in the customer's bucket, a customer-hosted gateway with a TrueFoundry-hosted control plane, and a self-hosted control plane and gateway installed from [one Helm chart](https://www.truefoundry.com/docs/platform/deploy-control-plane-and-gateway-plane). VPC, on-prem, air-gapped, and data residency options are [Enterprise only](https://www.truefoundry.com/pricing), and the SaaS gateway runs in [more than 12 regions](https://www.truefoundry.com/docs/ai-gateway/globally-distributed-saas), with its control plane in Ireland.
- **Compliance.** TrueFoundry's [Trust Center](https://trust.truefoundry.com/) and [SaaS security page](https://www.truefoundry.com/docs/platform/saas-security) list SOC 2 Type II, HIPAA, and GDPR. Some deployment doc pages, such as [modes of deployment](https://www.truefoundry.com/docs/ai-gateway/modes-of-deployment), also claim ISO 27001, which neither source lists as of 2026-10-29.

## Coder Overview for This Comparison

- **AI Gateway.** An intermediary [between users' coding agents or IDEs and providers](https://coder.com/docs/ai-coder/ai-gateway) that supports clients inside or outside Coder workspaces and runs inside `coderd` or as a [standalone, horizontally scalable service](https://coder.com/docs/ai-coder/ai-gateway/standalone). It speaks the [OpenAI and Anthropic API formats](https://coder.com/docs/ai-coder/ai-gateway/providers#provider-types), with provider types for OpenAI, Anthropic, Bedrock, GitHub Copilot, Azure, Google, OpenRouter, Vercel, and any OpenAI-compatible endpoint, plus [key pooling and failover](https://coder.com/docs/ai-coder/ai-gateway/providers#key-failover).
- **Cost controls.** Per-user [spend budgets](https://coder.com/docs/ai-coder/ai-gateway/cost-controls), set by group or for individual users, that stop a user's requests once their spend reaches their budget, plus spend reporting and [Prometheus metrics](https://coder.com/docs/ai-coder/ai-gateway/monitoring#prometheus-metrics).
- **Client coverage.** Tested clients include Claude Code, Codex CLI, OpenCode, Cline, Kilo Code, Factory, Junie, Zed, VS Code, and JetBrains, with GitHub Copilot supported through [AI Gateway Proxy](https://coder.com/docs/ai-coder/ai-gateway/ai-gateway-proxy) ([compatibility table](https://coder.com/docs/ai-coder/ai-gateway/clients#compatibility)).
- **MCP governance.** Coder Agents has organization-scoped [MCP server management](https://coder.com/docs/ai-coder/agents/platform-controls/mcp-servers) with group and user access controls. AI Gateway's original in-gateway MCP tool injection is [deprecated](https://coder.com/docs/ai-coder/ai-gateway/mcp).
- **Coder Workspaces.** Self-hosted environments [defined in Terraform](https://coder.com/docs) where developers and agents run, with each template setting what the workspace can reach on the network ([network boundaries](https://coder.com/docs/ai-coder/agents/platform-controls/template-optimization#configure-network-boundaries)). If a template doesn't restrict outbound access, the workspace has [full internet access](https://coder.com/docs/ai-coder/agents#security-benefits-of-the-control-plane-architecture).
- **Packaging.** AI Gateway is part of AI Governance, included with [Premium](https://coder.com/pricing). [Community deployments can't use it](https://coder.com/docs/ai-coder/ai-gateway/standalone).

## Where TrueFoundry Is Strong or Coder Has a Gap

- **Gateway feature depth.** As a standalone gateway, TrueFoundry documents a broader feature set than Coder's AI Gateway today. The points below are specific.
- **Routing, caching, and rate limits.** TrueFoundry offers [multi-target routing with fallbacks](https://www.truefoundry.com/docs/ai-gateway/virtual-model), a [first chunk gate](https://www.truefoundry.com/docs/ai-gateway/first-chunk-gate) that holds a streaming response until the first chunk arrives so a provider error or slow first token can fall back to another target, [semantic caching](https://www.truefoundry.com/docs/ai-gateway/caching), and [rate limits on requests, tokens, and MCP tool calls](https://www.truefoundry.com/docs/ai-gateway/ratelimiting-v2). Coder documents [key failover within a provider](https://coder.com/docs/ai-coder/ai-gateway/providers#key-failover) and [per-replica request and concurrency limits](https://coder.com/docs/reference/cli/server#--ai-gateway-rate-limit), not cross-provider routing or response caching.
- **Guardrails and content inspection.** TrueFoundry runs [input, output, and MCP tool guardrails](https://www.truefoundry.com/docs/ai-gateway/guardrails-overview), including PII, secrets, and prompt-injection checks and integrations with vendors such as Palo Alto Prisma AIRS, CrowdStrike, and AWS Bedrock Guardrails, and can check Claude Code prompts and tool calls through [hooks](https://www.truefoundry.com/docs/ai-gateway/claude-code-hooks). Coder's AI Governance [doesn't inspect, redact, or block prompt content](../products/coder-ai-governance/playbook.md) the way a DLP or guardrails product does.
- **Full request and response logging.** TrueFoundry stores request and response bodies with [rule-based logging and redaction](https://www.truefoundry.com/docs/ai-gateway/logging-config) and can write them to a customer-owned bucket in Parquet format ([modes of deployment](https://www.truefoundry.com/docs/ai-gateway/modes-of-deployment)). Coder stores the last user prompt, token usage, tool call requests, and reasoning, [not model output text or tool responses](https://coder.com/docs/ai-coder/ai-gateway/audit#what-we-store).
- **Richer budget and attribution model.** TrueFoundry budgets support [team scope, per-model, per-agent, and per-metadata partitions, and audit and soft-enforce modes](https://www.truefoundry.com/docs/ai-gateway/budget-limiting-v2), plus non-human [virtual accounts](https://www.truefoundry.com/docs/platform/virtual-account-management) for applications. Coder's budgets are [per-user, set through groups or user overrides](https://coder.com/docs/ai-coder/ai-gateway/cost-controls).
- **Dedicated MCP Gateway.** TrueFoundry's MCP Gateway includes [hosted stdio servers](https://www.truefoundry.com/docs/ai-gateway/mcp/stdio-mcp-server), which its docs recommend for local IDE development only, [OpenAPI-to-MCP conversion](https://www.truefoundry.com/docs/ai-gateway/mcp/openapi-mcp-server), [tool-call approval workflows](https://www.truefoundry.com/docs/ai-gateway/mcp/mcp-tool-approval), and [federated gateways across networks](https://www.truefoundry.com/docs/ai-gateway/mcp/mcp-federated-architecture). Coder's MCP server management applies to [Coder Agents](https://coder.com/docs/ai-coder/agents/platform-controls/mcp-servers), and AI Gateway's earlier MCP tool injection for other clients is [deprecated](https://coder.com/docs/ai-coder/ai-gateway/mcp).
- **Agent registry and harness.** TrueFoundry registers and proxies agents built on other frameworks, including A2A agents, through its [Agent Registry and Agent Gateway](https://www.truefoundry.com/docs/agent-platform/agent-governance/agent-registry), and hosts custom agents in [TrueForge](https://www.truefoundry.com/docs/agent-platform/agent-harness/overview). Coder's closest equivalent is [Coder Agents](https://coder.com/docs/ai-coder/agents), which runs Coder's own coding agent loop in the self-hosted Coder control plane.
- **Broader API and provider coverage.** TrueFoundry covers [embeddings, images, audio, batch, and realtime endpoints](https://www.truefoundry.com/docs/ai-gateway/intro-to-llm-gateway) across [35+ provider platforms](https://www.truefoundry.com/docs/ai-gateway/supported-providers), and serves applications beyond coding tools. Coder's AI Gateway is built for [coding agents and IDEs](https://coder.com/docs/ai-coder/ai-gateway).
- **Some clients Coder can't route.** TrueFoundry documents [Cursor](https://www.truefoundry.com/docs/ai-gateway/cursor) routing, which it [rates as partial](https://www.truefoundry.com/docs/ai-gateway/coding-agents-governance), and a [Gemini CLI](https://www.truefoundry.com/docs/ai-gateway/gemini-cli) integration. Coder lists Cursor and Gemini CLI as [not supported](https://coder.com/docs/ai-coder/ai-gateway/clients#compatibility) today.
- **SaaS option and free tier.** TrueFoundry offers a [managed, multi-region SaaS gateway](https://www.truefoundry.com/docs/ai-gateway/globally-distributed-saas) and a [$0 Developer plan for up to 3 users](https://www.truefoundry.com/pricing). Coder's AI Gateway is self-hosted and requires [Premium](https://coder.com/pricing).
- **Model serving and fine-tuning.** TrueFoundry can [host open-source models on the customer's GPUs](https://www.truefoundry.com/unified-ai-deployments) behind the same gateway, and in June 2026 it [announced the acquisition of Seldon AI](https://www.truefoundry.com/press-room/truefoundry-acquires-seldon-ai-to-accelerate-agentic-ai-capabilities-for-enterprise-customers), the company behind the Seldon Core model serving framework. Coder doesn't serve models. Its AI Gateway can point at a self-hosted [OpenAI-compatible endpoint](https://coder.com/docs/ai-coder/ai-gateway/providers#openai).
- **Analyst recognition.** TrueFoundry says it is a [representative vendor in Gartner's Market Guide for AI Gateways (October 2025)](https://www.truefoundry.com/blog/building-the-enterprise-ai-control-plane-gartner-r-insights-and-truefoundrys-approach) (company claim).

## Known Limitations in TrueFoundry's Approach

- **Coding-agent enforcement relies on customer devices and networks (as of 2026-10-29).** Where a tool's gateway setting is user-editable, TrueFoundry rates enforcement as partial and tells admins to push the setting with MDM and [block direct vendor endpoints with network policy](https://www.truefoundry.com/docs/ai-gateway/coding-agents-governance), which the customer supplies. Its [aitori](https://www.truefoundry.com/docs/ai-gateway/govern-traffic-through-ai-gateway) device proxy fails open by default if the gateway is unreachable, and TrueFoundry recommends MDM and endpoint tools such as CrowdStrike to block unsanctioned apps. The sandbox and egress allowlists in its [TrueForge harness](https://www.truefoundry.com/docs/agent-platform/agent-harness/what-truefoundry-adds) apply to agents run there, not to Claude Code, Codex, or IDE sessions on developer devices.
- **Self-hosted installs still use TrueFoundry's auth server (as of 2026-10-29).** Self-hosted control planes authenticate users through TrueFoundry's [central auth server](https://www.truefoundry.com/docs/ai-gateway/modes-of-deployment), which receives user emails and gateway request counts, unless an on-prem deployment on the [higher-tier Enterprise plan](https://www.truefoundry.com/docs/platform/sso/overview) connects the customer's IdP directly. Self-hosted gateways also send [hourly usage analytics](https://www.truefoundry.com/docs/platform/onprem-security#what-leaves-your-environment) without prompt or response content, much as Coder's AI Governance [reports usage data by default](https://coder.com/docs/install/prepare/airgap). TrueFoundry's [air-gapped install guidance](https://www.truefoundry.com/docs/platform/deploy-control-plane-faq) covers mirroring images but not the auth or analytics servers.
- **Output guardrails skip streamed responses (as of 2026-10-29).** Output guardrails are [not applied when `stream: true`](https://www.truefoundry.com/docs/ai-gateway/guardrails-overview), and no guardrails run on realtime or speech requests. Input guardrails still run on streamed requests, and TrueFoundry's [GitHub Copilot guide](https://www.truefoundry.com/docs/ai-gateway/github-copilot) requires models that support streaming.
- **Some built-in guardrails are SaaS only (as of 2026-10-29).** The built-in content moderation, PII/PHI, and prompt-injection guardrails, which run on Azure AI services, are [only available on TrueFoundry SaaS](https://www.truefoundry.com/docs/ai-gateway/guardrails-overview). Self-hosted customers use alternatives such as bring-your-own-key Azure, AWS Bedrock Guardrails, CrowdStrike, or Palo Alto Prisma AIRS.
- **Customer-bucket logging still involves TrueFoundry's control plane (as of 2026-10-29).** In the SaaS option with a customer bucket, request and response data [flows through TrueFoundry's control plane](https://www.truefoundry.com/docs/ai-gateway/modes-of-deployment) before it's stored. With a customer-hosted gateway and a TrueFoundry-hosted control plane, the control plane needs [access to the customer's bucket](https://www.truefoundry.com/docs/ai-gateway/modes-of-deployment) to browse and index logs.
- **Partial coverage for some coding tools (as of 2026-10-29).** TrueFoundry rates [Cursor and GitHub Copilot as partial](https://www.truefoundry.com/docs/ai-gateway/coding-agents-governance) for model traffic. Cursor Tab completions and some agent features stay on Cursor's backend, and Copilot inline completions always use GitHub's models.
- **Some agent governance controls are labeled coming soon (as of 2026-10-29).** Agent discovery and per-hop token exchange are [labeled coming soon](https://www.truefoundry.com/docs/agent-platform/agent-governance/truefoundry-implementation). Per-agent tool scope and a one-click kill switch are also coming soon, with virtual MCP servers and grant revocation available today.

## Common Questions

- **Is Coder a TrueFoundry replacement?** Partly. The two overlap at the gateway layer, where TrueFoundry has the deeper feature set today, and partly on environments. Coder's [general-purpose workspaces](https://coder.com/docs) go beyond TrueFoundry's ML workbench, and their [template network policy](https://coder.com/docs/ai-coder/agents/platform-controls/template-optimization#configure-network-boundaries) applies to everything in the workspace, while TrueFoundry's egress allowlists cover agents in its [TrueForge sandbox](https://trueforge.dev/sandbox). TrueFoundry's model serving and fine-tuning have no Coder equivalent.
- **We already run TrueFoundry. Do we have to remove it?** No. Coder's AI Gateway can use [an OpenAI-compatible endpoint, such as a hosted proxy](https://coder.com/docs/ai-coder/ai-gateway/providers#openai), or an [Anthropic-compatible broker](https://coder.com/docs/ai-coder/ai-gateway/providers#provider-types) as an upstream provider, and TrueFoundry exposes [OpenAI-compatible and Anthropic Messages endpoints](https://www.truefoundry.com/docs/ai-gateway/messages-overview). Neither vendor documents this specific pairing, so confirm it during a pilot.
- **Why pay for Coder's AI Gateway when TrueFoundry has a free plan?** If the need is a proxy with routing, budgets, and guardrails, TrueFoundry may be enough, though its free Developer plan excludes [guardrails and SSO](https://www.truefoundry.com/pricing). The difference is knowing which developer, workspace, and agent session produced a request, and controlling what that agent could reach. Coder [attributes every interaction to a user](https://coder.com/docs/ai-coder/ai-gateway), groups activity into [sessions](https://coder.com/docs/ai-coder/ai-gateway/audit), and sets egress in the [workspace template](https://coder.com/docs/ai-coder/agents/platform-controls/template-optimization#configure-network-boundaries).
- **Doesn't TrueFoundry also offer dev environments?** It offers [Jupyter notebooks](https://www.truefoundry.com/docs/launch-notebooks) and [SSH servers for local VS Code](https://www.truefoundry.com/docs/launch-an-ssh-server) on Kubernetes, with notebooks framed around ML work. Coder templates cover [VMs, Kubernetes, and Docker across Windows, Linux, and macOS](https://coder.com/docs), with access from most major IDEs.
- **Can both govern Claude Code?** Yes, for model traffic. TrueFoundry documents [Claude Code routing and subscription passthrough](https://www.truefoundry.com/docs/ai-gateway/claude-code) and [hooks that send prompts and tool calls to its guardrails](https://www.truefoundry.com/docs/ai-gateway/claude-code-hooks). Coder supports [Claude Code](https://coder.com/docs/ai-coder/ai-gateway/clients#compatibility), and when Claude Code runs in a Coder workspace, the template also controls what it can reach.
- **Are both self-hosted?** Coder is self-hosted, including [air-gapped deployments](https://coder.com/docs/install/prepare/airgap). TrueFoundry offers SaaS on every plan and VPC, on-prem, and air-gapped installs on [Enterprise](https://www.truefoundry.com/pricing), and its self-hosted installs authenticate users through TrueFoundry's [auth server](https://www.truefoundry.com/docs/ai-gateway/modes-of-deployment) unless an on-prem customer on its higher-tier Enterprise plan [connects its IdP directly](https://www.truefoundry.com/docs/platform/sso/overview).
- **Is Coder's AI Gateway free?** No. It requires [Premium](https://coder.com/pricing), and [Community deployments can't use it](https://coder.com/docs/ai-coder/ai-gateway/standalone).

## When TrueFoundry Alone Is Enough

- **Application teams building LLM features.** Teams that need one endpoint, routing, caching, and guardrails across many providers for their own applications are the use case TrueFoundry's [gateway](https://www.truefoundry.com/docs/ai-gateway/intro-to-llm-gateway) is built for.
- **Organizations that also host their own models.** Teams serving open-source models on their own GPUs can put [deployment](https://www.truefoundry.com/unified-ai-deployments) and gateway on one platform.
- **Teams building and hosting their own agents.** TrueFoundry pairs its gateway with an [Agent Registry](https://www.truefoundry.com/docs/agent-platform/agent-governance/agent-registry) and a hosted [agent harness](https://www.truefoundry.com/docs/agent-platform/agent-harness/overview).
- **Teams that need content guardrails or advanced routing today.** TrueFoundry's [guardrails](https://www.truefoundry.com/docs/ai-gateway/guardrails-overview) and [routing](https://www.truefoundry.com/docs/ai-gateway/virtual-model) go further than Coder's AI Gateway does today.
- **Organizations comfortable with SaaS.** Teams that don't need self-hosting can start on the [SaaS gateway](https://www.truefoundry.com/docs/ai-gateway/globally-distributed-saas) without running infrastructure.
- **Teams not yet running coding agents against sensitive systems.** Without agents executing code inside internal networks, governed workspaces and template network policy matter less.

## Pricing and Packaging

- **TrueFoundry.** Per the [pricing page](https://www.truefoundry.com/pricing), Developer is $0 for up to 3 users with 10K requests and tool calls per user per month. Pro is $25 per user per month with 20K requests and tool calls per user, pooled across the team, plus $20 per additional 100K requests, SSO, and built-in guardrails. Enterprise is a custom annual contract and the only tier with VPC, on-prem, air-gapped, and data residency options, MCP tool approvals, and third-party guardrails. MCP tool calls count as requests, model costs pass through without markup, and Agent Gateway and Agent Harness pricing is custom.
- **TrueFoundry service levels and marketplace.** TrueFoundry's [SLA](https://www.truefoundry.com/service-level-agreement) commits to 99.99% uptime for Enterprise, on SaaS or on-prem, and gives Developer and Pro best-effort availability with no SLA. Its [AWS Marketplace listing](https://aws.amazon.com/marketplace/pp/prodview-cfheeich3ggpy) sells AI Gateway as contract units labeled Pro, Enterprise, and On-Prem, at $6,250, $12,500, and $16,666.66 per month, which the listing doesn't map to the website's per-user prices.
- **Coder.** AI Gateway is included with [Premium](https://coder.com/pricing). See [coder.com/pricing](https://coder.com/pricing) for current tiers and [Packaging](../company/packaging.md) for the narrative behind them.
