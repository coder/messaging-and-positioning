*(Claude Managed Agents is Anthropic's API platform for building and running agents. It has three hosting options. Anthropic can host everything, the customer can host only the sandboxes, or, since the [private beta announced on 2026-11-12](https://claude.com/resources/articles/self-hosted-claude-managed-agents), the customer can host the whole service. This page focuses on the self-hosted service, because that is where it competes with Coder Agents. Claude Managed Agents is a different product from Claude Code and its self-hosted environments, which are covered in [Coder and Claude Code](./claude-code.md).)*

## One-Line Positioning

Self-hosted Claude Managed Agents gives teams a Claude-only agent harness and sandbox service to build agents on and operate themselves, while Coder Agents is a ready, model-neutral coding agent that runs in the Coder deployment and workspaces a customer already operates, governed alongside every other agent its developers use.

## Strategic Themes and Patterns

- **Relationship.** Competitive for unattended coding agents, and complementary at the model layer. Anthropic positions self-hosted Managed Agents for agents that fix broken builds, test releases, triage alerts, and work through a bug backlog inside a company's own code and systems ([Anthropic announcement](https://claude.com/resources/articles/self-hosted-claude-managed-agents)). Coder Agents targets the same background development work, with an API built for CI and webhook triggers ([Coder Agents docs](https://coder.com/docs/@main/coder-agents/getting-started#use-the-api-for-programmatic-automation)). Claude models also power Coder Agents through Anthropic, Amazon Bedrock, or an Anthropic-compatible endpoint ([Coder Agents models](https://coder.com/docs/@main/coder-agents/models#providers)), so a customer can use Claude without choosing Anthropic's harness.
- **The architectures are similar.** Anthropic separates the harness that calls Claude from the sandbox where the agent's code runs, and keeps credentials out of the sandbox ([Anthropic announcement](https://claude.com/resources/articles/self-hosted-claude-managed-agents)). Coder Agents also runs its agent loop in the Coder control plane and uses workspaces only for file and shell work, with no LLM credentials in the workspace ([Coder Agents architecture](https://coder.com/docs/@main/coder-agents/architecture#what-runs-where)). The difference is not where the loop runs. It is what surrounds it, which models it can use, and what the customer has to build and operate.
- **Choice, Control, Consistency.** The main tradeoff is Choice. Self-hosted Managed Agents runs Claude models, and every inference route it documents carries Claude requests, whether to Anthropic, Amazon Bedrock, Google Cloud, Microsoft Foundry, or a customer gateway ([Anthropic inference provider docs](https://platform.claude.com/docs/en/managed-agents/self-hosted/inference-provider)). Coder Agents supports Anthropic, OpenAI, Google, Azure OpenAI, Amazon Bedrock, OpenRouter, Vercel AI Gateway, and any OpenAI-compatible endpoint, including self-hosted models ([Coder Agents models](https://coder.com/docs/@main/coder-agents/models#providers)). Control is close for the agent itself, since both can run on the customer's infrastructure. Consistency differs. Managed Agents sandboxes are per-session containers or pods built for the agent ([Anthropic Kubernetes docs](https://platform.claude.com/docs/en/managed-agents/self-hosted/kubernetes)), while Coder Agents works in Terraform-defined workspaces that developers also use ([Coder Workspaces message house](../products/coder-workspaces/message-house.md)).
- **Lock-in risk.** Agents, skills, and workflows built on the Managed Agents API run on Anthropic's harness with Claude models ([Claude Managed Agents overview](https://platform.claude.com/docs/en/managed-agents/overview)). Moving them to another model family means rebuilding them on a different harness. Coder Agents lets an organization change or mix model providers without changing the agent or the platform ([Coder Agents message house](../products/coder-agents/message-house.md)).
- **Build versus buy.** Self-hosted Managed Agents supplies the harness, but the customer still builds and runs a lot around it. Production runs on Kubernetes 1.30 or later with the Agent Sandbox controller, gVisor nodes, a CNI that enforces NetworkPolicy, external PostgreSQL 16 or later, and images the customer builds ([Anthropic Kubernetes docs](https://platform.claude.com/docs/en/managed-agents/self-hosted/kubernetes)). The customer also writes the applications that create sessions, since the product is an API ([Anthropic self-hosted docs](https://platform.claude.com/docs/en/managed-agents/self-hosted)). Coder Agents is part of the Coder deployment, with a chat interface and API already in place ([Coder Agents docs](https://coder.com/docs/@main/coder-agents)). This is the build-it-yourself pattern described in [Why Coder](../company/why-coder.md), applied to everything around a vendor's harness.
- **Where Claude Managed Agents is sufficient on its own.** Anthropic designed it for developers building agents into their own applications, including non-coding agents ([Anthropic launch post](https://claude.com/blog/claude-managed-agents)). Teams standardized on Claude that don't need full developer environments, other models, or one governance layer across several agents can meet the need without Coder.

## Coder's Strengths Here

- **Any model, including self-hosted models.** Coder Agents can use several providers at once, with a default model per organization ([Coder Agents docs](https://coder.com/docs/@main/coder-agents#llm-provider-support)). Self-hosted and open-weight models connect through the OpenAI-compatible provider ([Coder Agents models](https://coder.com/docs/@main/coder-agents/models#providers)).
- **A ready agent product, not a toolkit.** Developers delegate work through a chat interface with plan mode, and automation calls the Chats API ([Coder Agents docs](https://coder.com/docs/@main/coder-agents), [Chats API reference](https://coder.com/docs/@main/reference/api/chats)). With Managed Agents, the customer builds the agent definitions and the applications that start and follow sessions ([Anthropic self-hosted docs](https://platform.claude.com/docs/en/managed-agents/self-hosted)).
- **No new platform for Coder customers.** Coder Agents ships in the same Coder deployment, uses the same templates and RBAC, and needs no agent software or API keys in the workspace ([Coder Agents docs](https://coder.com/docs/@main/coder-agents)). Self-hosted Managed Agents is a separate service with its own server, database, sandbox charts, and release upgrades ([Anthropic self-hosted docs](https://platform.claude.com/docs/en/managed-agents/self-hosted), [Anthropic upgrade docs](https://platform.claude.com/docs/en/managed-agents/self-hosted/upgrade)).
- **Full development environments.** Coder Agents picks a workspace from the templates a user can access, and developers can open the same workspace in VS Code, Cursor, or JetBrains to review and finish the work ([Coder Agents docs](https://coder.com/docs/@main/coder-agents#automatic-workspace-provisioning), [Coder Agents docs](https://coder.com/docs/@main/coder-agents#what-coder-agents-is-and-isnt)).
- **Every action tied to the person who asked.** Coder Agents has exactly the permissions of the user who started it, and commits and pull requests go through that user's own Git authentication ([Coder Agents architecture](https://coder.com/docs/@main/coder-agents/architecture#user-identity-on-every-action), [Coder Agents architecture](https://coder.com/docs/@main/coder-agents/architecture#permission-boundaries)). A self-hosted Managed Agents server writes commits under one configured author, `Claude` by default ([Anthropic configuration reference](https://platform.claude.com/docs/en/managed-agents/self-hosted/configuration-reference)).
- **Multiple teams on one deployment.** Coder Agents scopes models and MCP servers per organization and limits each user to their own workspaces and templates ([Coder Agents organizations](https://coder.com/docs/@main/coder-agents/platform-controls/organizations), [Coder Agents architecture](https://coder.com/docs/@main/coder-agents/architecture#permission-boundaries)). Anthropic says each self-hosted Managed Agents deployment serves one tenant at one trust level, and every caller with a role can run sessions in every environment ([Anthropic data and access docs](https://platform.claude.com/docs/en/managed-agents/self-hosted-data-and-access)).
- **One governance layer across agents.** AI Gateway records prompts, token usage, and tool calls for Coder Agents and for supported clients such as Claude Code and Codex ([AI Gateway docs](https://coder.com/docs/@main/ai-governance/ai-gateway)). Template network policy applies to every process in a workspace, whichever agent started it ([Coder template optimization](https://coder.com/docs/@main/coder-agents/platform-controls/template-optimization#configure-network-boundaries)). Managed Agents governs the agents built on Managed Agents.
- **Documented air-gapped deployment.** Coder documents air-gapped installs, and Coder Agents can use self-hosted models there ([Coder air-gapped docs](https://coder.com/docs/@main/install/prepare/airgap), [Coder Agents docs](https://coder.com/docs/@main/coder-agents#what-coder-agents-is-and-isnt)). Agent Time reporting needs an outbound HTTPS connection to Coder unless the customer makes other arrangements with Coder ([Coder Agents licensing](https://coder.com/docs/@main/coder-agents/licensing-usage#agent-time-usage-reporting)).
- **Generally available.** Coder Agents is generally available ([Coder Agents getting started](https://coder.com/docs/@main/coder-agents/getting-started#plan-for-change-between-releases)). Self-hosted Managed Agents is in private beta ([Anthropic announcement](https://claude.com/resources/articles/self-hosted-claude-managed-agents)).

## Claude Managed Agents Overview

- **What it is.** A pre-built, configurable agent harness and the infrastructure to run it, built around agents, environments, sessions, and events ([Claude Managed Agents overview](https://platform.claude.com/docs/en/managed-agents/overview)). Anthropic describes it as a suite of composable APIs for building and deploying agents ([Anthropic announcement](https://claude.com/resources/articles/self-hosted-claude-managed-agents)).
- **Status.** The hosted service launched in beta on 2026-04-08, self-hosted sandboxes followed on 2026-05-19, and the self-hosted service launched on 2026-11-12 ([Claude Platform release notes](https://platform.claude.com/docs/en/release-notes/overview)). The self-hosted service is in private beta, and access goes through the Anthropic account team ([Anthropic announcement](https://claude.com/resources/articles/self-hosted-claude-managed-agents), [Anthropic self-hosted docs](https://platform.claude.com/docs/en/managed-agents/self-hosted)).
- **Hosting options.** With cloud sandboxes, Anthropic hosts the sandboxes and the service. With self-hosted sandboxes, the customer hosts the sandboxes and Anthropic runs the service. With self-hosted Managed Agents, the customer hosts both and chooses the model provider ([Anthropic self-hosted docs](https://platform.claude.com/docs/en/managed-agents/self-hosted)).
- **Architecture, self-hosted.** The customer runs `cma-server`, which serves the API, runs the agent loop, and stores agents, sessions, and history, plus a PostgreSQL database and workers that run the agent's shell and file tools in sandboxes ([Anthropic self-hosted docs](https://platform.claude.com/docs/en/managed-agents/self-hosted)). The server never runs shell or file tools itself, and it never connects to a worker ([Anthropic data and access docs](https://platform.claude.com/docs/en/managed-agents/self-hosted-data-and-access)).
- **Security features.** Self-hosted servers add single sign-on through an OpenID Connect identity provider with admin, developer, and user roles, secrets stored in the customer's secret manager, and short-lived agent identity tokens for MCP servers ([Anthropic differences page](https://platform.claude.com/docs/en/managed-agents/self-hosted/differences), [Anthropic SSO docs](https://platform.claude.com/docs/en/managed-agents/self-hosted/configure)). Vaults keep credentials out of the sandbox, and environments can be limited to a list of allowed hosts ([Anthropic announcement](https://claude.com/resources/articles/self-hosted-claude-managed-agents), [Anthropic vaults docs](https://platform.claude.com/docs/en/managed-agents/vaults)).
- **Inference.** The server can call the Claude API, Amazon Bedrock, Claude Models on Google Cloud, Microsoft Foundry, or a customer-run gateway ([Anthropic inference provider docs](https://platform.claude.com/docs/en/managed-agents/self-hosted/inference-provider)). It contacts Anthropic only when the Claude API is the provider, and Anthropic says it has no remote access to the server or its logs ([Anthropic data and access docs](https://platform.claude.com/docs/en/managed-agents/self-hosted-data-and-access)).
- **Target customer.** Developers building agents through the API. Anthropic's launch customers include Notion, Rakuten, Asana, and Sentry ([Anthropic launch post](https://claude.com/blog/claude-managed-agents)).
- **Deployment model.** Hosted SaaS by default, a hybrid with customer-hosted sandboxes, or a customer-operated service in the customer's own cloud or on-premises ([Anthropic announcement](https://claude.com/resources/articles/self-hosted-claude-managed-agents)).

## Coder Overview for This Comparison

- **Coder Agents.** A chat interface and API for delegating development work to Coder's own agent, whose loop runs in the Coder control plane on the customer's infrastructure ([Coder Agents docs](https://coder.com/docs/@main/coder-agents)). Chat state lives in the Coder database and survives a workspace being rebuilt or deleted ([Coder Agents architecture](https://coder.com/docs/@main/coder-agents/architecture#chat-state-and-persistence)).
- **Platform controls.** Admins set providers, models, system prompts, MCP servers, concurrency, and spend limits, and the server enforces these settings rather than leaving them to user preference ([Coder Agents platform controls](https://coder.com/docs/@main/coder-agents/platform-controls)).
- **Workspace network policy.** Coder describes the workspace as the network boundary for the agent, and an agent workspace needs to reach only the control plane and the Git provider ([Coder template optimization](https://coder.com/docs/@main/coder-agents/platform-controls/template-optimization#configure-network-boundaries)). Agent workspaces get normal workspace network access unless the template restricts it.
- **AI Gateway.** Part of AI Governance in Premium. It sits between agents and model providers, authenticates requests with Coder identities, and records prompts, token usage, and tool calls ([AI Gateway docs](https://coder.com/docs/@main/ai-governance/ai-gateway)). Coder Agents routes its model requests through AI Gateway automatically ([Coder Agents models](https://coder.com/docs/@main/coder-agents/models#providers)).
- **Agent Relay.** A Premium beta that connects Claude Code cloud sessions and Cursor cloud agent sessions to ephemeral Coder workspaces ([Agent Relay docs](https://coder.com/docs/@main/agent-relay#supported-providers)). For Claude, it is built on Claude Code self-hosted environments. Claude Managed Agents is not a supported provider ([Agent Relay for Claude Code](https://coder.com/docs/@main/agent-relay/claude-code)).

## Where Claude Managed Agents Is Strong or Coder Has a Gap

- **A first-party harness from the model provider.** Anthropic builds the harness for Claude ([Anthropic launch post](https://claude.com/blog/claude-managed-agents)). Teams that want Anthropic's own agent loop get it directly.
- **The same API hosted or self-hosted.** A self-hosted server has the same API as the hosted service, apart from documented differences ([Anthropic differences page](https://platform.claude.com/docs/en/managed-agents/self-hosted/differences)). Teams can start on the hosted service and move in-house without rewriting their applications, although agents, skills, and credentials have to be recreated on the new server.
- **Built for agents inside other applications.** Managed Agents is designed for developers embedding agents in their own products and internal tools, including productivity, finance, and legal agents ([Anthropic launch post](https://claude.com/blog/claude-managed-agents)). Coder Agents can be extended beyond coding, but its focus is software development ([Coder Agents FAQ](../products/coder-agents/faq.md#11-use-cases-and-future-direction)).
- **Sandbox isolation in the reference deployment.** The Kubernetes install runs each session's sandbox as a gVisor pod with network policy ([Anthropic Kubernetes docs](https://platform.claude.com/docs/en/managed-agents/self-hosted/kubernetes)). In Coder, agent workspace isolation depends on the template, and the separate agent pod pattern is in early access ([Coder agent isolation guide](https://coder.com/docs/@main/coder-agents/platform-controls/agent-isolation)).
- **Credential injection for agent tools.** With the egress gateway turned on, the server substitutes secrets for placeholder values at egress, so the agent never sees the secret value ([Anthropic vaults docs](https://platform.claude.com/docs/en/managed-agents/vaults), [Anthropic agent identity docs](https://platform.claude.com/docs/en/managed-agents/self-hosted/agent-identity)). Coder keeps LLM credentials out of workspaces ([Coder Agents architecture](https://coder.com/docs/@main/coder-agents/architecture#no-api-keys-in-workspaces)), and templates decide which other credentials a workspace holds.

## Known Limitations in Claude Managed Agents' Approach

- **Claude models only (as of 2026-11-12).** Every documented inference route carries Claude requests, and a mapped model ID must name the same model the agent asked for ([Anthropic inference provider docs](https://platform.claude.com/docs/en/managed-agents/self-hosted/inference-provider)).
- **Private beta with pricing through sales (as of 2026-11-12).** Access to the self-hosted download and its pricing both go through the Anthropic account team ([Anthropic self-hosted docs](https://platform.claude.com/docs/en/managed-agents/self-hosted), [Claude pricing docs](https://platform.claude.com/docs/en/about-claude/pricing)).
- **Hosted features missing from the self-hosted server (as of 2026-11-12).** Cloud environments, the Files API, webhooks, scheduled deployments, OAuth credentials for MCP servers, and Anthropic's prebuilt document skills are not available. Multiagent work is limited to a coordinator with 1 to 20 listed agents ([Anthropic differences page](https://platform.claude.com/docs/en/managed-agents/self-hosted/differences)).
- **A new Kubernetes stack to operate (as of 2026-11-12).** Anthropic says the Docker Compose stack is for development, not production ([Anthropic quickstart](https://platform.claude.com/docs/en/managed-agents/self-hosted/quickstart)). Production uses two Helm charts with the cluster requirements listed above, and the customer builds the images ([Anthropic Kubernetes docs](https://platform.claude.com/docs/en/managed-agents/self-hosted/kubernetes)).
- **Isolation comes from the customer's sandbox (as of 2026-11-12).** The agent's shell has the worker process's permissions and network access, and the worker doesn't isolate it ([Anthropic self-hosted docs](https://platform.claude.com/docs/en/managed-agents/self-hosted)).
- **One tenant per deployment (as of 2026-11-12).** Environments in one deployment don't keep trust levels apart ([Anthropic data and access docs](https://platform.claude.com/docs/en/managed-agents/self-hosted-data-and-access)).
- **Conversation data goes to the model provider (as of 2026-11-12).** By default, each model request from a self-hosted server sends the conversation history and tool results to Anthropic ([Anthropic environment guide](https://platform.claude.com/docs/en/managed-agents/choosing-an-environment)). Pointing the server at Bedrock, Google Cloud, Foundry, or a gateway changes where that data goes, not whether a model provider receives it.
- **With self-hosted sandboxes only, the service stays with Anthropic (as of 2026-11-12).** In that mode, conversation history, tool results, skills, and memory stores reach Anthropic ([Anthropic environment guide](https://platform.claude.com/docs/en/managed-agents/choosing-an-environment)). Managed Agents is not eligible for zero data retention except for the self-hosted service ([Claude Managed Agents overview](https://platform.claude.com/docs/en/managed-agents/overview)).
- **No documented disconnected deployment (as of 2026-11-12).** Anthropic's self-hosted docs describe connections to the chosen inference provider and don't describe running without one ([Anthropic data and access docs](https://platform.claude.com/docs/en/managed-agents/self-hosted-data-and-access)). Claude models are reached through Anthropic, a cloud provider, or a customer gateway in front of one ([Anthropic inference provider docs](https://platform.claude.com/docs/en/managed-agents/self-hosted/inference-provider)).

## Common Questions

- **Anthropic now lets us self-host Managed Agents. Why would we use Coder Agents instead?** Choose Coder Agents when the organization wants a ready coding agent on the Coder deployment it already runs, the freedom to use any model, including self-hosted models, and one set of identity, network, and audit controls across all of its agents ([Coder Agents docs](https://coder.com/docs/@main/coder-agents), [Coder Agents models](https://coder.com/docs/@main/coder-agents/models#providers)). Choose self-hosted Managed Agents when a team is standardized on Claude, wants Anthropic's harness, and is building agents into its own applications on a Kubernetes stack it will operate ([Anthropic self-hosted docs](https://platform.claude.com/docs/en/managed-agents/self-hosted)).
- **Why would we use Coder Agent Relay instead of Managed Agents?** They answer different needs. Agent Relay gives developers the Claude Code or Cursor experience they already use, with execution in governed Coder workspaces, while Anthropic or Cursor keeps orchestration and inference ([Agent Relay docs](https://coder.com/docs/@main/agent-relay#what-agent-relay-is-and-isnt)). Managed Agents is for building custom agents on Anthropic's API. When everything, including the agent loop, has to run in-house, Coder's answer is Coder Agents ([Agent Relay message house](../products/coder-agent-relay/message-house.md)).
- **Does Agent Relay support Claude Managed Agents?** No. Agent Relay supports Claude Code self-hosted environments and Cursor self-hosted machines ([Agent Relay docs](https://coder.com/docs/@main/agent-relay#supported-providers)).
- **Is Claude Managed Agents the same as Claude Code's self-hosted environments?** No. Claude Code self-hosted environments run Claude Code cloud sessions on customer runners for Team and Enterprise plans ([Claude Code docs](https://code.claude.com/docs/en/self-hosted-environments)). Managed Agents is an API platform for building agents ([Claude Managed Agents overview](https://platform.claude.com/docs/en/managed-agents/overview)). Agent Relay is built on the first ([Agent Relay for Claude Code](https://coder.com/docs/@main/agent-relay/claude-code)).
- **Both keep the agent loop on our infrastructure. What's the real difference?** Models, environments, and scope. Managed Agents runs Claude only, in per-session sandboxes, for agents built on its API ([Anthropic inference provider docs](https://platform.claude.com/docs/en/managed-agents/self-hosted/inference-provider), [Anthropic Kubernetes docs](https://platform.claude.com/docs/en/managed-agents/self-hosted/kubernetes)). Coder Agents runs any configured model, in the Terraform-defined workspaces developers also use, inside a platform that also governs Claude Code, Codex, and other agents ([Coder Agents docs](https://coder.com/docs/@main/coder-agents), [AI Gateway docs](https://coder.com/docs/@main/ai-governance/ai-gateway)).
- **Can we use Claude models with Coder Agents?** Yes. Coder Agents supports Anthropic directly, including Claude Platform on AWS, and Amazon Bedrock ([Coder Agents models](https://coder.com/docs/@main/coder-agents/models#providers), [Coder Agents message house](../products/coder-agents/message-house.md)).
- **Can a self-hosted Managed Agents server send its model calls through Coder AI Gateway?** Neither company documents this combination as of 2026-11-12. Anthropic documents pointing the server at a gateway that accepts Claude API requests ([Anthropic inference provider docs](https://platform.claude.com/docs/en/managed-agents/self-hosted/inference-provider)), and AI Gateway exposes an Anthropic-compatible base URL ([AI Gateway clients](https://coder.com/docs/@main/ai-governance/ai-gateway/clients#base-urls)). Treat it as a configuration to validate, not a supported integration.
- **Which is ready for production?** Coder Agents is generally available ([Coder Agents getting started](https://coder.com/docs/@main/coder-agents/getting-started#plan-for-change-between-releases)). Self-hosted Managed Agents is in private beta, and the hosted service is in beta ([Anthropic announcement](https://claude.com/resources/articles/self-hosted-claude-managed-agents), [Claude Managed Agents overview](https://platform.claude.com/docs/en/managed-agents/overview)).
- **Can we use both?** Yes. A team can build Claude agents into its own products with Managed Agents while developers use Coder Agents, Claude Code, and other agents in Coder workspaces. No native integration between the two exists today.

## When Claude Managed Agents Alone Is Enough

- **Building Claude agents into a product or internal tool.** Teams embedding agents in their own software, including non-coding agents, get a harness, sandboxes, and session storage without writing their own agent loop ([Claude Managed Agents overview](https://platform.claude.com/docs/en/managed-agents/overview)).
- **Claude-standardized teams that don't need developer environments.** If agents need only a sandbox and the organization has no plan to use other models, Managed Agents covers the need.
- **Teams comfortable with a hosted service.** With cloud sandboxes, Anthropic hosts both the sandboxes and the service ([Anthropic self-hosted docs](https://platform.claude.com/docs/en/managed-agents/self-hosted)).

## Pricing and Packaging

- **Hosted Managed Agents.** Billed on tokens at standard Claude API rates plus $0.08 per session-hour while a session is running ([Claude pricing docs](https://platform.claude.com/docs/en/about-claude/pricing)).
- **Self-hosted Managed Agents.** Pricing is not public. Anthropic asks customers to contact their account team ([Claude pricing docs](https://platform.claude.com/docs/en/about-claude/pricing)).
- **Coder.** Every tier can run Coder Agents. Community and Premium allow five concurrent agents, and AI Premium removes the cap with a pool of Agent Hours ([Coder pricing](https://coder.com/pricing), [Coder Agents licensing](https://coder.com/docs/@main/coder-agents/licensing-usage)). Customers pay their own model providers. See [Packaging](../company/packaging.md) for the narrative.
