*(Claude Managed Agents is Anthropic's platform for configuring and running agents. Customers can use Anthropic-hosted service and sandboxes, host only the sandboxes, or host the service and sandboxes themselves ([hosting options](https://platform.claude.com/docs/en/managed-agents/self-hosted)). The self-hosted service entered private beta on November 12, 2026 ([Anthropic announcement](https://claude.com/resources/articles/self-hosted-claude-managed-agents), [dated articles index](https://claude.com/resources/articles)). It is a different product from Claude Code and its self-hosted environments, covered in [Coder and Claude Code](./claude-code.md).)*

## One-Line Positioning

Self-hosted Claude Managed Agents supplies Anthropic's configurable Claude harness and sandbox stack; Coder Agents supplies a coding agent workflow across supported model providers, integrated with the development workspaces Coder manages for people and agents ([Anthropic docs](https://platform.claude.com/docs/en/managed-agents/self-hosted), [Coder Agents docs](https://coder.com/docs/ai-coder/agents)).

## Strategic Themes and Patterns

- **Relationship.** The products compete for unattended coding work: Anthropic names build repair, release testing, alert triage, and backlog work, while Coder documents similar automation through its agent API ([Anthropic announcement](https://claude.com/resources/articles/self-hosted-claude-managed-agents), [Coder automation docs](https://coder.com/docs/ai-coder/agents/getting-started#use-the-api-for-programmatic-automation)). The relationship is also complementary: Claude models can power Coder Agents, and developers can use Claude Code in Coder workspaces without adopting Managed Agents ([Coder models](https://coder.com/docs/ai-coder/agents/models#providers), [Claude Code on Coder](./claude-code.md)).
- **Similar architecture, different platform choices.** Both self-hosted services separate the agent loop from the environment where shell and file tools execute, and keep LLM provider credentials outside that execution environment ([Anthropic docs](https://platform.claude.com/docs/en/managed-agents/self-hosted), [Coder architecture](https://coder.com/docs/ai-coder/agents/architecture#what-runs-where)). The comparison is therefore not simply hosted versus self-hosted: it is about model support, development workflows, controls, and operating responsibilities.
- **Model choice and agent choice are different.** Managed Agents documents Claude inference through Anthropic, Amazon Bedrock, Google Cloud, Microsoft Foundry, or a compatible gateway; those are serving options for Claude, not documented support for other model families ([Anthropic inference providers](https://platform.claude.com/docs/en/managed-agents/self-hosted/inference-provider)). Coder Agents retains Coder's own harness while supporting multiple model families and compatible self-hosted endpoints; choosing a different harness, such as Claude Code or Codex, means running that separate agent in a Coder workspace ([Coder models](https://coder.com/docs/ai-coder/agents/models#providers), [Coder Workspaces](../products/coder-workspaces/message-house.md)).
- **Model and harness dependence.** Adopting another harness requires adapting Managed Agents-specific API integrations and revalidating behavior, but compatible skills, MCP servers, and application-owned tools can be reused rather than rebuilt wholesale ([Managed Agents overview](https://platform.claude.com/docs/en/managed-agents/overview), [skills](https://platform.claude.com/docs/en/managed-agents/skills), [MCP](https://platform.claude.com/docs/en/managed-agents/mcp-connector), [custom tools](https://platform.claude.com/docs/en/managed-agents/tools)). Coder supports switching among configured, supported models while retaining its agent and platform; that is not a guarantee of identical model behavior or zero migration work ([Coder Agents docs](https://coder.com/docs/ai-coder/agents)).
- **Both self-hosted options require operations.** Anthropic supplies deployable service and worker software, a console, and reference sandbox deployment tooling; customers configure, secure, operate, and upgrade them ([Anthropic docs](https://platform.claude.com/docs/en/managed-agents/self-hosted), [upgrade guide](https://platform.claude.com/docs/en/managed-agents/self-hosted/upgrade)). Existing Coder customers can reuse their deployment, templates, and identity integration for Coder Agents; new customers must establish and operate that platform, and both groups maintain their workspace templates and infrastructure ([Coder Agents docs](https://coder.com/docs/ai-coder/agents), [template guidance](https://coder.com/docs/ai-coder/agents/platform-controls/template-optimization)).

## Who Supplies and Operates the Execution Environments?

- **Anthropic supplies an execution stack, not just a harness.** Its self-hosted distribution includes workers, a browser console, development Compose configuration, and production-oriented Helm charts with a dispatcher that allocates session sandboxes ([Anthropic overview](https://platform.claude.com/docs/en/managed-agents/self-hosted), [console](https://platform.claude.com/docs/en/managed-agents/self-hosted/console), [Kubernetes deployment](https://platform.claude.com/docs/en/managed-agents/self-hosted/kubernetes)).
- **The customer still owns the deployment.** Self-hosting means supplying and operating compute, database, images, dependencies, credentials, network boundaries, and upgrades; Anthropic also documents custom worker images and launchers ([Kubernetes deployment](https://platform.claude.com/docs/en/managed-agents/self-hosted/kubernetes), [custom workers](https://platform.claude.com/docs/en/managed-agents/self-hosted/call-the-api)). Its supplied Kubernetes stack uses per-session sandboxes with persistent workspace storage.
- **Coder addresses the broader development-workspace need.** Coder provisions template-defined environments with project tools and access controls, and developers can open a Coder Agents workspace in an IDE to inspect and finish its work ([Coder Workspaces](../products/coder-workspaces/message-house.md), [Coder Agents docs](https://coder.com/docs/ai-coder/agents)). Choosing Managed Agents for an automation workload does not require replacing the Coder workspaces used separately by developers.
- **Potential workspace integration.** A complementary integration is technically plausible: Coder could provision and manage workspaces running Managed Agents' custom workers ([Anthropic custom workers](https://platform.claude.com/docs/en/managed-agents/self-hosted/call-the-api#run-your-own-workers), [custom launchers](https://platform.claude.com/docs/en/managed-agents/self-hosted-sandboxes-workers#run-one-sandbox-per-session), [Coder workspace API](https://coder.com/docs/reference/api/workspaces#create-user-workspace)). As of November 12, 2026, the reviewed public documentation does not describe a native integration; this would require implementation and end-to-end validation.

## Coder's Strengths Here

- **Supported models across providers.** Coder Agents supports providers including Anthropic, OpenAI, Google, Azure OpenAI, Amazon Bedrock, OpenRouter, and Vercel AI Gateway, plus compatible self-hosted endpoints ([Coder models](https://coder.com/docs/ai-coder/agents/models#providers)). Organizations can configure multiple models without choosing a different coding agent product for each model family.
- **An integrated development workflow.** Coder combines chat, plan mode, an automation API, workspace provisioning, and IDE handoff in its existing platform ([Coder Agents docs](https://coder.com/docs/ai-coder/agents)). Managed Agents also supplies a console and CLI for interactive sessions; the distinction is Coder's integrated development workflow, not the existence of a user interface ([Anthropic console](https://platform.claude.com/docs/en/managed-agents/self-hosted/console), [quickstart](https://platform.claude.com/docs/en/managed-agents/self-hosted/quickstart)).
- **Reuse for existing Coder customers.** Coder Agents uses the same deployment, templates, and Coder access controls, without a separate coding agent installation or LLM provider keys in the workspace ([Coder Agents docs](https://coder.com/docs/ai-coder/agents), [architecture](https://coder.com/docs/ai-coder/agents/architecture#no-api-keys-in-workspaces)). Workspace tools can still require Git, registry, or other service credentials supplied through the template ([external credentials](https://coder.com/docs/ai-coder/agents/platform-controls/template-optimization#external-service-credentials)).
- **Coder identity and organization controls.** Agent actions on Coder resources use the initiating user's Coder permissions; Premium supports multiple organizations with organization-scoped models and MCP servers ([permission boundaries](https://coder.com/docs/ai-coder/agents/architecture#permission-boundaries), [organizations](https://coder.com/docs/ai-coder/agents/platform-controls/organizations)). Git authentication and commit attribution still depend on workspace credentials and Git configuration, rather than an unconditional guarantee about every external action ([template Git identity](https://coder.com/docs/ai-coder/agents/platform-controls/template-optimization#git-identity)).
- **Controls across supported agent paths.** Template-defined network policy governs workspace traffic, while licensed AI Gateway controls apply to supported model traffic routed through it ([network boundaries](https://coder.com/docs/ai-coder/agents/platform-controls/template-optimization#configure-network-boundaries), [Gateway clients](https://coder.com/docs/ai-coder/ai-gateway/clients)). Agent Relay does not bring provider-hosted orchestration or inference into AI Gateway's audit scope ([Relay for Claude Code](https://coder.com/docs/ai-coder/agent-relay/claude-code), [Relay for Cursor](https://coder.com/docs/ai-coder/agent-relay/cursor)).
- **Documented air-gapped deployment.** Coder documents air-gapped deployment options ([air-gap guide](https://coder.com/docs/install/prepare/airgap)). Agent Time reporting requires outbound HTTPS unless the customer arranges an alternative with Coder ([usage reporting](https://coder.com/docs/ai-coder/agents/licensing-usage#agent-time-usage-reporting)).
- **General availability.** Coder Agents became generally available in September 2026; self-hosted Managed Agents is in private beta ([Coder GA announcement](https://coder.com/blog/coder-agents-ga), [Anthropic announcement](https://claude.com/resources/articles/self-hosted-claude-managed-agents)).

## Claude Managed Agents Overview

- **What it is.** A configurable agent harness and execution platform built around agents, environments, sessions, and events, with APIs for application integration ([Managed Agents overview](https://platform.claude.com/docs/en/managed-agents/overview)). The self-hosted console can create agents, start sessions, exchange messages, and approve tools without writing an SDK application ([console docs](https://platform.claude.com/docs/en/managed-agents/self-hosted/console)).
- **Hosting options.** Anthropic can operate both service and sandboxes; customers can operate sandboxes while Anthropic retains the service; or customers can operate both and choose the serving provider or gateway for Claude inference ([hosting options](https://platform.claude.com/docs/en/managed-agents/self-hosted)). The hosted beta launched April 8, 2026 and self-hosted sandboxes followed May 19; the full self-hosted service is the separate November announcement ([release notes](https://platform.claude.com/docs/en/release-notes/overview), [announcement index](https://claude.com/resources/articles)).
- **Self-hosted components.** The customer runs `cma-server` for the API and agent loop, PostgreSQL for stored state, and workers for shell and file execution ([self-hosted overview](https://platform.claude.com/docs/en/managed-agents/self-hosted)). Anthropic recommends its two Helm charts for production; the supplied Compose stack is for development ([quickstart](https://platform.claude.com/docs/en/managed-agents/self-hosted/quickstart)).
- **Security and identity.** Self-hosted deployments support configured OIDC roles, external secret managers, short-lived agent tokens, and an optional egress gateway; these are not all enabled by default ([SSO](https://platform.claude.com/docs/en/managed-agents/self-hosted/configure), [agent identity and credentials](https://platform.claude.com/docs/en/managed-agents/self-hosted/agent-identity)). Customer-hosted sandbox isolation and network restrictions remain the customer's responsibility ([security model](https://platform.claude.com/docs/en/managed-agents/self-hosted-sandboxes-security)).
- **Data control.** Anthropic says it has no remote access to a self-hosted server or its logs, and the server contacts Anthropic for inference only when configured to use the Claude API ([data and access](https://platform.claude.com/docs/en/managed-agents/self-hosted-data-and-access)). Both Managed Agents and Coder Agents send conversation context and relevant tool results to their configured inference endpoints: self-hosting the agent loop does not itself keep inference or all data inside the customer's infrastructure ([Anthropic overview](https://platform.claude.com/docs/en/managed-agents/self-hosted), [Coder architecture](https://coder.com/docs/ai-coder/agents/architecture)).

## Coder Overview for This Comparison

- **Coder Workspaces.** The template-defined development environments used by developers and agents, with platform-managed provisioning, access, and lifecycle controls ([Workspaces message house](../products/coder-workspaces/message-house.md)). This is a broader environment-management decision than choosing a harness for one automation workload.
- **Coder Agents.** Coder's native coding agent runs its loop in the customer-operated control plane and uses workspaces for shell and file work; chat state persists in the Coder database ([architecture](https://coder.com/docs/ai-coder/agents/architecture)).
- **Platform controls.** Administrators configure providers, models, system prompts, and MCP servers; licensed AI Gateway budgets control spend, while concurrent-agent pools are licensing limits rather than administrator-configurable deployment settings ([platform controls](https://coder.com/docs/ai-coder/agents/platform-controls)). Models and MCP servers are organization-scoped, but provider endpoints and credentials are deployment-wide ([organization scope](https://coder.com/docs/ai-coder/agents/platform-controls/organizations)).
- **AI Gateway.** Part of AI Governance in Premium, it records the last user prompt, token usage, and tool-call requests for supported traffic routed through it, not full tool responses or all generated text ([Gateway overview](https://coder.com/docs/ai-coder/ai-gateway), [audit scope](https://coder.com/docs/ai-coder/ai-gateway/audit#what-we-store)). Coder Agents routes model requests through it automatically; third-party clients require supported configuration ([Coder models](https://coder.com/docs/ai-coder/agents/models#providers), [Gateway clients](https://coder.com/docs/ai-coder/ai-gateway/clients)).
- **Agent Relay.** A Premium beta connecting Claude Code and Cursor cloud sessions to ephemeral Coder workspaces, while the provider retains its cloud orchestration and inference ([Agent Relay](https://coder.com/docs/ai-coder/agent-relay)). It is not a Managed Agents integration.

## Where Claude Managed Agents Is Strong or Coder Has a Gap

- **A first-party Claude harness.** Anthropic supplies the harness alongside its models, including tools and session infrastructure for teams that prefer that combination ([Managed Agents launch](https://claude.com/blog/claude-managed-agents)).
- **Hosted convenience and self-hosting under a related API.** Teams can use Anthropic-operated infrastructure or reuse supported API integrations on a self-hosted service ([hosting options](https://platform.claude.com/docs/en/managed-agents/self-hosted)). Migration requires recreating resources and adapting to documented feature differences; session history does not move automatically ([differences](https://platform.claude.com/docs/en/managed-agents/self-hosted/differences)).
- **Configurable agents for broader applications.** Managed Agents targets agents embedded in products and internal tools, including non-coding workloads, and supplies a console for interactive use ([launch post](https://claude.com/blog/claude-managed-agents), [console docs](https://platform.claude.com/docs/en/managed-agents/self-hosted/console)). Coder Agents focuses on software development, although its API can also support custom automation ([Coder Agents FAQ](../products/coder-agents/faq.md#11-use-cases-and-future-direction)).
- **Reference sandbox isolation.** Anthropic's GKE deployment uses per-session gVisor sandboxes with NetworkPolicy and persistent workspace storage; its other-cluster guidance allows other sandboxed runtimes ([Kubernetes guide](https://platform.claude.com/docs/en/managed-agents/self-hosted/kubernetes)). Coder workspace isolation depends on templates, and its separate agent-sandbox pattern is early-stage ([Coder isolation guide](https://coder.com/docs/ai-coder/agents/platform-controls/agent-isolation)).
- **Credential injection for tools.** The optional egress gateway substitutes stored credentials for placeholders in supported outbound headers, reducing direct secret exposure to agent execution ([agent identity and credentials](https://platform.claude.com/docs/en/managed-agents/self-hosted/agent-identity)). This is not blanket secret protection: substitution is outbound-only, and returned tokens can still reach the sandbox ([vault limitations](https://platform.claude.com/docs/en/managed-agents/vaults)).

## Known Limitations in Claude Managed Agents' Approach

- **Documented model support is Claude-specific (as of 2026-11-12).** Provider and gateway configuration routes Claude requests, with no documented support for other model families ([inference provider docs](https://platform.claude.com/docs/en/managed-agents/self-hosted/inference-provider)).
- **Self-hosted access is private beta (as of 2026-11-12).** Downloads and pricing go through the Anthropic account team ([self-hosted docs](https://platform.claude.com/docs/en/managed-agents/self-hosted), [pricing](https://platform.claude.com/docs/en/about-claude/pricing)).
- **Feature differences from the hosted service (as of 2026-11-12).** Self-hosting lacks cloud environments, the Files API, webhooks, scheduled deployments, and managed OAuth refresh for MCP; prebuilt document-skill declarations are unavailable, although their sources can be uploaded as custom skills ([differences](https://platform.claude.com/docs/en/managed-agents/self-hosted/differences)). Multiagent sessions are limited to a coordinator with 1 to 20 listed agents.
- **Customer-operated infrastructure (as of 2026-11-12).** The recommended Kubernetes path requires Kubernetes 1.30+, the Agent Sandbox controller, an enforced NetworkPolicy implementation, PostgreSQL 16+, a suitable sandboxed runtime, and customer-built images from supplied Dockerfiles ([Kubernetes guide](https://platform.claude.com/docs/en/managed-agents/self-hosted/kubernetes)).
- **Workers are not themselves an isolation boundary (as of 2026-11-12).** Shell commands inherit the worker's permissions and network access; the supplied stacks place sessions in separate containers or sandboxed pods, whose underlying security the customer operates ([self-hosted docs](https://platform.claude.com/docs/en/managed-agents/self-hosted)). Coder likewise requires appropriate workspace isolation and network configuration ([Coder template guidance](https://coder.com/docs/ai-coder/agents/platform-controls/template-optimization#configure-network-boundaries)).
- **One tenant and trust level per deployment (as of 2026-11-12).** Every authorized caller can use every environment, so environments do not separate different trust levels ([data and access](https://platform.claude.com/docs/en/managed-agents/self-hosted-data-and-access)). SSO still provides caller-scoped access to resources such as agents and sessions ([SSO roles](https://platform.claude.com/docs/en/managed-agents/self-hosted/configure)).
- **Hosting mode matters for retention (as of 2026-11-12).** With only sandboxes self-hosted, conversation history and tool results still reach the Anthropic-operated service, which is not eligible for zero data retention ([environment comparison](https://platform.claude.com/docs/en/managed-agents/choosing-an-environment), [overview](https://platform.claude.com/docs/en/managed-agents/overview)). The fully self-hosted service stores transcripts locally, while model requests follow the selected provider's applicable agreement; self-hosting does not automatically enable zero data retention ([data and access](https://platform.claude.com/docs/en/managed-agents/self-hosted-data-and-access)).
- **No documented disconnected model-serving path (as of 2026-11-12).** The reviewed deployment docs describe Claude inference at Anthropic, a cloud provider, or a gateway, not locally hosted model inference ([inference providers](https://platform.claude.com/docs/en/managed-agents/self-hosted/inference-provider)).

## Common Questions

- **Does self-hosted Managed Agents still need somewhere for agents to work?** Yes, but Anthropic supplies worker software and sandbox deployment tooling; the customer supplies and operates the underlying infrastructure ([self-hosted docs](https://platform.claude.com/docs/en/managed-agents/self-hosted), [Kubernetes guide](https://platform.claude.com/docs/en/managed-agents/self-hosted/kubernetes)). Coder could provide those execution environments through the [potential custom-worker integration](#who-supplies-and-operates-the-execution-environments) described above.
- **Why choose Coder Agents rather than self-hosted Managed Agents?** Evaluate Coder for its integrated coding workflow, supported model-family choice, developer workspace handoff, and reuse of an existing Coder platform ([Coder Agents docs](https://coder.com/docs/ai-coder/agents)). Evaluate Managed Agents when Anthropic's configurable harness, Claude models, and supported console/API workflows fit the workload, including internal coding automation; both require customer operations when self-hosted ([Anthropic docs](https://platform.claude.com/docs/en/managed-agents/self-hosted)).
- **Is this a choice between complete lock-in and complete freedom?** No: Managed Agents couples its documented harness support to Claude, but has multiple serving providers and supports reusable skills and MCP integrations ([inference providers](https://platform.claude.com/docs/en/managed-agents/self-hosted/inference-provider), [skills](https://platform.claude.com/docs/en/managed-agents/skills), [MCP](https://platform.claude.com/docs/en/managed-agents/mcp-connector)). Coder separates the native agent from supported model-provider choices, and Workspaces can host other coding agents; integrations, model compatibility, and migration work still need evaluation ([Coder models](https://coder.com/docs/ai-coder/agents/models), [Workspaces message house](../products/coder-workspaces/message-house.md)).
- **How is Agent Relay different?** Agent Relay connects the existing Claude Code or Cursor cloud experience to Coder-managed execution; it does not connect Managed Agents ([supported providers](https://coder.com/docs/ai-coder/agent-relay#supported-providers)). Coder Agents instead runs Coder's agent loop in the customer deployment with supported model-provider choice ([Coder architecture](https://coder.com/docs/ai-coder/agents/architecture), [Coder models](https://coder.com/docs/ai-coder/agents/models)).
- **Can Claude models power Coder Agents?** Yes, through the supported Anthropic and Amazon Bedrock configurations, including Claude Platform for AWS through the Anthropic provider ([Coder provider configuration](https://coder.com/docs/ai-coder/ai-gateway/providers)). Using Claude models does not require adopting Managed Agents.
- **Can Managed Agents use Coder AI Gateway?** The reviewed docs describe a Claude-compatible gateway configuration and an Anthropic-compatible Coder endpoint, but do not document this combination as supported ([Anthropic inference providers](https://platform.claude.com/docs/en/managed-agents/self-hosted/inference-provider), [Coder client endpoints](https://coder.com/docs/ai-coder/ai-gateway/clients#base-urls)). Treat it as a configuration to validate, not an established integration.
- **What is each product's release status?** Coder Agents is generally available; Anthropic-hosted Managed Agents is in beta and the fully self-hosted service is in private beta ([Coder GA announcement](https://coder.com/blog/coder-agents-ga), [Managed Agents overview](https://platform.claude.com/docs/en/managed-agents/overview), [self-hosted announcement](https://claude.com/resources/articles/self-hosted-claude-managed-agents)).
- **Could Managed Agents execute in Coder Workspaces?** A custom-worker integration is technically plausible: Anthropic supports customer-defined worker launchers, and Coder exposes APIs for provisioning workspaces ([Anthropic worker deployment](https://platform.claude.com/docs/en/managed-agents/self-hosted-sandboxes-workers#run-one-sandbox-per-session), [Coder workspace API](https://coder.com/docs/reference/api/workspaces#create-user-workspace)). A native integration is not described in the reviewed public documentation as of November 12, 2026; this is a potential complementary use, not an existing Agent Relay capability.

## When Claude Managed Agents Alone Is Enough

- **The workload fits Anthropic's harness and Claude.** A team can choose Managed Agents for a coding or non-coding workflow without adopting Coder or committing every other workload to the same models ([Managed Agents use cases](https://claude.com/blog/claude-managed-agents), [self-hosted use cases](https://claude.com/resources/articles/self-hosted-claude-managed-agents)).
- **The supplied sandbox approach meets the environment need.** A team comfortable operating Anthropic's self-hosted stack or a supported custom worker deployment does not need Coder merely to obtain an execution environment ([self-hosted docs](https://platform.claude.com/docs/en/managed-agents/self-hosted), [custom workers](https://platform.claude.com/docs/en/managed-agents/self-hosted/call-the-api)).
- **Hosted operation meets the requirements.** With cloud sandboxes, Anthropic operates both the service and execution infrastructure, avoiding that self-hosting burden ([hosting options](https://platform.claude.com/docs/en/managed-agents/self-hosted)).

## Pricing and Packaging

- **Hosted Managed Agents.** Standard Claude token rates plus $0.08 per session-hour while running; other applicable features and pricing modifiers are documented separately ([Claude pricing](https://platform.claude.com/docs/en/about-claude/pricing)).
- **Self-hosted Managed Agents.** Anthropic's public pricing page lists no self-hosted rate and directs customers to their account team ([Claude pricing](https://platform.claude.com/docs/en/about-claude/pricing)).
- **Coder.** Coder Agents is available in every tier; Community and Premium allow five concurrent agents deployment-wide, while AI Premium removes that cap and provides a pool of Agent Hours ([Coder pricing](https://coder.com/pricing), [licensing](https://coder.com/docs/ai-coder/agents/licensing-usage)). Customers pay their model providers separately; see [Packaging](../company/packaging.md) for the tier narrative.
