*(Runlayer is operated by Anysource Inc. ([llms.txt](https://www.runlayer.com/llms.txt)). This page is complementary at the execution layer, since Runlayer doesn't provide development environments. It overlaps with Coder in three areas covered under Strategic Themes, which are MCP governance, AI session audit, and hosted agents.)*

## One-Line Positioning

Runlayer governs which tools, MCP servers, and AI clients employees and their agents can use across the company, while Coder provides the self-hosted environments where developers and coding agents run and controls what those environments can reach.

## Strategic Themes and Patterns

- **Relationship.** Mostly complementary. Runlayer describes itself as a governed layer between the AI clients employees already use and company systems ([llms.txt](https://www.runlayer.com/llms.txt)), and its docs treat agent runtimes such as AWS Bedrock AgentCore, Claude Managed Agents, and Vercel Eve as platforms that route MCP calls through Runlayer ([Agent Platforms](https://docs.runlayer.com/agent-platforms)). Coder is self-hosted infrastructure for development environments and AI coding workflows ([Coder Agents](https://coder.com/docs/@main/coder-agents)), which Runlayer doesn't offer.
- **Overlap in MCP governance.** Runlayer's core product is an MCP gateway with a catalog, approvals, and policy scoped by user, group, role, agent account, client, tool, and resource ([MCP Gateway](https://www.runlayer.com/mcp-gateway)). Coder Agents lets organization admins register MCP servers with per-user OAuth2 and availability policies ([MCP servers](https://coder.com/docs/@main/coder-agents/platform-controls/mcp-servers)), and AI Gateway's in-gateway MCP tool injection is [deprecated](https://coder.com/docs/@main/ai-governance/ai-gateway/mcp). For MCP governance across many AI clients, Runlayer covers more today.
- **Overlap in AI session audit and spend.** Both record AI activity for audit and cost. Runlayer collects sessions through hooks in IDE and CLI clients and through server-side imports ([Sessions](https://docs.runlayer.com/platform-sessions)). Coder's AI Gateway records prompts, tool calls, token usage, and reasoning for clients routed through it, and enforces per-user spend budgets ([audit](https://coder.com/docs/@main/ai-governance/ai-gateway/audit), [cost controls](https://coder.com/docs/@main/ai-governance/ai-gateway/cost-controls)).
- **Overlap in hosted agents.** Runlayer Agents run in a sandbox with shell access and can clone repositories, run tests, push branches, and open pull requests as a customer-owned GitHub App ([GitHub access for agents](https://docs.runlayer.com/platform-agents-github)). Runlayer frames agents as an automation layer with short-lived runs, and its examples center on support, incident, RevOps, and reporting workflows ([Agents](https://docs.runlayer.com/platform-agents)). Coder Agents provisions a workspace from the customer's templates and delivers branches and pull requests under the developer's identity ([Coder Agents](https://coder.com/docs/@main/coder-agents)).
- **Choice, Control, Consistency.** Not a direct tradeoff, since Runlayer doesn't replace development environments. On Consistency, Runlayer's agent sandbox ships a fixed toolset ([Agents](https://docs.runlayer.com/platform-agents)), while Coder workspaces come from the customer's own templates.
- **How they work together.** Runlayer exposes approved tools through a remote MCP endpoint ([MCP Gateway](https://www.runlayer.com/mcp-gateway)), and Coder Agents can register a remote MCP server over streamable HTTP with OAuth2, including dynamic client registration ([MCP servers](https://coder.com/docs/@main/coder-agents/platform-controls/mcp-servers)). An admin can register the Runlayer endpoint once so Coder Agents chats reach approved tools through Runlayer's policy and scanning. Inside workspaces, Runlayer's per-user CLI hook installer supports Linux ([Enforce](https://docs.runlayer.com/shadow-ai/enforce)), so a template can install it for clients such as Claude Code, while the template also sets what the workspace can reach on the network ([template optimization](https://coder.com/docs/@main/coder-agents/platform-controls/template-optimization)). Neither vendor documents this pairing as of 2026-11-14.

## Coder's Strengths Here

- **Governs where agents run.** Coder templates define each workspace and what it can reach on the network ([template optimization](https://coder.com/docs/@main/coder-agents/platform-controls/template-optimization)), and Agent Firewall restricts and audits the domains and HTTP verbs a terminal-based agent can use ([Agent Firewall](https://coder.com/docs/@main/ai-governance/agent-firewall)). Runlayer governs tool calls that pass through its gateway or hooks, and its docs note that a session integration doesn't make unwrapped vendor tools pass through the gateway ([Agent Platforms](https://docs.runlayer.com/agent-platforms)).
- **Full development environments for agents.** Coder Agents runs tool calls in a Coder workspace over the same connection used for terminals and IDEs ([Coder Agents](https://coder.com/docs/@main/coder-agents)), so the agent works with the languages, services, and dependencies the template provides, and a developer can open the same workspace in an editor. Runlayer's agent sandbox is built for short-lived runs (see Known Limitations).
- **Coverage for Linux workspaces.** Coder Agents and AI Gateway work in Linux workspaces without a device agent. Runlayer's managed AI Watch package is Detect-only on Linux, without hooks, endpoint modes, or Sessions ([Linux](https://docs.runlayer.com/shadow-ai/deploy/linux)), so Linux enforcement depends on its per-user CLI path.
- **Self-hosted on any infrastructure, including air-gapped.** Coder supports [air-gapped deployments](https://coder.com/docs/@main/install/prepare/airgap) and runs Coder Agents with no SaaS or managed component ([Coder Agents](https://coder.com/docs/@main/coder-agents)). Self-hosted Runlayer runs in an AWS account or an EKS or GKE cluster ([Deployment Overview](https://docs.runlayer.com/deployment/overview)) and lists outbound hosts, including WorkOS for SSO and Runlayer's catalog and licensing hosts, as always required ([egress requirements](https://docs.runlayer.com/deployment/egress-requirements)).
- **Identity tied to the development platform.** AI Gateway authenticates users with their Coder identity and attributes requests to a user and session ([AI Gateway](https://coder.com/docs/@main/ai-governance/ai-gateway)), so model activity lines up with the workspace where the work happens.

## Runlayer Overview

- **What it is.** An enterprise AI platform that combines enablement and an AI control plane, covering an MCP gateway, agent identity and governance, runtime security, shadow AI discovery, and observability ([llms.txt](https://www.runlayer.com/llms.txt)).
- **Products.** [MCP Gateway](https://www.runlayer.com/mcp-gateway), [Runlayer Catalog](https://www.runlayer.com/catalog) for skills and plugins, [Runtime Security](https://www.runlayer.com/guard) with the [ToolGuard](https://docs.runlayer.com/runlayer-toolguard) and [AgentGuard](https://docs.runlayer.com/agentguard) scanners, [Agent IAM and Governance](https://www.runlayer.com/identity-policy), [Shadow AI](https://www.runlayer.com/watch) discovery through MDM, [ROI and Observability](https://www.runlayer.com/visibility), and [Runlayer Agents](https://www.runlayer.com/agents).
- **Architecture.** MCP requests route through the gateway, which checks OAuth state, identity-aware policy, and security scans and writes an audit record on every call ([MCP Gateway](https://www.runlayer.com/mcp-gateway)). Client hooks send IDE and CLI activity, including shell commands and file operations, to Runlayer Sessions ([Sessions](https://docs.runlayer.com/platform-sessions)).
- **Coverage.** Runlayer lists 212 active MCP servers and 27 publicly supported AI clients ([Integrations](https://www.runlayer.com/integrations)), with hook clients including Cursor, VS Code, Claude Code, GitHub Copilot CLI, Gemini CLI, Codex, and Windsurf ([Sessions](https://docs.runlayer.com/platform-sessions)).
- **Target customer.** Companies rolling out AI agents across engineering, security, IT, operations, and business teams ([About](https://www.runlayer.com/about)).
- **Deployment model.** A Runlayer-hosted single-tenant deployment in an AWS account Runlayer operates, or self-hosted in the customer's AWS account or Kubernetes cluster ([Deployment Overview](https://docs.runlayer.com/deployment/overview), [shared responsibility](https://docs.runlayer.com/operations/shared-responsibility)).
- **Compliance.** Runlayer states it is SOC 2 certified, HIPAA compliant, and GDPR compliant ([llms.txt](https://www.runlayer.com/llms.txt)) (company claim).
- **Company.** Runlayer launched in November 2025 with an $11M seed ([TechCrunch](https://techcrunch.com/2025/11/17/mcp-ai-agent-security-startup-runlayer-launches-with-8-unicorns-11m-from-khoslas-keith-rabois-and-felicis/)) and announced a $30M Series A from Felicis and Khosla Ventures in June 2026, bringing total funding to $42M ([Runlayer blog](https://www.runlayer.com/blog/series-A-30m-fundraise-felicis-khosla)).

## Coder Overview for This Comparison

- **Coder Agents.** A chat interface and API that delegates development work to a self-hosted coding agent running in the Coder control plane, which provisions a workspace from a template and executes tool calls there ([Coder Agents](https://coder.com/docs/@main/coder-agents), [architecture](https://coder.com/docs/@main/coder-agents/architecture)).
- **MCP servers in Coder Agents.** Organization-scoped MCP servers with None, OAuth2, API key, custom header, or OIDC authentication, availability policies, and optional Coder identity headers on outgoing requests ([MCP servers](https://coder.com/docs/@main/coder-agents/platform-controls/mcp-servers)). Developers can also add their own servers with a workspace `.mcp.json` file ([bring your own MCP servers](https://coder.com/docs/@main/coder-agents/bring-your-own-mcp-servers)).
- **AI Gateway.** An LLM gateway between coding tools and model providers that holds provider keys centrally, records prompts, tool calls, and token usage, and enforces spend budgets ([AI Gateway](https://coder.com/docs/@main/ai-governance/ai-gateway)). It covers supported clients only, and Cursor isn't one of them today ([compatibility](https://coder.com/docs/@main/ai-governance/ai-gateway/clients#compatibility)).
- **Agent Firewall.** A process-level firewall that blocks domains and HTTP verbs for terminal-based agents and streams audit logs to the Coder control plane ([Agent Firewall](https://coder.com/docs/@main/ai-governance/agent-firewall)).
- **Scope.** AI Governance doesn't inspect, redact, or block prompt content the way a DLP or guardrails product does ([AI Governance playbook](../products/coder-ai-governance/playbook.md)).

## Known Limitations in Runlayer's Approach

- **Agent runs are short-lived (as of 2026-11-14).** Runlayer documents an 8-hour run limit that is configurable per deployment and no support for interactive programs that need a TTY, and says long-running services and background daemons aren't a good fit ([Agents](https://docs.runlayer.com/platform-agents)).
- **Fixed sandbox toolset (as of 2026-11-14).** Bun is the only JavaScript runtime in the agent sandbox, and Node.js, npm, and pnpm aren't installed ([Agents](https://docs.runlayer.com/platform-agents)).
- **Agent network policy depends on the runtime (as of 2026-11-14).** Per-agent network access policies are enforced by an egress proxy that ships with the AgentCore sandbox runtime, and the Kubernetes agent sandbox doesn't offer the setting ([Agents](https://docs.runlayer.com/platform-agents)).
- **Linux endpoints are Detect-only through MDM (as of 2026-11-14).** The managed Linux package scans for shadow AI but has no hooks, endpoint modes, or Sessions ([Linux](https://docs.runlayer.com/shadow-ai/deploy/linux)). The per-user CLI hook installer does support Linux ([Enforce](https://docs.runlayer.com/shadow-ai/enforce)).
- **Air-gapped support is unclear (as of 2026-11-14).** The self-hosted egress page lists WorkOS and Runlayer-operated hosts as always required ([egress requirements](https://docs.runlayer.com/deployment/egress-requirements)), while the AI Watch FAQ refers to self-hosted air-gapped instances ([AI Watch FAQ](https://docs.runlayer.com/shadow-ai/faq)). Confirm with Runlayer before planning a disconnected deployment.

## Common Questions

- **Does Runlayer replace Coder?** No. Runlayer doesn't provide development environments, and its agent runtime targets short-lived automation runs ([Agents](https://docs.runlayer.com/platform-agents)). Coder provides the self-hosted workspaces where developers and coding agents run ([Coder Agents](https://coder.com/docs/@main/coder-agents)).
- **Can Coder Agents use tools governed by Runlayer?** Yes, as a remote MCP server. Coder Agents supports remote MCP servers over streamable HTTP with OAuth2 ([MCP servers](https://coder.com/docs/@main/coder-agents/platform-controls/mcp-servers)), and Runlayer exposes approved tools through its gateway ([MCP Gateway](https://www.runlayer.com/mcp-gateway)). Neither vendor publishes a joint guide as of 2026-11-14.
- **If we use Runlayer, do we still need AI Gateway?** They cover different traffic. Runlayer governs MCP and tool calls and records client sessions ([Sessions](https://docs.runlayer.com/platform-sessions)). AI Gateway governs model requests from supported coding clients, holds provider keys, and enforces per-user spend budgets ([AI Gateway](https://coder.com/docs/@main/ai-governance/ai-gateway)).
- **Which product scans tool calls for prompt injection?** Runlayer. Its Runtime Security inspects tools, outputs, and agent behavior ([Runtime Security](https://www.runlayer.com/guard)). Coder's AI Governance doesn't inspect or block prompt content ([AI Governance playbook](../products/coder-ai-governance/playbook.md)).
- **Who controls what agents reach on the network?** In a Coder workspace, the template and Agent Firewall do, for processes in the workspace ([template optimization](https://coder.com/docs/@main/coder-agents/platform-controls/template-optimization), [Agent Firewall](https://coder.com/docs/@main/ai-governance/agent-firewall)). Runlayer applies network policy to its own agent sandbox where its egress proxy is deployed ([Agents](https://docs.runlayer.com/platform-agents)).
