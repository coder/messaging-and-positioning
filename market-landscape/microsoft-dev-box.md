*Microsoft Dev Box [stopped accepting new sign-ups on November 1, 2025](https://azure.microsoft.com/en-us/products/dev-box), entered a closing-down period on September 14, 2026, and [retires on September 18, 2028](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-retirement-guide). Microsoft names Windows 365 as the recommended path forward, so this page also covers the Windows 365 developer setup where it replaces Dev Box.*

## One-Line Positioning

Microsoft Dev Box provides Microsoft-managed Windows workstations in Azure and is retiring in favor of Windows 365 Cloud PCs, while Coder provisions Linux, Windows, and macOS development environments defined as code on infrastructure the customer runs, in any cloud, on-premises, or air-gapped.

## Strategic Themes and Patterns

- **Relationship.** Competitive. Dev Box runs developer workstations as [Azure VMs](https://learn.microsoft.com/en-us/azure/dev-box/overview-what-is-microsoft-dev-box) that [exist in a subscription owned by Microsoft](https://learn.microsoft.com/en-us/azure/dev-box/concept-dev-box-architecture), and Coder [provisions workspaces with Terraform](https://coder.com/docs/tutorials/template-from-scratch) on infrastructure the customer controls. Both answer the same question of where developers work.
- **A forced decision for existing customers.** Microsoft asks Dev Box customers to move their workflows [to Windows 365 or another appropriate solution](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-retirement-guide) by September 18, 2028, and states that Windows 365 isn't a one-to-one replacement. Every Dev Box customer has to re-platform its developer environments either way, which makes the migration itself the evaluation point.
- **Choice, Control, Consistency.** Dev Box and Windows 365 trade off Choice and Control. Dev Box runs [Windows 10 and Windows 11 Enterprise images](https://learn.microsoft.com/en-us/azure/dev-box/how-to-prepare-custom-image-dev-box), runs only in Azure, and requires [Microsoft Intune and Microsoft Entra ID](https://learn.microsoft.com/en-us/azure/dev-box/quickstart-configure-dev-box-service). Coder runs on any cloud or on-premises, supports Linux, Windows, and macOS workspaces ([Coder Workspaces FAQ](../products/coder-workspaces/faq.md)), and works with OIDC identity providers including Entra ID. Both address Consistency through centrally defined environments.
- **Lock-in risk.** The retirement shows the risk directly. Dev Box projects, pools, and dev box definitions don't carry over to Windows 365 as-is. Microsoft's [transition guide](https://learn.microsoft.com/en-us/windows-365/enterprise/devbox-transition-to-w365) maps pools and dev box definitions onto provisioning policies and Windows 365 licenses, replaces projects with Entra groups, Intune assignments, and scope tags, and moves catalog tasks into images, Intune apps, and scripts. Standardizing again on a single vendor's managed workstation service leaves the next change of direction in that vendor's hands. Coder templates are Terraform the customer owns and runs.
- **Build versus buy.** For teams leaving Dev Box that don't want a managed desktop, the realistic alternative to Coder is building an internal platform on Azure VMs, Kubernetes, and images, not another hosted vendor. See [Why Coder](../company/why-coder.md).
- **Where Windows 365 is sufficient on its own.** Windows-centric teams already standardized on Microsoft 365, Intune, and Entra ID, with no requirement to self-host or support Linux-native development, can get managed Cloud PCs with a [Windows 11 developer configuration image](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-retirement-guide) and no infrastructure to operate.

## Coder's Strengths Here

- **Any cloud, on-premises, or air-gapped.** Coder runs on Kubernetes or VMs on AWS, Azure, or GCP ([Coder Workspaces FAQ](../products/coder-workspaces/faq.md)), and [all Coder features are supported in air-gapped and offline deployments](https://coder.com/docs/install/prepare/airgap). Dev Box setup is documented only as an [Azure service that requires an Azure subscription](https://learn.microsoft.com/en-us/azure/dev-box/quickstart-configure-dev-box-service).
- **Teams that stay on Azure can.** Coder provides registry templates for [Windows](https://registry.coder.com/templates/coder/azure-windows) and [Linux](https://registry.coder.com/templates/coder/azure-linux) Azure VMs, so an organization can move off Dev Box without leaving Azure.
- **Linux, Windows, and macOS.** Coder templates provision VMs, Kubernetes pods, and Docker containers on Linux, Windows, or macOS, on x86-64 or ARM ([Coder Workspaces FAQ](../products/coder-workspaces/faq.md)). For Linux, Dev Box supports Windows Subsystem for Linux and [suggests GitHub Codespaces for GitHub users who develop in VS Code](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-faq).
- **Developer self-service stays.** Developers create workspaces from shared templates on demand ([Coder Docs](https://coder.com/docs/user-guides/workspace-management)). Windows 365 replaces Dev Box's developer portal and self-service creation with [admin-led provisioning](https://learn.microsoft.com/en-us/windows-365/enterprise/devbox-transition-to-w365).
- **Environments as code.** Coder runs a Terraform apply [every time a workspace is created, started, or stopped](https://coder.com/docs/tutorials/template-from-scratch), so a toolchain change is a template change that also manages the underlying infrastructure. Dev Box customizations are [YAML files that list tasks](https://learn.microsoft.com/en-us/azure/dev-box/concept-what-are-dev-box-customizations), such as WinGet, PowerShell, and Git clone, that configure Windows dev boxes when they're created.
- **The developer's own IDE.** Developers connect from VS Code, JetBrains IDEs, Cursor, Zed, or any SSH-capable editor ([Coder Workspaces FAQ](../products/coder-workspaces/faq.md)). Windows workspaces are also reachable over [RDP](https://coder.com/docs/user-guides/workspace-access/remote-desktops), including a [browser-based RDP client](https://registry.coder.com/modules/coder/windows-rdp). Dev Box connects through the [Windows App or a browser](https://learn.microsoft.com/en-us/azure/dev-box/how-to-create-dev-boxes-developer-portal), and VS Code access through Dev Box Tunnels is [in preview](https://learn.microsoft.com/en-us/azure/dev-box/how-to-set-up-dev-tunnels).
- **Faster starts through prebuilt workspaces.** Coder Premium can keep a pool of [prebuilt workspaces](https://coder.com/docs/admin/templates/extending-templates/prebuilt-workspaces) ready to claim. Microsoft's Dev Box FAQ explains why provisioning a dev box [takes 25 minutes or more](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-faq).
- **Entra ID without Intune.** Coder signs users in with [Microsoft Entra ID over OIDC](https://coder.com/docs/admin/users/oidc-auth/microsoft) and doesn't require device management. Dev Box requires every user to hold [Windows Enterprise, Intune, and Entra ID P1 licenses](https://learn.microsoft.com/en-us/azure/dev-box/quickstart-configure-dev-box-service).
- **A foundation for governed AI agents.** Coder Agents and AI Governance, including AI Gateway, layer onto the same Coder deployment and infrastructure that workspaces run on ([Coder Workspaces message house](../products/coder-workspaces/message-house.md)), and platform teams set what each workspace can reach in the template ([template network boundaries](https://coder.com/docs/ai-coder/agents/platform-controls/template-optimization#configure-network-boundaries)). Dev Box is in maintenance mode with [no new feature development planned](https://azure.microsoft.com/updates?id=567933).

## Microsoft Dev Box Overview

- **What it is.** A service for self-service, cloud-based Windows developer workstations, now [retiring on September 18, 2028](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-retirement-guide). Microsoft stopped accepting [new sign-ups on November 1, 2025](https://azure.microsoft.com/en-us/products/dev-box).
- **Architecture.** A dev center contains projects, which contain dev box pools that set the image, compute, storage, and network for each dev box ([Microsoft Learn](https://learn.microsoft.com/en-us/azure/dev-box/concept-dev-box-architecture)). Dev boxes are Azure VMs in a [Microsoft-owned subscription](https://learn.microsoft.com/en-us/azure/dev-box/concept-dev-box-architecture) that use either a Microsoft-hosted network or an Azure network connection to the customer's virtual network, and Dev Box is [built on Azure Virtual Desktop and Windows 365 infrastructure](https://learn.microsoft.com/en-us/azure/dev-box/concept-dev-box-network-requirements). Images come from [YAML image definitions, Azure Compute Gallery, or Azure Marketplace](https://learn.microsoft.com/en-us/azure/dev-box/overview-what-is-microsoft-dev-box).
- **Target customer.** Developer teams in organizations that use Microsoft Intune and Microsoft Entra ID, with per-user [Windows Enterprise, Intune, and Entra ID P1 licensing](https://learn.microsoft.com/en-us/azure/dev-box/quickstart-configure-dev-box-service), which Microsoft 365 E3 and E5 include.
- **Deployment model.** A managed Azure service. Dev boxes use a Microsoft-hosted network, or the customer's network through an Azure network connection ([Microsoft Learn](https://learn.microsoft.com/en-us/azure/dev-box/concept-dev-box-architecture)).
- **Successor.** Microsoft calls Windows 365 [the recommended path forward for virtualized developer environments](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-retirement-guide). Its Windows 11 developer configuration image, with pre-installed Microsoft 365 apps, became [generally available the week of September 21, 2026](https://learn.microsoft.com/en-us/windows-365/enterprise/whats-new).

## Coder Overview for This Comparison

- **Self-hosted workspaces.** The Coder server provisions workspaces from [Terraform templates](https://coder.com/docs/tutorials/template-from-scratch) on any infrastructure Terraform can manage, including Azure.
- **Windows workspaces.** Templates can provision Windows VMs, and developers reach them over [RDP](https://coder.com/docs/user-guides/workspace-access/remote-desktops) or an IDE. The registry's [Azure Windows template](https://registry.coder.com/templates/coder/azure-windows) uses a Windows Server 2022 image.
- **Cost controls.** Templates set a default autostop and, in Premium, control which [autostart and autostop schedules](https://coder.com/docs/admin/templates/managing-templates/schedule) users can set ([Coder pricing](https://coder.com/pricing)), and Coder templates typically [persist user data while deleting compute](https://coder.com/docs/admin/templates/extending-templates/resource-persistence) when a workspace stops.
- **Governance.** SSO through OIDC and built-in roles in every edition, and, in Premium, groups, custom roles, audit logging, SCIM, and multi-organization access control ([Coder Workspaces message house](../products/coder-workspaces/message-house.md), [Coder pricing](https://coder.com/pricing)).
- **AI on the same platform.** [Coder Agents](https://coder.com/docs/ai-coder/agents) runs in the Coder control plane and works in Coder workspaces, and [AI Governance](https://coder.com/docs/ai-coder/ai-governance), including [AI Gateway](https://coder.com/docs/ai-coder/ai-gateway), governs AI tools in the same deployment.

## Where Microsoft Dev Box Is Strong or Coder Has a Gap

- **No infrastructure to operate.** Microsoft runs the dev box VMs in [its own subscription](https://learn.microsoft.com/en-us/azure/dev-box/concept-dev-box-architecture). Coder is [self-hosted](../company/why-coder.md), so the customer operates the control plane and the compute.
- **Native Intune and Entra ID management.** Dev boxes [enroll in Microsoft Intune automatically](https://learn.microsoft.com/en-us/azure/dev-box/overview-what-is-microsoft-dev-box) and support conditional access, MFA, and [Entra join or, with an Azure network connection, Entra hybrid join](https://learn.microsoft.com/en-us/azure/dev-box/concept-dev-box-architecture). Coder has no native Intune integration for workspaces.
- **Licensing many customers already own.** Dev Box's per-user prerequisites are [included in Microsoft 365 E3, E5, and other plans](https://learn.microsoft.com/en-us/azure/dev-box/quickstart-configure-dev-box-service), so organizations that already hold those licenses mainly add Dev Box's [consumption-based compute and storage charges](http://web.archive.org/web/20260711055157/https://azure.microsoft.com/en-us/pricing/details/dev-box/) (inferred).
- **Full Windows desktop development.** Dev Box offers [Azure Marketplace images](https://learn.microsoft.com/en-us/azure/dev-box/overview-what-is-microsoft-dev-box) that include Visual Studio and supports [nested virtualization with Hyper-V](https://learn.microsoft.com/en-us/azure/dev-box/how-to-connect-dev-box-virtual-switch). Coder supports Windows workspaces, but its [Dev Containers integration](https://coder.com/docs/admin/integrations/devcontainers/integration) isn't supported on Windows or macOS workspaces ([Coder Workspaces FAQ](../products/coder-workspaces/faq.md)).
- **Terraform ownership with Coder.** Coder templates are [Terraform](https://coder.com/docs/tutorials/template-from-scratch). The built-in [template builder](https://coder.com/docs/admin/templates/creating-templates) creates templates without writing Terraform, but platform teams own and maintain the resulting templates. Dev Box and Windows 365 are configured through the Azure portal, Intune, and image definitions.
- **Agents that operate Windows applications.** Windows 365 for Agents, [generally available since the week of June 1, 2026](https://learn.microsoft.com/en-us/windows-365/agents/whats-new), provides managed Cloud PCs that computer-using agents [check out to complete tasks](https://learn.microsoft.com/en-us/windows-365/agents/introduction-windows-365-for-agents). Coder workspaces are built for coding agents. Coder Agents can drive a graphical desktop inside a workspace through an [experimental virtual desktop feature](https://coder.com/docs/ai-coder/agents/platform-controls/virtual-desktop), but Coder doesn't offer managed Windows Cloud PCs for agents.

## Known Limitations in Microsoft Dev Box's Approach

- **Retiring (as of 2026-10-29).** Dev Box retires on September 18, 2028, and Microsoft says to [expect deletion of remaining customer workloads](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-retirement-guide) after that date. During the transition, Microsoft tells customers to check the current product and subscription experience to see whether new resource creation remains available.
- **Closed to new customers (as of 2026-10-29).** Dev Box hasn't accepted [new sign-ups](https://azure.microsoft.com/en-us/products/dev-box) since November 1, 2025.
- **Maintenance mode (as of 2026-10-29).** No new feature development is planned ([Azure Updates](https://azure.microsoft.com/updates?id=567933)). Previously planned features, including developer offboarding and single sign-on for existing dev boxes, [won't reach general availability](http://web.archive.org/web/20260611084242/https://learn.microsoft.com/en-us/azure/dev-box/dev-box-roadmap).
- **Windows only (as of 2026-10-29).** Dev Box supports [client editions of Windows 10 and Windows 11](https://learn.microsoft.com/en-us/azure/dev-box/concept-dev-box-architecture), and custom images must be [generalized generation 2 Windows Enterprise images](https://learn.microsoft.com/en-us/azure/dev-box/how-to-prepare-custom-image-dev-box). Linux tooling runs through [WSL](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-faq).
- **Azure only (as of 2026-10-29).** Microsoft documents Dev Box only as an [Azure service](https://learn.microsoft.com/en-us/azure/dev-box/quickstart-configure-dev-box-service). We found no documented on-premises, other-cloud, or air-gapped option.
- **Provisioning time (as of 2026-10-29).** Microsoft's FAQ addresses why a dev box [takes 25 minutes or more to provision](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-faq), attributing the time to networking, Entra ID join and security checks, Intune registration, and any installation and configuration tasks in the dev box definition.
- **Hibernation and GPU limits (as of 2026-10-29).** Hibernation works only on [8 and 16 vCPU sizes](https://learn.microsoft.com/en-us/azure/dev-box/how-to-configure-dev-box-hibernation). GPU access is a [serverless GPU preview in seven regions](https://learn.microsoft.com/en-us/azure/dev-box/how-to-configure-dev-box-serverless-gpu).
- **The Windows 365 path changes the model (as of 2026-10-29).** Windows 365 uses [admin-led provisioning instead of developer self-service, and license-based provisioning instead of Azure consumption billing](https://learn.microsoft.com/en-us/windows-365/enterprise/devbox-transition-to-w365). Microsoft states it [isn't a one-to-one replacement](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-retirement-guide) for Dev Box.

## Common Questions

- **Microsoft is retiring Dev Box. Do we have to move to Windows 365?** No. Microsoft recommends Windows 365, and its retirement guide tells customers to move to [Windows 365 or another appropriate solution](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-retirement-guide) by September 18, 2028. Coder is an option for teams that want developer environments defined as code on infrastructure they control.
- **Can we stay on Azure with Coder?** Yes. Coder runs on Kubernetes or VMs on Azure ([Coder Workspaces FAQ](../products/coder-workspaces/faq.md)), and registry templates provision [Windows](https://registry.coder.com/templates/coder/azure-windows) and [Linux](https://registry.coder.com/templates/coder/azure-linux) Azure VMs as workspaces.
- **Can our developers keep Windows workstations?** Yes. Templates can provision Windows workspaces, and developers open them over [RDP from a desktop client or the browser](https://coder.com/docs/user-guides/workspace-access/remote-desktops). The registry's [Azure Windows template](https://registry.coder.com/templates/coder/azure-windows) uses Windows Server 2022, so teams that need Windows 10 or 11 client editions set a different image in their template, subject to Microsoft licensing (inferred).
- **Can we keep Microsoft Entra ID?** Yes. Coder authenticates users with [Entra ID through OIDC](https://coder.com/docs/admin/users/oidc-auth/microsoft).
- **What happens to our Dev Box images and customizations?** They need to be rebuilt either way. Microsoft's transition guide maps Dev Box catalog tasks to [Windows 365 images, Intune apps and scripts, and Autopilot device preparation](https://learn.microsoft.com/en-us/windows-365/enterprise/devbox-transition-to-w365). In Coder, the same setup becomes Terraform templates, which can start from Azure Marketplace images, as the registry's [Azure templates](https://registry.coder.com/templates/coder/azure-windows) do.
- **What about our Linux developers?** Dev Box offers Linux through WSL and [suggests GitHub Codespaces for GitHub users who develop in VS Code](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-faq). Coder serves Linux and Windows developers from one platform ([Coder Workspaces FAQ](../products/coder-workspaces/faq.md)). See also [Coder and GitHub Codespaces](./github-codespaces.md).
- **Which is cheaper?** It depends on usage and existing licensing. Dev Box bills Azure consumption, Windows 365 requires a Windows 365 license (Enterprise for personally assigned Cloud PCs, Flex for dedicated or shared use), and Coder runs on the customer's own compute plus a Coder Premium license if needed. See Pricing and Packaging below.

## When Microsoft Dev Box Alone Is Enough

- **Existing Dev Box customers with time left.** Teams whose current dev boxes meet their needs can keep using them, since existing usage [remains supported during the transition period](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-retirement-guide), which ends at retirement on September 18, 2028. Microsoft calls this a temporary solution and advises against creating new long-lived dependencies on the service.
- **Windows-only, Microsoft-standardized organizations.** Teams that build Windows software, already manage devices with Intune, and want Microsoft to operate the workstations may find Windows 365 with the [developer configuration image](https://learn.microsoft.com/en-us/windows-365/enterprise/whats-new) sufficient.
- **Organizations without platform engineering capacity.** Teams that don't want to operate infrastructure or maintain Terraform templates.

## Pricing and Packaging

- **Dev Box is consumption-billed.** Microsoft's last published pricing page described a monthly storage charge for each dev box, hourly compute while it runs, a [maximum monthly price per size](http://web.archive.org/web/20260711055157/https://azure.microsoft.com/en-us/pricing/details/dev-box/), and no compute charges while a dev box is hibernated. The archived copy doesn't preserve the per-size prices, and Microsoft no longer publishes a Dev Box pricing page, which now redirects to Azure's general pricing page (as of 2026-10-29).
- **Windows 365 is license-based.** Microsoft states that [Windows 365 requires the appropriate license before a Cloud PC can be provisioned](https://learn.microsoft.com/en-us/windows-365/enterprise/devbox-transition-to-w365), with Enterprise for personally assigned Cloud PCs and Flex for dedicated or shared use.
- **Coder.** Coder Community is free and open source. Premium is licensed annually per user, and Coder does not publish a Premium price ([Coder pricing](https://coder.com/pricing)). See [Packaging](../company/packaging.md) for the narrative. Compute is billed separately by the customer's own cloud or infrastructure provider.
