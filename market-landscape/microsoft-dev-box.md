*Microsoft Dev Box stopped accepting new customers on November 1, 2025, entered a closing-down period on September 14, 2026, and [retires on September 18, 2028](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-retirement-guide). Microsoft names Windows 365 as the recommended path forward, so this page also covers the Windows 365 developer setup where it replaces Dev Box. For Windows 365 as a general desktop service, see [Coder and VDI](./vdi.md).*

## One-Line Positioning

Microsoft Dev Box provides Microsoft-managed Windows workstations in Azure and is retiring in favor of Windows 365 Cloud PCs, while Coder provisions Linux, Windows, and macOS development environments defined as code on infrastructure the customer runs, in any cloud, on-premises, or air-gapped.

## Strategic Themes and Patterns

- **Relationship.** Competitive. Dev Box runs developer workstations as Azure VMs that [exist in a subscription owned by Microsoft](https://learn.microsoft.com/en-us/azure/dev-box/concept-dev-box-architecture), and Coder [provisions workspaces with Terraform](https://coder.com/docs/@main/templates/tour) on infrastructure the customer controls. Both answer the same question of where developers work.
- **A forced decision for existing customers.** Microsoft asks Dev Box customers to move their workflows [to Windows 365 or another appropriate solution](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-retirement-guide) by September 18, 2028, and states that Windows 365 isn't a one-to-one replacement. Every Dev Box customer has to re-platform its developer environments either way, which makes the migration itself the evaluation point.
- **Choice, Control, Consistency.** Dev Box and Windows 365 trade off Choice and Control. Dev Box supports [client editions of Windows 10 and Windows 11](https://learn.microsoft.com/en-us/azure/dev-box/concept-dev-box-architecture) only, runs only in Azure, and requires [Microsoft Intune and Microsoft Entra ID](https://learn.microsoft.com/en-us/azure/dev-box/quickstart-configure-dev-box-service). Coder runs on any cloud or on-premises, supports Linux, Windows, and macOS workspaces ([Coder Workspaces FAQ](../products/coder-workspaces/faq.md)), and works with OIDC identity providers including Entra ID. Both address Consistency through centrally defined environments.
- **Lock-in risk.** The retirement shows the risk directly. Dev Box image definitions, pools, and projects don't carry over to Windows 365 as-is, and Microsoft's [transition guide](https://learn.microsoft.com/en-us/windows-365/enterprise/devbox-transition-to-w365) maps them onto Intune provisioning policies, images, and scripts. Standardizing again on a single vendor's managed workstation service leaves the next change of direction in that vendor's hands. Coder templates are Terraform the customer owns and runs.
- **Build versus buy.** For teams leaving Dev Box that don't want a managed desktop, the realistic alternative to Coder is building an internal platform on Azure VMs, Kubernetes, and images, not another hosted vendor. See [Why Coder](../company/why-coder.md).
- **Where Windows 365 is sufficient on its own.** Windows-centric teams already standardized on Microsoft 365, Intune, and Entra ID, with no requirement to self-host or support Linux-native development, can get managed Cloud PCs with a [Windows 11 developer configuration image](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-retirement-guide) and no infrastructure to operate.

## Coder's Strengths Here

- **Any cloud, on-premises, or air-gapped.** Coder runs on Kubernetes or VMs on AWS, Azure, or GCP ([Coder Workspaces FAQ](../products/coder-workspaces/faq.md)), and [all Coder features are supported in air-gapped and offline deployments](https://coder.com/docs/@main/install/airgap). Dev Box setup is documented only as an [Azure service in an Azure subscription](https://learn.microsoft.com/en-us/azure/dev-box/quickstart-configure-dev-box-service).
- **Teams that stay on Azure can.** Coder provides registry templates for [Windows](https://registry.coder.com/templates/coder/azure-windows) and [Linux](https://registry.coder.com/templates/coder/azure-linux) Azure VMs, so an organization can move off Dev Box without leaving Azure.
- **Linux, Windows, and macOS.** Coder templates provision VMs, Kubernetes pods, and Docker containers on Linux, Windows, or macOS, on x86-64 or ARM ([Coder Workspaces FAQ](../products/coder-workspaces/faq.md)). For Linux, Dev Box supports Windows Subsystem for Linux and [points Linux VS Code users to GitHub Codespaces](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-faq).
- **Developer self-service stays.** Developers create workspaces from templates on demand ([Coder Docs](https://coder.com/docs/@main/templates/tour)). Windows 365 replaces Dev Box's developer portal and self-service creation with [admin-led provisioning](https://learn.microsoft.com/en-us/windows-365/enterprise/devbox-transition-to-w365).
- **Environments as code.** Coder runs a Terraform apply [each time a workspace is created, started, or stopped](https://coder.com/docs/@main/templates/tour), so a toolchain change is a template change. Dev Box customizations are [PowerShell-based tasks](https://learn.microsoft.com/en-us/azure/dev-box/concept-what-are-dev-box-customizations) applied to Windows images.
- **The developer's own IDE.** Developers connect from VS Code, JetBrains IDEs, Cursor, Zed, or any SSH-capable editor ([Coder Workspaces FAQ](../products/coder-workspaces/faq.md)). Windows workspaces are also reachable over [RDP](https://coder.com/docs/@main/user-guides/workspace-access/remote-desktops), including a [browser-based RDP client](https://registry.coder.com/modules/coder/windows-rdp). Dev Box connects through the [Windows App or a browser](https://learn.microsoft.com/en-us/azure/dev-box/how-to-create-dev-boxes-developer-portal), and VS Code tunnel access is [in preview](https://learn.microsoft.com/en-us/azure/dev-box/how-to-set-up-dev-tunnels).
- **Faster starts through prebuilt workspaces.** Coder Premium can keep a pool of [prebuilt workspaces](https://coder.com/docs/@main/admin/templates/extending-templates/prebuilt-workspaces) ready to claim. Microsoft's Dev Box FAQ explains why provisioning a dev box [takes 25 minutes or more](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-faq).
- **Entra ID without Intune.** Coder signs users in with [Microsoft Entra ID over OIDC](https://coder.com/docs/@main/admin/users/oidc-auth/microsoft) and doesn't require device management. Dev Box requires every user to hold [Windows Enterprise, Intune, and Entra ID P1 licenses](https://learn.microsoft.com/en-us/azure/dev-box/quickstart-configure-dev-box-service).
- **A foundation for governed AI agents.** Coder Agents, AI Gateway, and AI Governance run on the same workspace infrastructure ([Coder Workspaces message house](../products/coder-workspaces/message-house.md)), and platform teams set what each workspace can reach in the template ([template network boundaries](https://coder.com/docs/@main/ai-coder/agents/platform-controls/template-optimization#configure-network-boundaries)). Dev Box is in maintenance mode with [no new feature development planned](https://azure.microsoft.com/updates?id=567933).

## Microsoft Dev Box Overview

- **What it is.** A service for self-service, cloud-based Windows developer workstations, now [retiring on September 18, 2028](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-retirement-guide). Microsoft stopped accepting [new sign-ups on November 1, 2025](https://azure.microsoft.com/en-us/products/dev-box).
- **Architecture.** A dev center contains projects, which contain dev box pools that set the image, compute, storage, and network for each dev box ([Microsoft Learn](https://learn.microsoft.com/en-us/azure/dev-box/concept-dev-box-architecture)). Dev boxes are Azure VMs in a Microsoft-owned subscription that join either a Microsoft-hosted network or the customer's virtual network, and Dev Box is [built on Azure Virtual Desktop and Windows 365 infrastructure](https://learn.microsoft.com/en-us/azure/dev-box/concept-dev-box-network-requirements). Images come from [YAML image definitions, Azure Compute Gallery, or Azure Marketplace](https://learn.microsoft.com/en-us/azure/dev-box/overview-what-is-microsoft-dev-box).
- **Target customer.** Developer teams in organizations that use Microsoft Intune and Microsoft Entra ID, with per-user [Windows Enterprise, Intune, and Entra ID P1 licensing](https://learn.microsoft.com/en-us/azure/dev-box/quickstart-configure-dev-box-service), which Microsoft 365 E3 and E5 include.
- **Deployment model.** A managed Azure service. The customer's network can be attached through an Azure network connection ([Microsoft Learn](https://learn.microsoft.com/en-us/azure/dev-box/concept-dev-box-architecture)).
- **Successor.** Microsoft calls Windows 365 [the recommended path forward for virtualized developer environments](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-retirement-guide). Its Windows 11 developer configuration image, with pre-installed Microsoft 365 apps, became [generally available the week of September 21, 2026](https://learn.microsoft.com/en-us/windows-365/enterprise/whats-new).

## Coder Overview for This Comparison

- **Self-hosted workspaces.** The Coder server provisions workspaces from [Terraform templates](https://coder.com/docs/@main/templates/tour) on any infrastructure Terraform can manage, including Azure.
- **Windows workspaces.** Templates can provision Windows VMs ([Azure Windows template](https://registry.coder.com/templates/coder/azure-windows)), and developers reach them over [RDP](https://coder.com/docs/@main/user-guides/workspace-access/remote-desktops) or an IDE.
- **Cost controls.** Templates set [autostart and autostop schedules](https://coder.com/docs/@main/admin/templates/managing-templates/schedule), and Coder templates typically [persist user data while deleting compute](https://coder.com/docs/@main/admin/templates/extending-templates/resource-persistence) when a workspace stops.
- **Governance.** SSO through OIDC, RBAC, and, in Premium, audit logging, SCIM, and multi-organization access control ([Coder Workspaces message house](../products/coder-workspaces/message-house.md)).
- **AI on the same platform.** [Coder Agents](https://coder.com/docs/@main/ai-coder/agents), [AI Gateway](https://coder.com/docs/@main/ai-coder/ai-gateway), and [AI Governance](https://coder.com/docs/@main/ai-coder/ai-governance) run on the workspaces developers use.

## Where Microsoft Dev Box Is Strong or Coder Has a Gap

- **No infrastructure to operate.** Microsoft runs the dev box VMs in [its own subscription](https://learn.microsoft.com/en-us/azure/dev-box/concept-dev-box-architecture). Coder is [self-hosted](../company/why-coder.md), so the customer operates the control plane and the compute.
- **Native Intune and Entra ID management.** Dev boxes [enroll in Microsoft Intune automatically](https://learn.microsoft.com/en-us/azure/dev-box/overview-what-is-microsoft-dev-box) and support Entra join or hybrid join, conditional access, and MFA. Coder doesn't manage workspaces as Intune devices.
- **Licensing many customers already own.** Dev Box's per-user prerequisites are [included in Microsoft 365 E3 and E5](https://learn.microsoft.com/en-us/azure/dev-box/quickstart-configure-dev-box-service), so Microsoft-standardized organizations pay only for Azure consumption on top.
- **Full Windows desktop development.** Dev Box offers [Azure Marketplace images](https://learn.microsoft.com/en-us/azure/dev-box/overview-what-is-microsoft-dev-box) that include Visual Studio and supports [nested virtualization with Hyper-V](https://learn.microsoft.com/en-us/azure/dev-box/how-to-connect-dev-box-virtual-switch). Coder supports Windows workspaces, but its [Dev Containers integration](https://coder.com/docs/@main/admin/integrations/devcontainers/integration) isn't supported on Windows or macOS workspaces ([Coder Workspaces FAQ](../products/coder-workspaces/faq.md)).
- **Terraform skills required for Coder.** Coder templates are [Terraform](https://coder.com/docs/@main/templates/tour), so platform teams write and maintain them. Dev Box and Windows 365 are configured through the Azure portal, Intune, and image definitions.
- **Agents that operate Windows applications.** Windows 365 for Agents, [generally available since the week of June 1, 2026](https://learn.microsoft.com/en-us/windows-365/agents/whats-new), gives computer-using agents their own Cloud PCs. Coder workspaces are built for coding agents, not automation of desktop business applications.

## Known Limitations in Microsoft Dev Box's Approach

- **Retiring (as of 2026-10-29).** Dev Box retires on September 18, 2028, and Microsoft says to [expect deletion of remaining customer workloads](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-retirement-guide) after that date. During the closing-down period, Microsoft tells customers to check the current product experience to see whether new resource creation remains available.
- **Closed to new customers (as of 2026-10-29).** Organizations with no prior Dev Box deployment [can't sign up](https://azure.microsoft.com/en-us/products/dev-box) as of November 1, 2025.
- **Maintenance mode (as of 2026-10-29).** No new feature development is planned ([Azure Updates](https://azure.microsoft.com/updates?id=567933)). Previously planned features, including developer offboarding and single sign-on for existing dev boxes, [won't reach general availability](http://web.archive.org/web/20260611084242/https://learn.microsoft.com/en-us/azure/dev-box/dev-box-roadmap).
- **Windows only (as of 2026-10-29).** Dev Box supports [client editions of Windows 10 and Windows 11](https://learn.microsoft.com/en-us/azure/dev-box/concept-dev-box-architecture), and custom images must be [generalized generation 2 Windows Enterprise images](https://learn.microsoft.com/en-us/azure/dev-box/how-to-prepare-custom-image-dev-box). Linux tooling runs through WSL.
- **Azure only (as of 2026-10-29).** Microsoft documents Dev Box only as an [Azure service](https://learn.microsoft.com/en-us/azure/dev-box/quickstart-configure-dev-box-service). We found no documented on-premises, other-cloud, or air-gapped option.
- **Provisioning time (as of 2026-10-29).** Microsoft's FAQ addresses why a dev box [takes 25 minutes or more to provision](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-faq), attributing the time to networking, Entra join, Intune enrollment, and customization tasks.
- **Hibernation and GPU limits (as of 2026-10-29).** Hibernation works only on [8 and 16 vCPU sizes](https://learn.microsoft.com/en-us/azure/dev-box/how-to-configure-dev-box-hibernation). GPU access is a [serverless GPU preview in seven regions](https://learn.microsoft.com/en-us/azure/dev-box/how-to-configure-dev-box-serverless-gpu).
- **The Windows 365 path changes the model (as of 2026-10-29).** Windows 365 uses [admin-led provisioning instead of developer self-service, and per-user licensing instead of Azure consumption billing](https://learn.microsoft.com/en-us/windows-365/enterprise/devbox-transition-to-w365). Microsoft states it [isn't a one-to-one replacement](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-retirement-guide) for Dev Box.

## Common Questions

- **Microsoft is retiring Dev Box. Do we have to move to Windows 365?** No. Microsoft recommends Windows 365, and its retirement guide tells customers to move to [Windows 365 or another appropriate solution](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-retirement-guide) by September 18, 2028. Coder is an option for teams that want developer environments defined as code on infrastructure they control.
- **Can we stay on Azure with Coder?** Yes. Coder runs on Kubernetes or VMs on Azure ([Coder Workspaces FAQ](../products/coder-workspaces/faq.md)), and registry templates provision [Windows](https://registry.coder.com/templates/coder/azure-windows) and [Linux](https://registry.coder.com/templates/coder/azure-linux) Azure VMs as workspaces.
- **Can our developers keep Windows workstations?** Yes. Templates can provision Windows workspaces, and developers open them over [RDP from a desktop client or the browser](https://coder.com/docs/@main/user-guides/workspace-access/remote-desktops).
- **Can we keep Microsoft Entra ID?** Yes. Coder authenticates users with [Entra ID through OIDC](https://coder.com/docs/@main/admin/users/oidc-auth/microsoft).
- **What happens to our Dev Box images and customizations?** They need to be rebuilt either way. Microsoft's transition guide maps Dev Box catalog tasks to [Windows 365 images, Intune apps and scripts, and Autopilot device preparation](https://learn.microsoft.com/en-us/windows-365/enterprise/devbox-transition-to-w365). In Coder, the same setup becomes Terraform templates, which can start from Azure VM images (inferred).
- **What about our Linux developers?** Dev Box offers Linux only through WSL and [points Linux VS Code users to GitHub Codespaces](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-faq). Coder serves Linux and Windows developers from one platform ([Coder Workspaces FAQ](../products/coder-workspaces/faq.md)). See also [Coder and GitHub Codespaces](./github-codespaces.md).
- **Which is cheaper?** It depends on usage and existing licensing. Dev Box bills Azure consumption, Windows 365 requires a per-user license, and Coder runs on the customer's own compute plus a Coder Premium license if needed. See Pricing and Packaging below.

## When Microsoft Dev Box Alone Is Enough

- **Existing Dev Box customers with time left.** Teams whose current dev boxes meet their needs can keep using them during the transition period, which Microsoft says [remains supported](https://learn.microsoft.com/en-us/azure/dev-box/dev-box-retirement-guide) until September 18, 2028.
- **Windows-only, Microsoft-standardized organizations.** Teams that build Windows software, already manage devices with Intune, and want Microsoft to operate the workstations may find Windows 365 with the [developer configuration image](https://learn.microsoft.com/en-us/windows-365/enterprise/whats-new) sufficient.
- **Organizations without platform engineering capacity.** Teams that don't want to operate infrastructure or maintain Terraform templates.

## Pricing and Packaging

- **Dev Box is consumption-billed.** Microsoft's last published pricing page described a monthly storage charge for each dev box, hourly compute while it runs, a [maximum monthly price per size](http://web.archive.org/web/20260711055157/https://azure.microsoft.com/en-us/pricing/details/dev-box/), and no compute charges while a dev box is hibernated. Current per-size prices aren't public, since the Dev Box pricing page now redirects to Azure's general pricing page (as of 2026-10-29).
- **Windows 365 is licensed per user.** Microsoft states that [Windows 365 requires the appropriate license before a Cloud PC can be provisioned](https://learn.microsoft.com/en-us/windows-365/enterprise/devbox-transition-to-w365), with Enterprise for personally assigned Cloud PCs and Flex for dedicated or shared use.
- **Coder.** Coder Community Edition is free and open source. Coder Premium pricing is not public and is available by quote. See [coder.com/pricing](https://coder.com/pricing) and [Packaging](../company/packaging.md). Compute is billed separately by the customer's own cloud or infrastructure provider.
