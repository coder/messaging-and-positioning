*Google Cloud Workstations is distinct from Google Workspace, Google's [productivity and collaboration suite](https://workspace.google.com/) (Gmail, Drive, Docs), which is not a development environment product. It is also distinct from Firebase Studio (formerly Project IDX). Project IDX was [built on Google Cloud Workstations](https://firebase.studio/blog/article/introducing-project-idx), and Google is [shutting Firebase Studio down on March 22, 2027](https://firebase.google.com/docs/studio/migrating-project).*

## One-Line Positioning

Google Cloud Workstations is a Google-managed cloud development environment that runs workstation VMs inside a customer's own Google Cloud project, while Coder is a self-hosted platform that provisions development environments for developers and AI agents on infrastructure the customer runs, including Google Cloud, other clouds, on-premises, and air-gapped networks.

## Strategic Themes and Patterns

- **Relationship.** Competitive. Both products provide the infrastructure development environments run on. Cloud Workstations runs [Compute Engine VMs and persistent disks in the customer's project](https://cloud.google.com/workstations/docs/overview), orchestrated by a [Google-managed controller and gateway](https://cloud.google.com/workstations/docs/architecture). Coder [provisions workspaces with Terraform](https://coder.com/docs/templates/tour) on infrastructure the customer controls. An organization standardizing on one generally does not need the other for the same developers.
- **Choice, Control, Consistency.** Both address Consistency through admin-defined environments ([workstation configurations](https://cloud.google.com/workstations/docs/overview) and container images for Cloud Workstations, [Terraform templates](https://coder.com/docs/templates/tour) for Coder). The main tradeoff is Choice. Cloud Workstations runs only in [Google Cloud regions](https://cloud.google.com/workstations/docs/locations) and only on [Linux container images](https://cloud.google.com/workstations/docs/architecture), while Coder is [cloud-agnostic and self-hosted](../company/why-coder.md). Control is a narrower tradeoff than with fully hosted CDEs, because workstation VMs and disks live in the customer's VPC and support [CMEK](https://cloud.google.com/workstations/docs/encrypt-workstation-resources-using-cmek) and [VPC Service Controls](https://cloud.google.com/workstations/docs/configure-vpc-service-controls-private-clusters). The control plane itself remains a Google-operated service with no documented on-premises or air-gapped option.
- **Lock-in risk.** Adopting Cloud Workstations ties the development environment layer to Google Cloud. An organization that later needs AWS, Azure, on-premises, or disconnected compute for some teams, or Windows development environments, would need to re-platform those environments rather than reconfigure them. Custom workstation images are [Linux container images](https://cloud.google.com/workstations/docs/architecture), so the toolchain inside them can likely carry over to a container-based Coder template (inferred). Images built on Google's [preconfigured base images](https://cloud.google.com/workstations/docs/preconfigured-base-images) rely on Google-specific startup scripts that would need adapting.
- **Build versus buy.** Cloud Workstations already removes much of the build burden for GCP-only Linux teams. For organizations whose requirements extend past one cloud or into air-gapped networks, the realistic alternative to Coder is usually building an internal platform on VMs, Kubernetes, and container images, not another hosted vendor. See [Why Coder](../company/why-coder.md).
- **Where Cloud Workstations is sufficient on its own.** Organizations standardized on Google Cloud, developing on Linux, with no requirement to run outside GCP, and comfortable with a Google-operated control plane can get governed, reproducible environments without operating a control plane of their own.

## Coder's Strengths Here

- **Any cloud, on-premises, or air-gapped.** Coder workspaces run on AWS, Azure, GCP, on-premises, or air-gapped infrastructure ([Coder Workspaces message house](../products/coder-workspaces/message-house.md)), and [all Coder features are supported in air-gapped and offline deployments](https://coder.com/docs/install/airgap). Cloud Workstations documents deployment only in [Google Cloud regions](https://cloud.google.com/workstations/docs/locations), with outside networks reaching private clusters [through Cloud VPN or Cloud Interconnect](https://cloud.google.com/workstations/docs/configure-vpc-service-controls-private-clusters).
- **Self-hosted control plane.** The Coder server runs on infrastructure the customer operates ([Air-gapped Deployments](https://coder.com/docs/install/airgap)). In Cloud Workstations, the cluster's [controller and gateway are Google-managed](https://cloud.google.com/workstations/docs/architecture).
- **Windows and other workload shapes, including on GCP.** Coder templates can provision VMs, containers, Kubernetes pods, GPU instances, and Windows environments ([Coder Workspaces message house](../products/coder-workspaces/message-house.md)). Coder publishes GCP templates for [Linux VMs, Windows VMs, VM-hosted containers, and dev containers](https://github.com/coder/registry/tree/main/registry/coder/templates). Cloud Workstations runs [Linux containers on Container-Optimized OS hosts](https://cloud.google.com/workstations/docs/architecture).
- **IDE choice and first-party integrations.** Coder supports VS Code, Cursor, JetBrains IDEs, Jupyter, and any SSH-capable editor, with official VS Code and JetBrains plugins and browser access through code-server ([Coder Workspaces message house](../products/coder-workspaces/message-house.md)). Cloud Workstations ships a browser [Code OSS editor that uses the Open VSX registry](https://cloud.google.com/workstations/docs/preconfigured-ides), JetBrains images [accessible only through JetBrains Gateway](https://cloud.google.com/workstations/docs/preconfigured-base-images), and a [third-party Posit Workbench image](https://cloud.google.com/workstations/docs/preconfigured-base-images), and its [gcloud TCP tunnel works with any SSH client](https://cloud.google.com/workstations/docs/ssh-support), but Google documents only [VS Code](https://cloud.google.com/workstations/docs/develop-code-using-local-vscode-editor) and [JetBrains](https://cloud.google.com/workstations/docs/develop-code-using-local-jetbrains-ides) as local editors.
- **AI governance on the same infrastructure.** Coder Premium includes [AI Gateway](https://coder.com/docs/ai-coder/ai-gateway) for observing and controlling LLM traffic ([Packaging](../company/packaging.md)), including for third-party agents such as Claude Code and Codex running in a workspace ([Coder Workspaces message house](../products/coder-workspaces/message-house.md)). Each template also sets what its workspaces can reach on the network, so platform teams can give [dedicated agent templates](https://coder.com/docs/ai-coder/agents/platform-controls/template-optimization#create-dedicated-agent-templates) stricter egress than developer templates. Cloud Workstations documents [agent-optimized runtime features](https://cloud.google.com/workstations/docs/agent-optimized-development) and network-level egress control through [Secure Web Proxy](https://cloud.google.com/workstations/docs/set-up-security-best-practices), and Google's separately licensed Gemini Enterprise adds [security policies such as file access and terminal command execution, plus usage metrics](https://docs.cloud.google.com/gemini/enterprise/docs/release-notes), for Google's own AI developer tools only. We found no LLM gateway for other agents running in a workstation, such as Claude Code or custom agents (absence finding).
- **Agents that run where the workspaces run.** Coder Agents run their agent loop in the Coder control plane and provision workspaces only when tool execution is required, and third-party agents such as Claude Code and Codex run inside Coder workspaces under the template's network policy and AI Governance controls ([Coder Workspaces message house](../products/coder-workspaces/message-house.md)).

## Google Cloud Workstations Overview

- **What it is.** [Managed development environments on Google Cloud](https://cloud.google.com/workstations/docs/overview), defined by administrators as workstation configurations and accessed through a browser IDE, local IDEs, or SSH. Generally available [since May 2023](https://cloud.google.com/blog/products/application-development/cloud-workstations-managed-development-environment-is-now-ga).
- **Architecture.** A regional workstation cluster consists of a [Google-managed controller and gateway](https://cloud.google.com/workstations/docs/architecture). The controller creates a Compute Engine VM in the customer's project when a workstation starts and deletes it when the session ends, while a persistent disk mounted at `/home` keeps user data. Each cloud region [requires at least one workstation cluster](https://cloud.google.com/workstations/docs/architecture). IDE containers [run in privileged mode with root access](https://cloud.google.com/workstations/docs/set-up-security-best-practices), with one VM per developer as the isolation boundary.
- **Security and compliance.** Private clusters through Private Service Connect, VPC Service Controls, [CMEK](https://cloud.google.com/workstations/docs/encrypt-workstation-resources-using-cmek), IAM roles, and [Cloud Audit Logs](https://cloud.google.com/workstations/docs/audit-logging). In September 2026, Google made [regional API endpoints generally available in eight regions and added Cloud Workstations to the Google Cloud HIPAA BAA](https://cloud.google.com/workstations/docs/release-notes), and on October 5, 2026 it documented support for Assured Workloads control packages. Assured Workloads had already listed Cloud Workstations in [FedRAMP Moderate since March 2024 and IL4 and IL5 since September 2025](https://docs.cloud.google.com/assured-workloads/docs/release-notes).
- **Hardware.** Machine series from E2 through A3, M3, and Z3, with GPUs on [N1, A2, and A3 machine types](https://cloud.google.com/workstations/docs/available-gpus), including A100 and H100.
- **AI.** [Gemini Code Assist](https://cloud.google.com/workstations/docs/overview) in the Code OSS base editor, [Gemini CLI in all workstation images](https://cloud.google.com/workstations/docs/ai-agent-assisted-coding-gemini-cli), and Antigravity CLI in preconfigured images [since May 29, 2026](https://cloud.google.com/workstations/docs/release-notes). Since August 2026, [agent-optimized development](https://cloud.google.com/workstations/docs/agent-optimized-development) can suspend idle workstations while preserving memory and running processes, with sample keep-alive hooks for Antigravity CLI and Claude Code. Suspend is [in Preview](https://cloud.google.com/workstations/docs/release-notes).
- **AI licensing.** Gemini CLI [stopped serving individual, Google AI Pro, and Google AI Ultra users on June 18, 2026](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/), and new Gemini Code Assist Standard and Enterprise subscriptions [can no longer be purchased as of October 9, 2026](https://docs.cloud.google.com/gemini/docs/codeassist/release-notes). Google now offers Antigravity to enterprises [through Gemini Enterprise subscriptions and Gemini Enterprise Agent Platform](https://docs.cloud.google.com/gemini/docs/codeassist/release-notes), and [Antigravity in Gemini Enterprise doesn't support FedRAMP, IL4, IL5, ITAR, or SOC 1, 2, and 3](https://docs.cloud.google.com/gemini/enterprise/docs/ai-developer-tools-overview).
- **Target customer.** Organizations running on Google Cloud that want administrator-defined developer environments governed with Google Cloud IAM and networking ([Overview](https://cloud.google.com/workstations/docs/overview)).
- **Deployment model.** Managed service on Google Cloud, with workstation VMs in the customer's project and VPC. Available in [31 Google Cloud regions](https://cloud.google.com/workstations/docs/locations).

## Coder Overview for This Comparison

- **Self-hosted workspaces defined as code.** The Coder server runs a Terraform apply [each time a workspace is created, started, or stopped](https://coder.com/docs/templates/tour), so platform teams define workspaces on whatever infrastructure Terraform can manage.
- **Runs on Google Cloud.** Coder documents a [Compute Engine deployment](https://coder.com/docs/install/server/cloud/compute-engine) with two Google Cloud Marketplace SKUs, a license purchase and a bring-your-own-license VM deployment.
- **Dev container support.** Coder can start dev containers through the `coder_devcontainer` Terraform resource or [discover `devcontainer.json` files automatically](https://coder.com/docs/admin/integrations/devcontainers/integration).
- **Governance.** SSO through OIDC, RBAC, and, in Premium, audit logging, SCIM, connection logging, and multi-organization access control ([Coder Workspaces message house](../products/coder-workspaces/message-house.md)).
- **Cost controls.** Autostart and autostop, plus per-user and per-organization quotas and dormancy cleanup in Premium ([Coder Workspaces message house](../products/coder-workspaces/message-house.md)).

## Where Google Cloud Workstations Is Strong or Coder Has a Gap

- **No control plane to operate.** Google runs the [controller and gateway](https://cloud.google.com/workstations/docs/architecture). With Coder, the customer operates the control plane as well as the compute, which requires platform engineering capacity.
- **Native Google Cloud governance.** Access, encryption, perimeter, and audit use the same [IAM](https://cloud.google.com/workstations/docs/access-control), [VPC Service Controls](https://cloud.google.com/workstations/docs/configure-vpc-service-controls-private-clusters), [CMEK](https://cloud.google.com/workstations/docs/encrypt-workstation-resources-using-cmek), and [Cloud Audit Logs](https://cloud.google.com/workstations/docs/audit-logging) a GCP customer already uses.
- **Compliance packaging inherited from Google Cloud.** Cloud Workstations is [in scope for FedRAMP High and DoD IL2, IL4, and IL5](https://docs.cloud.google.com/architecture/security/fedramp-dod-compliance-scope), is supported in the matching [Assured Workloads control packages](https://cloud.google.com/assured-workloads/docs/supported-products), and is [covered under Google Cloud's HIPAA BAA](https://cloud.google.com/workstations/docs/release-notes). With self-hosted Coder, the customer's own environment and authorization boundary carry those obligations.
- **Terraform optional.** Workstation configurations can be created in the [Google Cloud console](https://cloud.google.com/workstations/docs/create-configuration) or with [gcloud](https://cloud.google.com/sdk/gcloud/reference/workstations/configs/create), and Google's Terraform provider also has [resources for clusters and configurations](https://registry.terraform.io/providers/hashicorp/google/latest/docs/resources/workstations_workstation_config). Coder templates are always Terraform.
- **Google AI tooling in the images.** Google's images include [Gemini CLI](https://cloud.google.com/workstations/docs/ai-agent-assisted-coding-gemini-cli), [Antigravity CLI](https://cloud.google.com/workstations/docs/release-notes), and Gemini Code Assist in the [Code OSS base editor](https://cloud.google.com/workstations/docs/overview), so teams that already hold the matching Google licenses avoid image work. Gemini CLI now needs a [Gemini Code Assist Standard or Enterprise license or a paid Gemini or Gemini Enterprise Agent Platform API key](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/), and enterprise use of Antigravity goes [through Gemini Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/release-notes).
- **Memory-preserving suspend for long agent sessions.** Suspend keeps RAM, running processes, and agent context while [stopping vCPU and memory compute costs](https://cloud.google.com/workstations/docs/agent-optimized-development) (Preview). Compute Engine [can't suspend instances with GPUs or more than 208 GB of memory](https://cloud.google.com/compute/docs/instances/suspend-resume-instance), the [running timeout keeps counting while a workstation is suspended](https://cloud.google.com/workstations/docs/reference/rest/v1/projects.locations.workstationClusters.workstationConfigs), and the [IL5 control package disables suspend and resume](https://cloud.google.com/assured-workloads/docs/control-packages/il5).
- **Fast start pools.** Configurations can keep [pre-started VMs and disks](https://cloud.google.com/workstations/docs/create-configuration) ready, and since August 2026 gcloud [defaults to a pool size of 1](https://docs.cloud.google.com/sdk/docs/release-notes). Coder offers prebuilt workspace pools in Premium ([Coder Workspaces message house](../products/coder-workspaces/message-house.md)).

## Known Limitations in Google Cloud Workstations' Approach

- **Google Cloud only.** Workstations run in [Google Cloud regions](https://cloud.google.com/workstations/docs/locations). We found no documented on-premises, other-cloud, self-hosted, or air-gapped option.
- **Linux only.** Workstations run [Linux container images](https://cloud.google.com/workstations/docs/architecture). Windows appears in the docs only as a [client OS for the JetBrains Gateway plugin](https://cloud.google.com/workstations/docs/develop-code-using-local-jetbrains-ides).
- **JetBrains through Gateway only.** The JetBrains images are [accessible only through JetBrains Gateway](https://cloud.google.com/workstations/docs/preconfigured-base-images), and Google lists [two Cloud Code debugging features](https://cloud.google.com/workstations/docs/known-issues), Debug on Kubernetes and debugging a local Cloud Run service, as unavailable in IntelliJ-based IDEs because of JetBrains Gateway limitations.
- **Default session timeouts.** Stopping a workstation [deletes its VM](https://cloud.google.com/workstations/docs/architecture), and idle workstations stop the same way unless the configuration [suspends them instead](https://cloud.google.com/workstations/docs/release-notes). Default timeouts depend on the tool: the [API](https://cloud.google.com/workstations/docs/reference/rest/v1/projects.locations.workstationClusters.workstationConfigs) defaults to 20 minutes idle and 12 hours running, the [console](https://cloud.google.com/workstations/docs/create-configuration) defaults auto-sleep to 2 hours, and [gcloud](https://cloud.google.com/sdk/gcloud/reference/workstations/configs/create) defaults both to 2 hours. Admins can disable either timeout, and Google added a [keep-alive script for long-running background tasks](https://cloud.google.com/workstations/docs/release-notes) in April 2026.
- **24-hour session cap with CMEK.** When a configuration uses CMEK, its running timeout [must be greater than 0 and less than 24 hours](https://cloud.google.com/workstations/docs/reference/rest/v1/projects.locations.workstationClusters.workstationConfigs). The [IL5 control package](https://cloud.google.com/assured-workloads/docs/control-packages/il5) requires CMEK for Cloud Workstations and disables Compute Engine suspend and resume, so an IL5 workstation session can't suspend or run longer than 24 hours.
- **Always-on cluster fee.** Each cluster bills a [control plane fee of $0.20 per hour](https://cloud.google.com/workstations/pricing), about $144 per 30-day month, whether or not its workstations are in use. Google says most deployments need only one cluster, with more required only for [additional regions or VPCs](https://cloud.google.com/workstations/pricing).
- **GPU support inconsistently documented.** The [GPU page](https://cloud.google.com/workstations/docs/available-gpus) says GPUs are supported only on N1, A2, and A3, but the [machine types page](https://cloud.google.com/workstations/docs/available-machine-types) marks G4 machine types as supporting GPU acceleration, and the GPU page's zone table lists RTX 6000. Buyers who need G4 GPUs should confirm support with Google.
- **No documented AI governance layer for third-party agents.** We found no LLM gateway for agents running in a workstation in the Cloud Workstations docs. Gemini Enterprise adds [admin policies and usage metrics](https://docs.cloud.google.com/gemini/enterprise/docs/release-notes) for Google's own AI developer tools only, and egress control is available at the network level through [Secure Web Proxy](https://cloud.google.com/workstations/docs/set-up-security-best-practices).

## Common Questions

- **We're standardized on Google Cloud. Why not just use Cloud Workstations?** If every team is on GCP, develops on Linux, and accepts a Google-operated control plane, Cloud Workstations may be enough. Coder fits when some teams need Windows, another cloud, on-premises or air-gapped environments, or governance over AI agents on the same platform ([Coder Workspaces message house](../products/coder-workspaces/message-house.md)).
- **Can Coder run on Google Cloud?** Yes. Coder documents a [Compute Engine deployment](https://coder.com/docs/install/server/cloud/compute-engine), is available through Google Cloud Marketplace, and publishes [GCP templates](https://github.com/coder/registry/tree/main/registry/coder/templates) for Linux VMs, Windows VMs, containers on VMs, and dev containers.
- **Can we reuse our Cloud Workstations container images in Coder?** Likely for custom images, with some work. Custom workstation images are [Linux container images](https://cloud.google.com/workstations/docs/architecture), and Coder templates can run containers ([Coder Workspaces message house](../products/coder-workspaces/message-house.md)). Images built on Google's base images use Google-specific startup scripts that would need replacing (inferred from [preconfigured base images](https://cloud.google.com/workstations/docs/preconfigured-base-images)).
- **Does Cloud Workstations support non-Google coding agents?** Yes. Its agent-optimized development docs name [Antigravity CLI and Claude Code](https://cloud.google.com/workstations/docs/agent-optimized-development) and describe a pattern for custom agents.
- **Does Cloud Workstations meet FedRAMP or IL5 requirements?** Within Google Cloud, yes. Cloud Workstations is [in scope for FedRAMP High and DoD IL2, IL4, and IL5](https://docs.cloud.google.com/architecture/security/fedramp-dod-compliance-scope) and supported in the matching [Assured Workloads control packages](https://cloud.google.com/assured-workloads/docs/supported-products), where IL4 and IL5 require a private gateway and IL5 requires CMEK ([IL5 control package](https://cloud.google.com/assured-workloads/docs/control-packages/il5)). [Antigravity in Gemini Enterprise doesn't support FedRAMP, IL4, or IL5](https://docs.cloud.google.com/gemini/enterprise/docs/ai-developer-tools-overview), so Google's agent tooling doesn't inherit that boundary. Cloud Workstations doesn't run outside Google Cloud, while Coder runs [fully air-gapped](https://coder.com/docs/install/airgap) inside the customer's own environment.
- **Is Firebase Studio an alternative?** No. Firebase Studio is in Preview, stopped accepting new workspaces on June 22, 2026, and [shuts down on March 22, 2027](https://firebase.google.com/docs/studio/migrating-project).
- **Which is cheaper?** It depends on usage. Cloud Workstations adds a per-vCPU management fee, about $40 per developer per month in [Google's e2-standard-4 example](https://cloud.google.com/workstations/pricing) (calculated), and a per-cluster fee that's small when shared across many developers, on top of Compute Engine and disk costs. With Coder, the customer pays its own infrastructure for workspaces and the Coder control plane, plus a Coder Premium license if needed. See Pricing and Packaging below.

## When Google Cloud Workstations Alone Is Enough

- **GCP-only Linux teams.** Organizations whose developers all work in Google Cloud on Linux and have no on-premises, multi-cloud, or air-gapped requirement.
- **Teams without platform engineering capacity.** Organizations that don't want to operate a control plane or maintain Terraform templates.
- **Regulated workloads that already live in Google Cloud.** Organizations that already rely on Assured Workloads, VPC Service Controls, and CMEK and want development environments inside the same boundary ([release notes](https://cloud.google.com/workstations/docs/release-notes)).
- **Teams standardizing on Google's AI tools.** Organizations adopting Antigravity through Gemini Enterprise, or holding existing Gemini Code Assist licenses, get Antigravity CLI, Gemini CLI, and Gemini Code Assist in Google's images ([release notes](https://cloud.google.com/workstations/docs/release-notes), [Gemini CLI](https://cloud.google.com/workstations/docs/ai-agent-assisted-coding-gemini-cli)).

## Pricing and Packaging

- **Cloud Workstations is metered.** Customers pay Compute Engine, disk, and GPU rates, plus a [management fee of $0.05 per vCPU per hour](https://cloud.google.com/workstations/pricing) while a workstation runs and a control plane fee of $0.20 per hour per cluster. The pricing page lists no free tier.
- **Google's worked example.** For 100 developers on e2-standard-4 machines, Google's [pricing example](https://cloud.google.com/workstations/pricing) totals $7,480 per month, about $74.80 per developer. At $0.05 per vCPU per hour over the example's 198 hours, the management fee accounts for about $39.60 of each developer's cost, while the shared cluster fee adds $1.44 (calculated). The pricing page doesn't state how suspended workstations are billed, though the agent docs say suspension [stops vCPU and memory compute costs](https://cloud.google.com/workstations/docs/agent-optimized-development).
- **Coder.** Coder Community is free and open source. Premium is licensed per user annually, and AI Premium has custom pricing ([Packaging](../company/packaging.md), [coder.com/pricing](https://coder.com/pricing)). Compute for workspaces and the Coder control plane is billed separately by the customer's cloud or infrastructure provider, and Coder licenses can be bought through [Google Cloud Marketplace](https://coder.com/docs/install/server/cloud/compute-engine).
