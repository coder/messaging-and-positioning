*(OpenShell is an open-source project from NVIDIA. The GitHub repository is [NVIDIA/OpenShell](https://github.com/NVIDIA/OpenShell). This comparison is competitive at the agent execution layer only, where OpenShell overlaps with Coder workspaces as the place coding agents run and with Agent Firewall as the control on what they can reach. OpenShell does not provide a coding agent, a model gateway, or a development environment platform, so it does not compete with the broader Coder platform. NVIDIA positions OpenShell as the software layer of its [Open Agent Safety Platform](https://nvidianews.nvidia.com/news/open-agent-safety-platform), alongside NVIDIA Sentry, a separate reference design for BlueField-4 DPUs that OpenShell [does not require](https://www.nvidia.com/en-us/solutions/ai/agent-safety/). This page covers OpenShell only.)*

## One-Line Positioning

OpenShell is an open-source runtime that confines each agent in a kernel-isolated sandbox under declarative policy, while Coder is a self-hosted platform that provisions governed environments for developers and agents and governs model access, so the two overlap on where coding agents run and how their actions are constrained, and differ on everything above the sandbox.

## Strategic Themes and Patterns

- **Relationship.** Competitive at the agent execution layer, not at the platform level. OpenShell provides its own control plane and compute. A [gateway](https://docs.nvidia.com/openshell/latest/about/architecture) manages sandbox lifecycle, identity, policy, and credentials, and sandboxes run on [Docker, Podman, MicroVM, or Kubernetes](https://docs.nvidia.com/openshell/latest/how-it-works/sandboxes/runtimes). NVIDIA lists secure coding agents such as Claude Code, OpenCode, Codex, and GitHub Copilot CLI as a [use case](https://docs.nvidia.com/openshell/latest/about/overview) and names [platform teams and security or IT teams](https://www.nvidia.com/en-us/ai/openshell/) among its users. Coder also provisions the environments where coding agents execute ([Coder Agents docs](https://coder.com/docs/ai-coder/agents)) and restricts what agent processes can reach with [Agent Firewall](https://coder.com/docs/ai-coder/agent-firewall). A platform team deciding where its coding agents run, and how they are confined, can evaluate both. OpenShell does not include a coding agent ([NVIDIA FAQ](https://www.nvidia.com/en-us/ai/openshell/)), a model gateway with prompt-level audit, or human development environments defined as infrastructure code (inferred from the scope of its docs), and NVIDIA says OpenShell [integrates with the enterprise ecosystem rather than replacing it](https://www.nvidia.com/en-us/ai/openshell/).
- **Choice, Control, Consistency.** Choosing OpenShell instead of Coder costs little on Choice. OpenShell is [Apache-2.0](https://github.com/NVIDIA/OpenShell/blob/main/LICENSE), intended by NVIDIA to be [model-agnostic and harness-agnostic](https://www.nvidia.com/en-us/ai/openshell/), and runs on several container and VM runtimes. One narrower point is Windows. OpenShell on Windows through WSL 2 is [Experimental](https://docs.nvidia.com/openshell/latest/about/support-matrix), while Coder workspaces run on [Windows, Linux, and macOS](https://coder.com/docs/about). The tradeoffs are on Control above the sandbox and on Consistency. OpenShell governs what an agent process can touch. Its documentation does not describe identity-attributed audit of prompts and tool calls, model access control, or spend controls (inferred from the scope of the docs), which Coder covers through [AI Gateway](https://coder.com/docs/ai-coder/ai-gateway). OpenShell sandboxes are defined by an [OCI image and workload templates](https://docs.nvidia.com/openshell/latest/how-it-works/sandboxes/templates) for agent workloads, while Coder templates define the [same governed environment for developers and agents](../products/coder-workspaces/message-house.md) on any infrastructure.
- **Lock-in risk.** OpenShell itself carries little lock-in risk. It is open source, sandboxes use [standard OCI images](https://docs.nvidia.com/openshell/latest/how-it-works/sandboxes/overview), and policies are [YAML files](https://docs.nvidia.com/openshell/latest/how-it-works/policies/overview) that can be kept in version control. The harder-to-reverse decision is architectural. An organization that runs agents in one system and developers in another ends up with two sets of environment definitions, identity mappings, and audit pipelines, and that split gets harder to unify once agents are running in production.
- **Build versus buy.** OpenShell is a building block for a platform team, not a complete answer to governing coding agents across an organization. Teams that adopt it still assemble the rest themselves, including environments for the developers who review agent work, a model gateway with attribution and budgets, central collection of [per-sandbox audit files](https://docs.nvidia.com/openshell/latest/observability/ocsf-json-export), and a [shared PostgreSQL backend](https://docs.nvidia.com/openshell/latest/kubernetes/high-availability) for highly available gateways. That matches [Why Coder](../company/why-coder.md), which says building self-hosted development infrastructure with this depth of governance is realistic for only a small number of organizations, and that sandboxing products each address a piece of the problem.
- **Where OpenShell is sufficient on its own.** An organization that mainly needs to run autonomous agents under kernel-enforced file, process, and network policy, with credentials kept out of the agent's reach, and that isn't asking for governed developer environments or model-level audit, may find OpenShell enough. This includes individual developers running agents on a laptop or on [DGX Spark or DGX Station](https://www.nvidia.com/en-us/ai/openshell/).
- **Possible combination.** The two could be layered, for example by running OpenShell sandboxes for long-running agents while Coder provides developer environments and AI Gateway, with OpenShell egress policy permitting model traffic only to AI Gateway. Neither company documents an integration or this configuration as of 2026-10-06, so it is inferred rather than tested.

## Coder's Strengths Here

- **One platform for developers and agents.** The same Terraform-defined model governs human workspaces and agent workspaces, and developers connect with VS Code, Cursor, JetBrains, or any SSH-capable editor ([Coder Workspaces message house](../products/coder-workspaces/message-house.md)). OpenShell also supports [connecting VS Code or Cursor over SSH](https://docs.nvidia.com/openshell/latest/how-it-works/sandboxes/overview), but its environments are scoped to agent workloads rather than defined as full development infrastructure.
- **Model governance tied to identity.** AI Gateway authenticates users with their [Coder credentials](https://coder.com/docs/ai-coder/ai-gateway/auth), records prompts, token usage, and tool invocations organized into [sessions and threads](https://coder.com/docs/ai-coder/ai-gateway/audit), and enforces [per-user and per-group budgets](https://coder.com/docs/ai-coder/ai-gateway/cost-controls) before requests reach the provider. OpenShell [removed its managed inference routing in 0.1.0](https://docs.nvidia.com/openshell/latest/how-it-works/inference). Agents now call provider endpoints directly.
- **A self-hosted coding agent with no credentials in the workspace.** Coder Agents runs the agent loop, chat history, and tool execution inside the Coder deployment, with no SaaS or managed component, and the workspace holds no LLM API keys or agent harness ([Coder Agents docs](https://coder.com/docs/ai-coder/agents), [architecture](https://coder.com/docs/ai-coder/agents/architecture)). OpenShell is [not an agent framework](https://www.nvidia.com/en-us/ai/openshell/), so the customer brings the agent and the image that contains it ([sandbox docs](https://docs.nvidia.com/openshell/latest/how-it-works/sandboxes/overview)).
- **Network audit in the same view as model activity.** Agent Firewall [streams every allow and deny decision to the Coder control plane](https://coder.com/docs/ai-coder/agent-firewall), and AI Gateway session views show [total and blocked Agent Firewall requests per session](https://coder.com/docs/ai-coder/ai-gateway/audit). OpenShell writes OCSF audit events to [JSON files inside each sandbox](https://docs.nvidia.com/openshell/latest/observability/ocsf-json-export), and its OTLP export [carries traces only](https://docs.nvidia.com/openshell/latest/how-it-works/gateways/configuration).
- **Any infrastructure and workload type.** Coder workspaces run as VMs, Kubernetes pods, or Docker containers, on ARM and x86-64 across Windows, Linux, and macOS ([Coder docs, About](https://coder.com/docs/about)), and [run air-gapped](https://coder.com/docs/install/prepare/airgap), though Coder Agents [usage reporting](https://coder.com/docs/ai-coder/agents/licensing-usage) needs outbound HTTPS unless arranged with Coder.
- **Commercial support.** Coder Premium customers have [direct access to global support from Coder's team](https://coder.com/pricing). OpenShell's README lists [GitHub Discussions and Issues](https://github.com/NVIDIA/OpenShell) as its community channels, and no paid support offering for OpenShell appears on NVIDIA's OpenShell pages as of 2026-10-06.

## NVIDIA OpenShell Overview

- **What it is.** NVIDIA describes OpenShell as "an open-source runtime for executing fleets of autonomous AI agents in sandboxed environments with kernel-level isolation," combining sandbox controls with declarative YAML policy ([OpenShell overview](https://docs.nvidia.com/openshell/latest/about/overview)). NVIDIA says it is not an agent framework and not just a sandbox, adding gateway-brokered credentials, policy-enforced egress, and audit ([NVIDIA FAQ](https://www.nvidia.com/en-us/ai/openshell/)).
- **Architecture.** A gateway is the control plane. A compute driver provisions each sandbox and a separate supervisor, which checks policy, supplies credentials, and opens approved connections. The sandbox runs the agent and makes no policy decisions, and the agent cannot start until controls are confirmed ([architecture](https://docs.nvidia.com/openshell/latest/about/architecture)). Filesystem access is confined with Landlock and system calls with seccomp, and the agent runs as a non-root identity with no capabilities. Filesystem and process rules are locked at sandbox creation, while network rules can change at runtime ([architecture](https://docs.nvidia.com/openshell/latest/about/architecture), [overview](https://docs.nvidia.com/openshell/latest/about/overview)).
- **Policy.** Egress is denied by default. Network rules can match the calling binary, destination, HTTP method, and path, and support MCP-aware and TLS-inspecting rules ([network rules](https://docs.nvidia.com/openshell/latest/how-it-works/policies/network-rules)). A policy prover uses an SMT solver to check whether a proposed change adds risky access ([prover](https://docs.nvidia.com/openshell/latest/how-it-works/policies/prover)). An optional advisor lets an agent propose new network rules for human review ([advisor](https://docs.nvidia.com/openshell/latest/how-it-works/policies/advisor)).
- **Credentials.** Agents receive opaque placeholders. The proxy substitutes the real credential only for requests that pass network policy and the provider's endpoint binding ([providers](https://docs.nvidia.com/openshell/latest/how-it-works/providers/overview)). Credentials can be stored in the gateway's encrypted database, Kubernetes Secrets, or Vault ([gateway configuration](https://docs.nvidia.com/openshell/latest/how-it-works/gateways/configuration)).
- **Multi-user access.** Workspaces separate sandboxes, providers, and policies, with Platform Admin, Workspace Admin, and Workspace User roles ([workspaces](https://docs.nvidia.com/openshell/latest/how-it-works/workspaces)). Users authenticate with mTLS, OIDC (Keycloak, Entra ID, or Okta), or a trusted reverse proxy ([authentication](https://docs.nvidia.com/openshell/latest/how-it-works/gateways/authentication)).
- **Target customer.** NVIDIA names "developers building autonomous agents, platform teams enabling those developers, and security or IT teams" ([NVIDIA FAQ](https://www.nvidia.com/en-us/ai/openshell/)). NVIDIA says over 100 organizations are working with Open Agent Safety Platform technologies, and describes integrations by partners including Microsoft, Canonical, Red Hat, SAP, and Salesforce ([NVIDIA press release, 2026-09-28](https://nvidianews.nvidia.com/news/open-agent-safety-platform), [NVIDIA press release, 2026-05-31](https://nvidianews.nvidia.com/news/enterprise-software-leaders-build-ai-agents-with-nvidia)).
- **Deployment model.** Self-hosted. The installer sets up a CLI and a local gateway, and a [Helm chart](https://docs.nvidia.com/openshell/latest/kubernetes/setup) deploys the gateway to Kubernetes, including [OpenShift](https://docs.nvidia.com/openshell/latest/kubernetes/openshift). NVIDIA lists cloud, hybrid, on-premises, edge, and air-gapped infrastructure as targets ([OpenShell product page](https://www.nvidia.com/en-us/ai/openshell/)). Supported hosts are Linux (amd64 and arm64) and macOS on Apple Silicon ([support matrix](https://docs.nvidia.com/openshell/latest/about/support-matrix)). Sandboxes can request GPUs ([sandbox docs](https://docs.nvidia.com/openshell/latest/how-it-works/sandboxes/overview)).
- **Project status.** Version 0.1.0 shipped on 2026-09-25 and 0.1.2 on 2026-09-28 ([releases](https://github.com/NVIDIA/OpenShell/releases)). NVIDIA describes OpenShell as broadly available as of its [2026-09-28 announcement](https://nvidianews.nvidia.com/news/open-agent-safety-platform), after an [early preview](https://nvidianews.nvidia.com/news/enterprise-software-leaders-build-ai-agents-with-nvidia) that followed its introduction at [GTC in March 2026](https://nvidianews.nvidia.com/news/ai-agents). The maintainer list includes engineers from NVIDIA and Red Hat ([MAINTAINERS.md](https://github.com/NVIDIA/OpenShell/blob/main/MAINTAINERS.md)), and its CNCF Sandbox application [passed a TOC vote](https://github.com/cncf/sandbox/issues/522) in September 2026.

## Coder Overview for This Comparison

- **Coder Workspaces.** Self-hosted, Terraform-provisioned environments where developers work and AI agents execute tasks, on any cloud, on-prem, or air-gapped ([Coder Workspaces message house](../products/coder-workspaces/message-house.md)).
- **Agent Firewall.** A [process-level firewall that restricts and audits what AI agents can access](https://coder.com/docs/ai-coder/agent-firewall), enforcing default-deny [rules by domain, HTTP method, and path](https://coder.com/docs/ai-coder/agent-firewall/rules-engine) for the processes it wraps. It uses Linux namespaces or Landlock as its jail backend ([Agent Firewall docs](https://coder.com/docs/ai-coder/agent-firewall)).
- **AI Gateway.** Centralizes model authentication, prompt and tool-call audit, and cost controls, and supports [OpenAI, Anthropic, Bedrock, Azure, Google, and OpenAI-compatible providers](https://coder.com/docs/ai-coder/ai-gateway/providers).
- **Coder Agents.** A [self-hosted coding agent](https://coder.com/docs/ai-coder/agents) whose loop runs in the Coder control plane and executes tools in a workspace. The agent [operates with the same permissions as the user who submitted the prompt](https://coder.com/docs/ai-coder/agents/architecture).
- **Packaging.** AI Gateway and Agent Firewall make up AI Governance, which is included with a Premium license rather than sold as a separate add-on ([AI Governance message house](../products/coder-ai-governance/message-house.md)).

## Where NVIDIA OpenShell Is Strong or Coder Has a Gap

- **Kernel-level confinement beyond the network.** OpenShell enforces filesystem, process, and system call policy for every sandbox with Landlock and seccomp ([architecture](https://docs.nvidia.com/openshell/latest/about/architecture)). Agent Firewall governs network access for the processes it wraps ([Agent Firewall docs](https://coder.com/docs/ai-coder/agent-firewall)), and per-directory or per-file runtime policy is not part of its current model ([AI Governance message house](../products/coder-ai-governance/message-house.md)). Coder's docs describe agent sandboxing as [at an early stage](https://coder.com/docs/ai-coder/agents/platform-controls/agent-isolation).
- **Credentials the agent never sees.** OpenShell injects real credentials only into requests bound for approved endpoints ([providers](https://docs.nvidia.com/openshell/latest/how-it-works/providers/overview)). Coder keeps LLM credentials out of the workspace for [Coder Agents](https://coder.com/docs/ai-coder/agents/architecture) and centralizes provider keys in [AI Gateway](https://coder.com/docs/ai-coder/ai-gateway/auth), but user secrets injected into a workspace are [readable by anyone with shell or file access](https://coder.com/docs/user-guides/user-secrets), which includes an agent running there.
- **Formal verification of policy changes.** OpenShell's prover flags policy changes that would add risky access before they're approved ([prover](https://docs.nvidia.com/openshell/latest/how-it-works/policies/prover)). Coder's documentation describes no equivalent.
- **Finer-grained network policy.** OpenShell rules can be scoped to the calling binary and can inspect MCP traffic ([network rules](https://docs.nvidia.com/openshell/latest/how-it-works/policies/network-rules)). Agent Firewall rules match domain, method, and path for the wrapped process ([rules engine](https://coder.com/docs/ai-coder/agent-firewall/rules-engine)).
- **Runs on a developer's laptop.** OpenShell installs locally on Linux or macOS with Docker or Podman ([support matrix](https://docs.nvidia.com/openshell/latest/about/support-matrix)). Agent Firewall supports Linux only ([coder/boundary](https://github.com/coder/boundary)), and Coder is built around remote, centrally governed workspaces.
- **Free and open source with broad ecosystem backing.** OpenShell is Apache-2.0 with no license cost ([LICENSE](https://github.com/NVIDIA/OpenShell/blob/main/LICENSE)), and NVIDIA has announced integrations with operating system and enterprise software vendors ([NVIDIA press release, 2026-09-28](https://nvidianews.nvidia.com/news/open-agent-safety-platform)). AI Governance requires a Coder Premium license ([AI Governance docs](https://coder.com/docs/ai-coder/ai-governance)).

## Known Limitations in NVIDIA OpenShell's Approach

- **Early versioning and breaking upgrades (as of 2026-10-06).** 0.1.0 is a breaking release. Local 0.0.x installs cannot be upgraded in place, and sandboxes must be recreated ([0.1.0 upgrade guide](https://docs.nvidia.com/openshell/latest/upgrade/0-1-0)). Security and reliability fixes cover only the latest and previous minor release ([support matrix](https://docs.nvidia.com/openshell/latest/about/support-matrix)).
- **No model-level governance (as of 2026-10-06).** Since 0.1.0, workloads call provider endpoints directly, and the provider profile's L7 rules define the allowed API surface ([inference](https://docs.nvidia.com/openshell/latest/how-it-works/inference)). The docs do not describe prompt or token audit, model access policy beyond endpoint rules, or spend controls (inferred from the scope of the docs).
- **Audit collection is left to the operator (as of 2026-10-06).** OCSF JSON logs are written per sandbox, inside the sandbox, with daily rotation ([OCSF export](https://docs.nvidia.com/openshell/latest/observability/ocsf-json-export)), and OTLP export covers traces only ([gateway configuration](https://docs.nvidia.com/openshell/latest/how-it-works/gateways/configuration)).
- **Multi-user scope is narrow (as of 2026-10-06).** The multi-user design, [RFC 0011](https://github.com/NVIDIA/OpenShell/blob/main/rfc/0011-multi-player-design/README.md), is still a draft though workspaces have shipped, and excludes cross-gateway federation, a user-management UI, and pod-level network isolation between workspaces. NVIDIA describes policy analysis across multiple agents as [ongoing work](https://developer.nvidia.com/blog/add-runtime-controls-to-ai-agents-with-nvidia-openshell/).
- **Kubernetes prerequisites (as of 2026-10-06).** The Kubernetes runtime requires the Kubernetes SIG Agent Sandbox controller, which the chart does not install, and a CNI that enforces NetworkPolicy ([Kubernetes setup](https://docs.nvidia.com/openshell/latest/kubernetes/setup)).
- **Windows is experimental (as of 2026-10-06).** Windows through WSL 2 is Experimental ([support matrix](https://docs.nvidia.com/openshell/latest/about/support-matrix)). NVIDIA's docs conflict on the native Windows driver, which the runtimes page lists as [coming soon](https://docs.nvidia.com/openshell/latest/how-it-works/sandboxes/runtimes) and the drivers page lists as [built in](https://docs.nvidia.com/openshell/latest/extensibility/drivers).
- **Agent images are the customer's to build (as of 2026-10-06).** The default sandbox image is minimal Ubuntu with no agent installed ([README](https://github.com/NVIDIA/OpenShell)). Running Claude Code means using an image that contains it and attaching a provider, and the provider requires an Anthropic Console API key rather than a subscription token ([providers](https://docs.nvidia.com/openshell/latest/how-it-works/providers/overview)).
- **Telemetry is on by default (as of 2026-10-06).** OpenShell sends anonymous telemetry unless the operator opts out ([telemetry](https://docs.nvidia.com/openshell/latest/observability/telemetry)).

## Common Questions

- **Is OpenShell a replacement for Coder?** For most Coder customers, no. OpenShell confines agent processes in [policy-governed sandboxes](https://docs.nvidia.com/openshell/latest/about/overview). Coder provides self-hosted environments for developers and agents with templates, identity, model governance, and audit ([Coder Workspaces message house](../products/coder-workspaces/message-house.md), [AI Governance docs](https://coder.com/docs/ai-coder/ai-governance)). They overlap when choosing where coding agents run and how they are confined.
- **How is OpenShell different from Agent Firewall?** Both enforce default-deny network policy on agent processes, with rules by [domain, HTTP method, and path](https://coder.com/docs/ai-coder/agent-firewall/rules-engine) in Agent Firewall and by [binary, destination, method, and path](https://docs.nvidia.com/openshell/latest/how-it-works/policies/network-rules) in OpenShell. OpenShell also confines filesystem access and system calls and injects credentials at egress ([architecture](https://docs.nvidia.com/openshell/latest/about/architecture)). Agent Firewall runs inside a Coder workspace and reports to the same control plane as AI Gateway, so network and model activity appear in [one session view](https://coder.com/docs/ai-coder/ai-gateway/audit).
- **Can we run OpenShell with Coder?** Neither company documents an integration as of 2026-10-06. Agents in OpenShell sandboxes could, in principle, send model traffic to AI Gateway as an approved endpoint, since AI Gateway serves [clients inside or outside Coder workspaces](https://coder.com/docs/ai-coder/ai-gateway). That configuration is inferred, not tested.
- **Does OpenShell work with the same agents Coder supports?** OpenShell can run any agent in its sandbox image, and NVIDIA lists [Claude Code, Codex, OpenCode, GitHub Copilot CLI, and others](https://www.nvidia.com/en-us/ai/openshell/). The same third-party agents run inside Coder workspaces, and Coder also provides its own [Coder Agents](https://coder.com/docs/ai-coder/agents).
- **Does OpenShell need NVIDIA hardware?** No. OpenShell runs on [Linux and macOS hosts](https://docs.nvidia.com/openshell/latest/about/support-matrix), and NVIDIA says it [does not require BlueField-4](https://www.nvidia.com/en-us/solutions/ai/agent-safety/). It can use GPUs and runs on [DGX Spark and DGX Station](https://www.nvidia.com/en-us/ai/openshell/).
- **Does OpenShell still route inference between local and frontier models?** The docs say no. OpenShell [removed managed inference routing in 0.1.0](https://docs.nvidia.com/openshell/latest/how-it-works/inference), but NVIDIA's [product page](https://www.nvidia.com/en-us/ai/openshell/) and [GTC blog](https://developer.nvidia.com/blog/run-autonomous-self-evolving-agents-more-safely-with-nvidia-openshell/) still describe a router.
- **Can both run air-gapped?** NVIDIA lists [air-gapped infrastructure](https://www.nvidia.com/en-us/ai/openshell/) as a deployment target. Coder [runs air-gapped](https://coder.com/docs/install/prepare/airgap) with offline license validation, except Coder Agents [usage reporting](https://coder.com/docs/ai-coder/agents/licensing-usage).

## When NVIDIA OpenShell Alone Is Enough

- **Individual developers running agents locally.** Developers who want to run an agent on their own machine with [kernel-enforced limits](https://docs.nvidia.com/openshell/latest/about/overview) on files, processes, and network access, and with credentials kept out of the agent's reach.
- **Long-running autonomous agents.** Teams operating autonomous agents that need a confinement boundary outside the agent, rather than environments where developers also work ([NVIDIA FAQ](https://www.nvidia.com/en-us/ai/openshell/)).
- **No need for model-level governance or developer environments.** Organizations that already handle model access, attribution, and developer environments elsewhere, and want an open-source runtime boundary for agents under [version-controlled policy](https://docs.nvidia.com/openshell/latest/about/overview).

## Pricing and Packaging

- **OpenShell is free and open source.** OpenShell is licensed under [Apache-2.0](https://github.com/NVIDIA/OpenShell/blob/main/LICENSE), and NVIDIA distributes it through its [developer resources and GitHub](https://nvidianews.nvidia.com/news/open-agent-safety-platform). NVIDIA publishes no price or paid support plan for OpenShell as of 2026-10-06. The customer pays for the infrastructure it runs on.
- **Coder is per-user.** Coder Community is free and open source, and Premium is an annual per-user subscription whose price isn't published. AI Gateway and Agent Firewall require Premium ([AI Governance docs](https://coder.com/docs/ai-coder/ai-governance)). Coder Agents is available on every tier, with up to five concurrently active agents on Community and Premium, and AI Premium with Coder Agents removes that cap ([Coder pricing](https://coder.com/pricing)). See [coder.com/pricing](https://coder.com/pricing) for current tiers, and [Packaging](../company/packaging.md) for the narrative behind them.
- **The comparison isn't license against license.** OpenShell has no license cost, but an organization adopting it takes on building and operating the surrounding layers covered in Build versus buy above. A direct cost comparison depends on how much of that the organization already has.
