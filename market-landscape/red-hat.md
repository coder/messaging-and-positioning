Red Hat OpenShift Dev Spaces, formerly [CodeReady Workspaces](https://docs.redhat.com/en/documentation/red_hat_openshift_dev_spaces/3.0/html-single/release_notes_and_known_issues/index), overlaps with Coder Workspaces. OpenShift AI's [Models-as-a-Service](https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html-single/govern_llm_access_with_models-as-a-service/index) (MaaS) overlaps with AI Gateway. ## One-Line Positioning

OpenShift is the Kubernetes platform and Red Hat AI serves the models. Coder runs on OpenShift as a standard workload and provides the governed development environments, AI Gateway, and Agent Firewall that developers and coding agents work in.

## Strategic Themes and Patterns

- **Relationship.** Complementary. Coder [installs on OpenShift with Helm](https://coder.com/docs/install/openshift) and runs under the `restricted-v2` security context constraint, so it consumes OpenShift rather than replacing it. Coder's own [OpenShift post](https://coder.com/blog/coder-on-red-hat-openshift-ai-agents-and-governance-for-regulated-environments) describes the split as "OpenShift secures the infrastructure. Coder governs how AI operates within it."
- **Two overlaps: Dev Spaces and Models-as-a-Service.** OpenShift Dev Spaces is a cloud development environment [built on Eclipse Che](https://developers.redhat.com/products/openshift-dev-spaces/overview) and [included with an OpenShift subscription](https://developers.redhat.com/products/openshift-dev-spaces/overview), and it can [inject AI coding assistants into workspaces](https://docs.redhat.com/en/documentation/red_hat_openshift_dev_spaces/3.30/html/develop/develop-con_using_ai_assistants_in_workspaces) as a Technology Preview. OpenShift AI's MaaS puts a gateway in front of models with [API keys, group subscriptions, token rate limits, and per-user usage tracking](https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html-single/govern_llm_access_with_models-as-a-service/index), and documents connecting AI coding tools such as Claude Code and OpenAI Codex to it. A customer on OpenShift may compare Dev Spaces with Coder Workspaces and MaaS with AI Gateway. Everything else in the portfolio (OpenShift, model serving in OpenShift AI, Red Hat AI Inference, OpenShift GitOps, UBI, Developer Hub) sits underneath or beside Coder.
- **Choice, Control, Consistency.** For the platform relationship this doesn't apply, since OpenShift is one of the infrastructure choices Coder [supports](https://coder.com/docs/install/server) alongside other Kubernetes distributions, Docker, and VMs. Against Dev Spaces the difference is Choice. Dev Spaces [is supported only on Red Hat OpenShift](https://docs.redhat.com/en/documentation/red_hat_openshift_dev_spaces/3.30/html/whats_new/whats_new-ref_differences_between_devspaces_and_che). Coder runs on OpenShift and on the other platforms listed in its [install docs](https://coder.com/docs/install/server), so development environments don't have to move if the underlying platform changes. Against MaaS the difference is Control at the agent level. MaaS governs access to models, while Coder also governs where agents run, through [Agent Firewall](https://coder.com/docs/ai-coder/agent-firewall) and the self-hosted [Coder Agents](https://coder.com/docs/ai-coder/agents) loop.
- **Federal and classified programs.** Department of Defense (DoD) and Intelligence Community (IC) programs that already run OpenShift in disconnected enclaves are the clearest fit for the combined stack. OpenShift's [oc-mirror v2 supports mirroring to multiple enclaves](https://docs.redhat.com/en/documentation/openshift_container_platform/4.22/html-single/disconnected_environments/index), and its Compliance Operator ships [profiles aligned with DISA STIG V2R6](https://docs.redhat.com/en/documentation/openshift_container_platform/4.22/html-single/security_and_compliance/index). Coder adds development environments and AI coding agents that [run air-gapped](https://coder.com/docs/install/prepare/airgap) inside the same accreditation boundary. The model, the agent, the source code, and the execution environment can all stay inside the enclave.
- **Accreditation reuse.** When development environments come from one governed platform, mission teams can inherit that platform's Authority to Operate (ATO) instead of each team pursuing its own. A U.S. defense intelligence organization [centralized its ATO process across all development teams](https://coder.com/success-stories/u-s-defense-intelligence-organization) this way, running 2,500+ developers on what it describes as the first true multi-tenant Coder deployment in the U.S. military. That deployment runs on AWS infrastructure, not OpenShift, so it shows the accreditation pattern rather than the Red Hat integration.
- **Where Dev Spaces is sufficient on its own.** An organization that runs only OpenShift, already pays for it, and wants browser-based VS Code or JetBrains IDEs [defined by devfiles](https://developers.redhat.com/products/openshift-dev-spaces/overview) may find Dev Spaces enough. It [installs through OperatorHub](https://developers.redhat.com/products/openshift-dev-spaces/overview), uses OpenShift OAuth and RBAC, and has a documented [restricted-environment install](https://docs.redhat.com/en/documentation/red_hat_openshift_dev_spaces/3.30/html/install/install-proc_installing_dev_spaces_in_a_restricted_environment_on_openshift). Teams that only need an AI coding CLI available in the workspace terminal can use Dev Spaces' [centrally registered AI providers](https://docs.redhat.com/en/documentation/red_hat_openshift_dev_spaces/3.30/html/extend/extend-proc_configuring_ai_providers), if they accept its Technology Preview support scope.
- **Where MaaS is sufficient on its own.** An organization that serves models on OpenShift AI and mainly needs API keys, group-based quotas, and token usage reporting for those models may find [MaaS](https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html-single/govern_llm_access_with_models-as-a-service/index) enough, especially if it doesn't run agents inside governed development environments.
- **How they work together.**
  - *Infrastructure.* OpenShift runs the Coder control plane and the workspaces. Workspaces are [Terraform-defined environments on OpenShift namespaces](https://coder.com/blog/coder-on-red-hat-openshift-ai-agents-and-governance-for-regulated-environments), and existing OpenShift monitoring, logging, and security tooling applies to them as it does to any workload.
  - *Models.* OpenShift AI and Red Hat AI Inference serve models through vLLM with an [OpenAI-compatible API](https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html-single/deploying_models/index). Coder's AI Gateway can route to [any OpenAI-compatible endpoint](https://coder.com/docs/ai-coder/ai-gateway/providers), so developer and agent traffic can go to models served inside the same cluster or network. MaaS also exposes [OpenAI-compatible inference endpoints with API key authentication](https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html-single/govern_llm_access_with_models-as-a-service/index), so a customer could point AI Gateway at MaaS and keep both layers. Neither company documents that configuration, so it is inferred rather than tested.
  - *Security layers.* Red Hat Advanced Cluster Security covers container runtime security and vulnerability scanning, while Agent Firewall adds [process-level domain allowlists](https://coder.com/blog/coder-on-red-hat-openshift-ai-agents-and-governance-for-regulated-environments) for agent processes inside a workspace.
  - *Compliance baseline.* The OpenShift Compliance Operator scans clusters and nodes against [STIG profiles](https://docs.redhat.com/en/documentation/openshift_container_platform/4.22/html-single/security_and_compliance/index). Coder workspace templates declare toolchains and policy as code on OpenShift namespaces, so a template validated once against the program's security controls becomes the baseline every later team starts from.
  - *Agents in a disconnected enclave.* Two Coder options work without outbound connectivity. Third-party agents such as Claude Code or Codex run inside Coder workspaces, with AI Gateway routing their model traffic to in-enclave endpoints. Coder Agents runs its [agent loop inside the Coder control plane](https://coder.com/docs/ai-coder/agents) against [any OpenAI-compatible endpoint](https://coder.com/docs/ai-coder/agents/models), such as a model served on OpenShift AI. Agent Relay is not a fit for disconnected networks, since the cloud agent's [orchestration and inference stay with the cloud provider](https://coder.com/docs/ai-coder/agent-relay).
  - *Delivery.* OpenShift GitOps [uses Argo CD](https://docs.redhat.com/en/documentation/red_hat_openshift_gitops/1.21/html-single/understanding_openshift_gitops/index) to deploy from Git, and can manage Coder's Helm-based deployment the same way it manages other workloads (inferred, not documented by either company).
  - *Portal.* Red Hat Developer Hub is a [productized distribution of Backstage](https://docs.redhat.com/en/documentation/red_hat_developer_hub/1.10/html-single/about_red_hat_developer_hub/index). Coder publishes [Backstage plugins](https://github.com/coder/backstage-plugins) for surfacing Coder workspaces in Backstage. Coder doesn't document Developer Hub specifically, so compatibility with Developer Hub's plugin model is unverified.

## Coder's Strengths Here

- **Runs on OpenShift's default security posture.** Coder's docs give the `securityContext` values for running under the [`restricted-v2` SCC with `readOnlyRootFilesystem`](https://coder.com/docs/install/openshift), and show how to expose Coder through an OpenShift Route. No privileged control plane is required.
- **Ties AI traffic to the development context.** AI Gateway authenticates users with their Coder credentials, [attributes every interaction to a user](https://coder.com/docs/ai-coder/ai-gateway), and enforces [per-user and per-group budgets](https://coder.com/docs/ai-coder/ai-gateway/cost-controls). MaaS offers comparable [per-user token tracking and group quotas](https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html-single/govern_llm_access_with_models-as-a-service/index) for models behind it. What AI Gateway adds is that the same identity governs the workspace, the template, and the agent, so model usage sits alongside workspace audit logs and Agent Firewall logs in one control plane.
- **Governs agent execution, not only model traffic.** Agent Firewall is a [process-level firewall that restricts and audits what AI agents can access](https://coder.com/docs/ai-coder/agent-firewall) from inside a workspace, with [rules by domain, HTTP method, and path](https://coder.com/docs/ai-coder/agent-firewall/rules-engine). This complements cluster-level controls such as network policies and ACS, and neither MaaS nor Dev Spaces' AI assistant feature documents an equivalent control over what an agent process can reach.
- **Built for disconnected networks.** [All Coder features are supported air-gapped](https://coder.com/docs/install/prepare/airgap). Licenses are validated locally with cryptographic signatures, and telemetry and update checks can be disabled. Public STUN can be disabled so connections relay through Coder's built-in or a custom DERP server. Terraform providers are served from a filesystem or network mirror, modules from [JFrog Artifactory](https://coder.com/docs/install/prepare/registry-mirror) or a private Git repository, and documentation from an internal docs URL ([air-gapped docs](https://coder.com/docs/install/prepare/airgap)). This pairs with OpenShift's [disconnected install path using oc-mirror v2](https://docs.redhat.com/en/documentation/openshift_container_platform/4.22/html-single/disconnected_environments/index).
- **A self-hosted coding agent for enclaves.** Coder Agents has [no SaaS or managed component](https://coder.com/docs/ai-coder/agents). The agent loop, chat history, and tool execution all run in the customer's deployment. That makes it an option where no third-party agent can be accredited. The agent [operates with the same permissions as the user who submitted the prompt](https://coder.com/docs/ai-coder/agents/architecture), with no shared service accounts or privilege escalation, which supports attribution for audit, insider-threat review, and incident response. Community and Premium support up to five concurrently active agents, and AI Premium removes that cap ([Coder pricing](https://coder.com/pricing)).
- **Least-privilege administration.** Coder supports SSO through [OpenID Connect](https://coder.com/docs/admin/users/oidc-auth), separate [Auditor, User Admin, Template Admin, and Owner roles](https://coder.com/docs/admin/users/groups-roles), and [audit logs](https://coder.com/docs/admin/security/audit-logs) of workspace and template activity.
- **UBI-based image for accredited environments.** Coder publishes a container image [built on Red Hat's UBI9-minimal base through Iron Bank](https://coder.com/docs/install/rpm), the Department of Defense hardened registry.
- **Not tied to one platform.** Coder also runs on [other Kubernetes distributions, Docker, RPM-based Linux, and VMs](https://coder.com/docs/install/server), so a customer with OpenShift and non-OpenShift infrastructure can run one Coder deployment model across both.

## Red Hat Overview

- **What it is.** Red Hat's hybrid cloud portfolio centered on [OpenShift](https://www.redhat.com/en/technologies/cloud-computing/openshift/pricing), sold in three self-managed tiers. Kubernetes Engine provides enterprise Kubernetes on RHEL CoreOS. Container Platform adds the developer console, Serverless, Service Mesh, Pipelines, and GitOps. Platform Plus adds Advanced Cluster Management, Advanced Cluster Security, OpenShift Data Foundation Essentials, and Quay.
- **Products relevant to Coder.**
  - *OpenShift AI.* An [Operator for model serving and AI workloads](https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html-single/installing_and_uninstalling_openshift_ai_self-managed/index). Its vLLM runtime is [compatible with the OpenAI REST API](https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html-single/deploying_models/index). [OpenShift AI 3.0 made llm-d generally available](https://www.redhat.com/en/about/press-releases/red-hat-brings-distributed-ai-inference-production-ai-workloads-red-hat-ai-3) for distributed inference.
  - *Models-as-a-Service.* An OpenShift AI capability that [governs LLM access through a gateway](https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html-single/govern_llm_access_with_models-as-a-service/index). It provides API keys, external OIDC authentication, group-based subscriptions with token rate limits, a per-user token consumption view, CSV export for cost attribution, and routing to external providers such as OpenAI, Anthropic, AWS Bedrock, Azure OpenAI, and Google Vertex AI. It documents configuring Claude Code and OpenAI Codex to use a single MaaS URL.
  - *Red Hat AI Inference.* An inference server [powered by vLLM and llm-d](https://www.redhat.com/en/products/ai/inference-server) that provides an [OpenAI-compatible API server](https://docs.redhat.com/en/documentation/red_hat_ai_inference/3.5/html-single/vllm_server_arguments/index).
  - *OpenShift Dev Spaces.* An [OpenShift-native CDE](https://docs.redhat.com/en/documentation/red_hat_openshift_dev_spaces/3.30/html/discover/discover-con_what_is_devspaces) where workspaces are OpenShift Pods defined by a devfile, with VS Code in the browser and IntelliJ through JetBrains Gateway. Administrators can [register AI providers](https://docs.redhat.com/en/documentation/red_hat_openshift_dev_spaces/3.30/html/extend/extend-proc_configuring_ai_providers) so that developers pick an AI coding assistant when creating a workspace. The tool binary is injected into the workspace at startup, API keys are stored as OpenShift Secrets in each user's project, and Red Hat states that [air-gapped deployments can connect to self-hosted models](https://docs.redhat.com/en/documentation/red_hat_openshift_dev_spaces/3.30/html/discover/discover-con_what_is_devspaces).
  - *OpenShift GitOps.* An [Operator that uses Argo CD](https://docs.redhat.com/en/documentation/red_hat_openshift_gitops/1.21/html-single/understanding_openshift_gitops/index), included from Container Platform upward.
  - *Universal Base Images.* OCI images [built from portions of RHEL that are freely redistributable](https://developers.redhat.com/articles/ubi-faq) to Red Hat and non-Red Hat platforms.
  - *Developer Hub.* A [supported distribution of Backstage](https://docs.redhat.com/en/documentation/red_hat_developer_hub/1.10/html-single/about_red_hat_developer_hub/index), included in [Red Hat Advanced Developer Suite](https://www.redhat.com/en/products/advanced-developer-suite).
- **Compliance tooling.** The OpenShift Compliance Operator provides `ocp4-stig`, `ocp4-stig-node`, and `rhcos4-stig` profiles [aligned with DISA STIG V2R6](https://docs.redhat.com/en/documentation/openshift_container_platform/4.22/html-single/security_and_compliance/index).
- **Target customer.** Enterprises standardizing on a supported Kubernetes platform across hybrid cloud, including public-sector and regulated organizations that need [disconnected installs](https://docs.redhat.com/en/documentation/openshift_container_platform/4.22/html-single/disconnected_environments/index).
- **Deployment model.** Self-managed on the customer's infrastructure, or managed as [ROSA (AWS), ARO (Azure), OpenShift Dedicated, or OpenShift on IBM Cloud](https://www.redhat.com/en/technologies/cloud-computing/openshift/pricing). OpenShift AI is supported on self-managed OpenShift, OpenShift Dedicated, ROSA, and ARO ([docs](https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html-single/installing_and_uninstalling_openshift_ai_self-managed/index)).

## Coder Overview for This Comparison

- **Coder Workspaces on OpenShift.** Self-hosted development environments for developers and agents, [installed with Helm on OpenShift](https://coder.com/docs/install/openshift) and defined as code by platform teams ([Coder Workspaces message house](../products/coder-workspaces/message-house.md)). Rootless Podman inside workspaces is a [documented option on OpenShift](https://coder.com/docs/admin/templates/extending-templates/docker-in-workspaces) for container builds without privileged containers.

- **Agent Firewall.** A [process-level firewall](https://coder.com/docs/ai-coder/agent-firewall) enforcing [domain, HTTP method, and path rules](https://coder.com/docs/ai-coder/agent-firewall/rules-engine) for agent processes inside a workspace.

Community and Premium support up to five concurrently active agents, and AI Premium removes the cap with a deployment-wide allotment of Agent Hours ([Coder pricing](https://coder.com/pricing), [Packaging](../company/packaging.md)).

- **Air-gapped deployment.** [Supported for all features](https://coder.com/docs/install/prepare/airgap), with offline license validation.

## Known Limitations in Red Hat's Approach

- **Dev Spaces runs only on OpenShift (as of 2026-09-30).** Red Hat states that [OpenShift Dev Spaces is supported only on Red Hat OpenShift](https://docs.redhat.com/en/documentation/red_hat_openshift_dev_spaces/3.30/html/whats_new/whats_new-ref_differences_between_devspaces_and_che), on [OpenShift 4.16 to 4.22](https://docs.redhat.com/en/documentation/red_hat_openshift_dev_spaces/3.30/html/plan/plan-supported_platforms_ref). Organizations with development infrastructure outside OpenShift need a separate approach for those environments.
- **Dev Spaces AI assistants are a Technology Preview (as of 2026-09-30).** Red Hat labels both [AI assistants in workspaces](https://docs.redhat.com/en/documentation/red_hat_openshift_dev_spaces/3.30/html/develop/develop-con_using_ai_assistants_in_workspaces) and [AI provider registration](https://docs.redhat.com/en/documentation/red_hat_openshift_dev_spaces/3.30/html/extend/extend-proc_configuring_ai_providers) as Technology Preview, which Red Hat doesn't support under production SLAs or recommend for production use. The feature injects a tool binary into the workspace. Its documentation doesn't describe controls over which network destinations the agent process can reach (inferred from the scope of the docs).
- **Parts of MaaS are a Technology Preview (as of 2026-09-30).** In OpenShift AI 3.5, Red Hat labels the [MaaS observability dashboard, external models, multi-provider API passthrough, multi-tenancy, and vLLM runtime support through MaaS](https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html-single/govern_llm_access_with_models-as-a-service/index) as Technology Preview. Per-user metrics are off by default and must be enabled with the `captureUser` setting. MaaS identifies users by API key owner or OIDC identity. Its documentation doesn't describe tying a request to a specific workspace or coding agent session (inferred from the scope of the docs).
- **UBI support terms depend on the platform (as of 2026-09-30).** UBI images are freely redistributable, but Red Hat [supports applications as a full RHEL stack only on OpenShift or RHEL](https://developers.redhat.com/articles/ubi-faq).

## Common Questions

- **Does Coder compete with OpenShift?** No. Coder [runs on OpenShift](https://coder.com/docs/install/openshift) as a workload. OpenShift provides the Kubernetes platform, and Coder provides governed development environments and AI governance on top of it.
- **How is Coder different from OpenShift Dev Spaces?** Both provide cloud development environments on OpenShift. Dev Spaces is [OpenShift-native, devfile-based, and included with an OpenShift subscription](https://developers.redhat.com/products/openshift-dev-spaces/overview), and is [supported only on OpenShift](https://docs.redhat.com/en/documentation/red_hat_openshift_dev_spaces/3.30/html/whats_new/whats_new-ref_differences_between_devspaces_and_che). It can inject AI coding assistants into workspaces as a [Technology Preview](https://docs.redhat.com/en/documentation/red_hat_openshift_dev_spaces/3.30/html/develop/develop-con_using_ai_assistants_in_workspaces). Coder uses Terraform-defined templates, runs on OpenShift and [other infrastructure](https://coder.com/docs/install/server), and includes AI Gateway and Agent Firewall for governing coding agents with a Premium license ([AI Governance message house](../products/coder-ai-governance/message-house.md)).
- **How is AI Gateway different from OpenShift AI Models-as-a-Service?** Both put a governed gateway in front of models. [MaaS](https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html-single/govern_llm_access_with_models-as-a-service/index) authenticates with API keys or OIDC, enforces token limits per group subscription, and reports usage per user, for models served on OpenShift AI and external providers. AI Gateway authenticates with the user's [Coder identity](https://coder.com/docs/ai-coder/ai-gateway), enforces [per-user and per-group budgets](https://coder.com/docs/ai-coder/ai-gateway/cost-controls), and sits in the same control plane as the workspaces, [Agent Firewall](https://coder.com/docs/ai-coder/agent-firewall), and [Coder Agents](https://coder.com/docs/ai-coder/agents). A customer can run both, with AI Gateway pointed at a MaaS endpoint as an OpenAI-compatible provider (inferred, not documented by either company).
- **Can Coder's AI Gateway use models served on OpenShift AI?** Yes. OpenShift AI's vLLM runtime is [OpenAI-compatible](https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html-single/deploying_models/index), and AI Gateway supports [generic OpenAI-compatible providers](https://coder.com/docs/ai-coder/ai-gateway/providers), either directly against the model endpoint or through MaaS. Model traffic and source code can then stay inside the customer's network.
- **Does Coder work in disconnected OpenShift clusters?** Yes. Coder supports [air-gapped deployments](https://coder.com/docs/install/prepare/airgap) with offline license validation, and OpenShift documents [disconnected installs with oc-mirror v2](https://docs.redhat.com/en/documentation/openshift_container_platform/4.22/html-single/disconnected_environments/index). Coder's container images need to be mirrored into the cluster's private registry along with OpenShift's.
- **Can AI coding agents run in a classified or disconnected enclave?** Yes, if the model is also served inside the enclave. OpenShift AI and Red Hat AI Inference can serve models in [disconnected environments](https://www.redhat.com/en/products/ai/openshift-ai). Coder's AI Gateway and Coder Agents both work with [OpenAI-compatible endpoints](https://coder.com/docs/ai-coder/agents/models), and every Coder feature is [supported air-gapped](https://coder.com/docs/install/prepare/airgap). Agent Relay is not suitable here, because the cloud agent's [orchestration and inference stay with the cloud provider](https://coder.com/docs/ai-coder/agent-relay).
- **Can mission teams inherit a platform ATO instead of repeating it?** That is the pattern Coder's multi-tenant deployments support. One U.S. defense intelligence organization [centralized its ATO process across all development teams](https://coder.com/success-stories/u-s-defense-intelligence-organization) on a single Coder platform. Authorization itself is granted by the operating organization to its own deployment.
- **Does Coder hold a FedRAMP or DoD Impact Level (IL) authorization?** Coder is self-hosted software that deploys inside the operating organization's accreditation boundary and operates under that organization's authorization. Coder's public documentation doesn't describe an independent FedRAMP or IL authorization for Coder itself.
- **Is Coder Red Hat certified?** Not as of 2026-09-30. Coder installs on OpenShift [with a Helm chart](https://coder.com/docs/install/openshift), and no Coder listing appears in the [Red Hat Ecosystem Catalog](https://catalog.redhat.com/), the [OpenShift Helm chart repository](https://charts.openshift.io/), or [OperatorHub.io](https://operatorhub.io/). Red Hat's [certification policy](https://docs.redhat.com/en/documentation/red_hat_software_certification/2026/html-single/red_hat_openshift_software_certification_policy_guide/index) covers both products managed by an Operator, which must deploy through Operator Lifecycle Manager, and products managed by Helm charts. It also requires container images built on UBI or Red Hat Hardened Images. A certified Coder listing would therefore not require an Operator, but it would need UBI-based images, which Coder's default image is not (see below).
- **Are Coder's images based on UBI?** One is. Coder publishes a [UBI9-minimal-based image through Iron Bank](https://coder.com/docs/install/rpm), the DoD hardened container registry, for compliance programs that require an accredited base image. Coder's default image is not UBI-based (inferred from the Coder repository's [Dockerfile](https://github.com/coder/coder/blob/main/scripts/Dockerfile.base)).
- **Does Coder integrate with Red Hat Developer Hub?** Coder publishes [Backstage plugins](https://github.com/coder/backstage-plugins). Developer Hub is [based on Backstage](https://docs.redhat.com/en/documentation/red_hat_developer_hub/1.10/html-single/about_red_hat_developer_hub/index), but neither company documents using Coder's plugins with Developer Hub specifically.
- **Which OpenShift versions does Coder support?** Coder's install guide lists [OpenShift 4.7 or later](https://coder.com/docs/install/openshift).

## Pricing and Packaging

- **Red Hat.** Self-managed OpenShift pricing [isn't published](https://www.redhat.com/en/technologies/cloud-computing/openshift/pricing) and varies by sizing and subscription. Managed OpenShift lists reserved instances from [$0.076 per hour](https://www.redhat.com/en/technologies/cloud-computing/openshift/pricing) (4 vCPU, 3-year contract), and ROSA and ARO are pay-as-you-go. Dev Spaces is [included with an OpenShift subscription](https://developers.redhat.com/products/openshift-dev-spaces/overview). OpenShift GitOps is included from Container Platform upward. OpenShift AI and Developer Hub pricing isn't published.
- **Coder.** Coder is licensed separately from OpenShift. AI Gateway and Agent Firewall require [Premium](https://coder.com/docs/ai-coder/ai-gateway/standalone). Coder Agents is available on every tier, with up to five concurrently active agents on Community and Premium. AI Premium removes that cap and includes a deployment-wide allotment of Agent Hours sized to expected usage ([Coder pricing](https://coder.com/pricing), [Packaging](../company/packaging.md)). See [coder.com/pricing](https://coder.com/pricing) for current tiers, and [Packaging](../company/packaging.md) for the narrative behind them.
